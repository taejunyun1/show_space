# 영상 작품 1차 구현과 검증 — 2026-10-07

원문 2 §60의 Video file, Aspect Ratio, Screen, Playback, 실제 3D VideoTexture를 구현한다. 이번 기록은 편집기와 저장 계층의 완료 증거이며, §60 전체 및 제품 전체 완료 판정은 아니다. 읽기 전용 공유·발표의 실제 영상 재생과 공개 배포는 다음 구현에서 이어간다. §61 프로젝터 투사 geometry는 별도 미구현이다.

## 편집기

- Outliner ‘영상 작품 추가’로 MP4 또는 WebM 원본을 가져온다. 기본 가로 1,200mm, 높이는 원본 비율, 스크린 형식으로 배치한다. 브라우저가 실제 파일을 디코딩해야 추가할 수 있다.
- Inspector에서 실제 영상 미리보기, 재생/일시정지/처음으로, 위치 이동, 반복, 비율 유지 또는 중앙 크롭, 원본 비율 복원을 제공한다. 기본 음소거이며 네이티브 소리 제어를 제공한다. 재생 위치와 소리는 프로젝트의 변경/자동 저장에 기록하지 않는다.
- R3F demand 렌더에 VideoTexture를 적용한다. 새 프레임/seek에서만 invalidate하고, 첫 프레임 준비와 map 유무 변경 시 material 재컴파일을 수행한다. 콜백/텍스처/Blob URL/디코더는 참조가 사라지면 해제한다.
- 최대 네 영상 동시 재생, 여덟 세션. 새 재생은 가장 먼저 재생한 다른 영상을 멈추며, 세션이 가득 차면 선택 중이 아닌 정지 영상을 먼저 해제한다. 숨겨진 페이지는 재생을 멈춘다. 세션은 Scene·JSON 상태와 분리된다. 실제 다수 기기 VRAM/장시간 스트레스 통과를 뜻하지 않는다.
- 잠긴 영상은 재생·seek만 가능하고 비율/반복/크기/설치 위치 변경은 차단된다. 영상 화면은 자체 발광 표현이므로 이미지 표면 재질 편집기를 노출하지 않는다. 액자/본체 외곽은 기존 구조를 사용한다.

## 자산과 저장

원본은 변환/재인코딩하지 않는다. 16MiB, 긴 변 1,920px, 2,073,600픽셀, 1시간까지이며 지원 코덱은 실제 브라우저 디코딩에 따른다. MP4/WebM의 실제 컨테이너와 제한을 검사하고 외부 URL/blob URL은 영구 자산으로 받지 않는다. loadedmetadata에서 실제 해상도·길이를 먼저 확인한다. 썸네일은 첫 loadeddata 직후 검은 픽셀이 나오는 브라우저를 고려해 시작 근처 프레임으로 seek한 뒤 만든다.

- 현재/숨김/미배치 작품, 모든 Scene, JSON, 작품 Library allowlist에 영상 원본과 비율/반복 설정을 포함한다. 배치 ID/위치/메모는 Library에 포함하지 않는다.
- ZIP은 SHA256 자산 포인터로 원본을 묶고 동일 원본은 Scene 사이에 중복하지 않는다. 영상은 assets/videos/<sha256>.mp4 또는 .webm이다. 영상 종류 포인터를 이미지/모델 슬롯으로 바꾼 백업은 거절한다. 기존 80MiB 복원 예산을 유지한다.
- ZIP/JSON/Library 복원 및 클라우드 Library 자산 검증에서 실제 영상 디코더의 크기/길이를 저장 메타데이터와 대조한다. 인증된 운영 계정 왕복을 검증했다고 확대하지 않는다.
- PNG는 현재 3D 영상 프레임을 캡처한다. PDF·GLB·glTF는 썸네일 정지 화면을 원본 비율 유지/크롭 설정에 맞춰 내보내며 영상 원본은 JSON/자산 ZIP에 보존한다. GLB의 영상 애니메이션 지원을 주장하지 않는다.

## 검증 증거

`npm test`: 179 파일, 975 테스트 통과, 선택 벤치마크 2개 제외. `npm run build`와 `git diff --check` 통과. 기존 큰 chunk 및 Library 정적/동적 import 경고는 남아 있다.

실제 CUA 브라우저, 별도 로컬 origin `http://127.0.0.1:5190/`, 직접 생성한 ffmpeg testsrc2 H.264 640×360/24fps/4초/382,181바이트 MP4를 사용했다. 기존 ANCA/공개 프로젝트 파일은 변경하지 않았다.

1. 실제 파일 선택→영상 스크린 생성, 새로고침 뒤 영상을 선택해 재생/일시정지/Home/End seek 확인. VideoTexture map 초기 적용 문제를 고치고 실제 3D 프레임 변화를 확인했다. 첫/끝 3D 스크린 픽셀 비교에서 지정한 73×48px 범위의 1,314 픽셀이 달라졌다. 이 측정은 해당 테스트 화면의 두 정지 프레임에만 적용된다.
2. 정사각 1,200×1,200mm 스크린에서 contain 검은 여백 및 cover 중앙 크롭을 화면으로 확인했다. 검은 썸네일 문제 수정 후 실제 포스터 RGB 범위가 0..255이고 640×360이다.
3. Scene 저장→ZIP 생성. ZIP의 원본 SHA256이 업로드 파일과 정확히 일치하고 Scene/현재 영상은 같은 자산 하나를 참조한다. 3,952,994바이트 ZIP 실제 파일 선택→새 프로젝트 복원→재생 확인. 원 프로젝트는 목록/이전작업 JSON으로 보존한다.
4. 복원 영상→Library 저장→새 객체 배치→다시 재생→잠금. 비율/반복/치수/배치 입력은 disabled, 재생/seek는 enabled다.
5. 실제 ‘현재 화면 캡처→PNG 저장’의 1,920×1,519px PNG에서 두 영상 화면 및 편집 핸들 제거를 시각 확인했다.
6. JSON 내 원본 MP4 SHA256을 검증했다. 이번 실제 JSON은 초기 검은 포스터 문제 발견용 파일이었고, 수정 후 ZIP의 정상 포스터도 따로 확인했다. 수정 후 JSON 업로드 왕복 및 실제 WebM 코덱 입력은 아직 별도 인수 전이다.
