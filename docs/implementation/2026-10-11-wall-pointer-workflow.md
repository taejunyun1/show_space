# 벽 편집의 최종 좌표와 포인터 보호

작성일: 2026-10-11. 가벼운 벽·숫자 초안과 문·주요 설비 후보 이후 자유 편집을 우선하는 사용자 결정을 유지한다.

## 변경한 동작

평면도는 이전에 캔버스에서 마우스를 놓으면 누가 시작했는지와 관계없이 벽·조명·3D 작품 드래그를 모두 종료했다. 벽/끝점과 Hand도 마지막 이동 이벤트의 값만 적용했다. 3D 벽은 같은 벽 ID만 확인해 다른 포인터나 새로운 외부 드래그를 확정할 수 있었다.

공통 포인터 소유권을 프로젝트 객체·뷰·도구·선택·활성 벽·포인터·store gesture 객체에 묶었다. 모든 store 전환을 관찰해 같은 렌더 사이의 왕복도 취소한다. 다른 포인터의 이동/놓기/캡처 손실은 무시하고, Escape·캡처 손실·unmount는 자신의 편집과 capture만 정리한다. 같은 벽이나 오브젝트에서 새로 시작한 외부 gesture는 이전 포인터로 확정하거나 취소하지 않는다. 유효한 최종 release 좌표/ray를 계산에 포함하고 한 번의 Undo로 저장한다. 기존 10mm ground rounding과 벽 스냅은 유지한다.

평면도 끝점은 이제 공통 wall gesture와 project preview로 표현한다. 연결된 모서리·바닥·붙어 있는 작품이 같은 미리보기를 사용하고, Scene/캡처 보호도 기존 전역 편집 상태를 따른다. 캔버스 내부에서 시작한 조명·3D 작품 이동과 Hand도 소유한 release 좌표를 사용한다. 우클릭 끝점 편집과 오래된 프로젝트의 start callback을 거절한다.

모델에서 가져온 바닥은 벽보다 우선하는 기존 경계를 유지한다. 일부 벽을 옮긴다고 원본 바닥/모델·조명·3D 작품 전체를 함께 이동시키지 않는다. 문·설비·설치 제외 영역 직접 편집이나 과도한 자동 복원은 추가하지 않았다.

## 검증과 연결 흐름

최종 새 검사 38개는 이전 `acf7462`의 세 제품 파일을 복원하고 GalleryWall의 test access export만 추가했을 때 28 실패/10 통과다. 수정 후 모두 통과했다. 원래 파일은 finally에서 바이트 그대로 복구했다. 초기 회전 기대값에서 ground ray의 10mm 반올림을 빠뜨린 검증 오류는 제품 실패로 집계하지 않는다.

- 실제 StrictMode PlanView/DOM 이벤트: 최종 좌표, 끝점·연결 바닥 미리보기, Scene 차단/확정, 단일 Undo, 외부/다른 포인터, 프로젝트·선택·뷰·도구·벽 왕복, 추가 편집, 캡처 손실/Escape/unmount, 잠금/우클릭, 조명/모델 release와 Hand.
- 실제 R3F reconciler/Three geometry/벽 및 Painting: 이전 단계의 소유 변환 전시 백업을 다시 읽고 벽 4개/작품 5점의 벽 이동·회전→두 Scene→ZIP 정확 복원으로 연결했다. 연결 모서리와 작품 위치를 확인하고 실제 box Mesh world 정점·작품 중심을 별도 계산과 비교했다.
- 벽 Mesh 모서리 최대 오차 약 0.00015mm, 붙어 있는 작품 중심 오차 0mm. 기대 벽을 100mm 옮긴 대조는 약 100mm 어긋난다. 이 대조는 assertion이며 외부 importer 실행이 아니다.
- 모델 바닥 74,996,700mm²와 원래 polygon은 두 편집·Scene·백업 뒤에도 유지된다. ZIP 9개 항목/6개 자산의 CRC·해시와 JSON 완전 복원을 확인했다.

관련 5개 파일 72개 통과, 전체 1,459개 통과/선택 10개 제외, TypeScript·Vite 빌드 통과. 기존 500kB chunk 안내는 유지한다. 입력 ray/capture target/CTM과 이미지 Texture/annotation/GPU transport는 검증 어댑터다. 실제 브라우저/GPU나 3D 캡처 픽셀 검증으로 확대하지 않는다. 이번에 새 PDF/GLB 독립 수신을 수행한 것으로 집계하지 않는다.
