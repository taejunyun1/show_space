# PNG 캡처 비율·해상도

2026-10-04. 원본 요구 문서 1 §27의 UI 없는 PNG, 1920×1080·2560×1440·3840×2160 및 사용자 지정 비율을 기존 캡처에 연결한다. 사용자가 요청한 정면·옆면·버드아이뷰·각도 회전과 같은 현재 시점을 쓰며 별도의 걷기/카메라 배치 흐름은 추가하지 않는다.

## 동작

현재 비율, 16:9, 4:3, 정사각, 3:4, 9:16, 사용자 지정 가로:세로와 긴 변 1920/2560/3840px를 선택한다. 16:9에서는 문서의 세 해상도를 정확히 만들며 실제 저장 픽셀 수를 보여 준다. 사용자 지정은 가로·세로 각각 1–10,000이고 소수도 허용한다. 빈칸/범위 밖/비정상 값에서는 저장을 막는다. 긴 변 고정 때문에 사용자 지정 비율의 짧은 변에는 픽셀 반올림이 적용된다.

3D는 현재 카메라/렌더 뷰포트 전체를, 평면도·벽면도는 현재 SVG viewBox 전체를 가운데 맞춘다. 비율이 달라지면 배경 여백을 추가하며 자르거나 늘리지 않는다. 3D 치수 주석에도 같은 배율·오프셋을 적용한다. 작품 이미지 래스터 해상도는 최종 fit 배율에 맞추고 편집 핸들은 제거한다. 저장 뒤 기존 DPR·격자·선택 표시를 복원한다. 극단적인 비율에서도 WebGL 소스 버퍼는 최소 1×1px를 유지한다.

캡처 중 제어를 잠그고 중복 저장을 방지한다. 설정은 창마다 적용되며 프로젝트·Scene 데이터를 새로 바꾸지 않는다. ResizeObserver로 작업 영역과 실제 캔버스/SVG 크기를 관찰해 열린 창의 현재 비율 표시를 갱신한다.

## 검증과 한계

전체 테스트 739개 통과·선택 벤치마크 2개 제외, TypeScript/Vite 빌드 통과. 기존 대형 번들 경고는 남아 있다. 테스트는 문서의 정확한 세 해상도, 세로/정사각/소수 비율, 네 모서리 포함·비율 보존 및 잘못된 입력을 다룬다.

실제 UI에서 합성 프로젝트를 가져와 3D 세 해상도·세로4K·현재 비율, 벽면도 2.4:1(1920×800), 평면도 정사각(2560×2560), 극단적인 1:10000(1×1920)을 다운로드했다. PNG 헤더와 실제 렌더에서 치수/격자 제거와 작품/외곽 비율을 확인했다. 캡처 후 프로젝트 JSON은 가져오기에서 부여한 새 id 외에는 원본과 같다. 390px 설정 창 가로 넘침이 없었다. 같은 창을 연 상태로 390px 변경/복원 시 현재 비율 표시가 1920×1519 → 1062×1920 → 1920×1519로 갱신됐다. 공개 HTTPS에서도 3840×2160 PNG를 다운로드했다. 기록은 ../validation/2026-10-04-capture-output.json에 있다.

화면에 이미 잘린 부분을 다시 추론하거나 카메라를 자동으로 재구성하지 않는다. 원본 작품 텍스처의 해상도를 넘는 세부 정보는 생기지 않는다. 극단적인 비율은 세부 표현을 잃는다. GPU 제한 오류 복구 경로는 유지하지만 실제 GPU 실패를 유발해 검증하지 않았다. 원본 도면 옵션은 이번 합성 입력에 도면 이미지가 없으므로 재검증하지 않았다. 브라우저 크기 검증은 모바일 실기기 검증이 아니다.

전체 목표는 진행 중이다. 실제 계정/두 기기 인증, 실제 SketchUp·대형 모델·모바일 실기기 성능, 동영상/프로젝션·사용자 작품 라이브러리·고급 Presentation과 원본 전체 요구 감사는 별도로 남아 있다.
