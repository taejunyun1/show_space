# 현장·발표 모드의 배치 전환과 비공개 메모 보호

2026-10-15. 현장 도면·임시 치수·설치 메모와 발표 Scene을 실제 UI/native 저장 흐름으로 연결하고 전환 중 남는 이전 작업을 수정했다. 현장 모드에 별도 Scene 편집기를 만들지 않으며 원래 전시의 위치/구조 고정 정책을 유지한다.

## 수정한 동작

- 현장 설치 창은 열린 프로젝트와 같은 ID의 문서/Scene/Undo·Redo 복원 context에 묶는다. 전시 A→B→A도 이전 창을 닫고 측정/선택을 새 문서로 넘기지 않는다. 반대 벽면을 고르면 이전 면의 작품 선택과 메모 대상을 지우고 현재 벽으로 바꾼다.
- NoteEditor의 입력은 프로젝트·복원 context·대상별로 구분한다. 같은 저장 텍스트라도 문서/참고 모델 원본이 바뀌면 이전 미확정 초안을 버린다. 제거된 대상은 편집 화면을 오류로 무너뜨리는 대신 재선택 안내를 표시한다.
- 메모 이미지 요청은 동기적 store 구독과 완료 시점 검사를 함께 사용한다. 문서 왕복·같은 ID 복원·참고 모델 원본 A→B→A에서 이전 이미지/오류/진행 상태를 폐기한다. 다음 업로드의 busy를 이전 작업이 해제하지 않는다. 정상 완료는 최신 텍스트·체크리스트·설치 상태를 보존해 이미지만 추가한다. 이미 시작한 decoder를 강제로 종료한다는 뜻은 아니다.
- 발표는 원본 프로젝트 ID가 바뀌면 Scene/선택/전체 화면 상태를 새 내부 화면으로 시작한다. 갱신된 원본에서 선택 Scene이 사라졌다면 현재 배치로 돌아간다. 공개/편집 원본을 복원하는 명령은 실행하지 않는다.
- 전체 화면 요청은 중복 실행을 막고 거절되면 일반 발표에서 다시 사용할 수 있다. 닫힌 발표의 늦은 진입은 자신이 소유한 fullscreen element만 종료한다. 다른 요소가 전체 화면인 경우 종료하지 않는다. 실제 브라우저/OS 전환 보장은 별도 검증이 필요하다.

## 실제 현장→저장→Scene→발표→전달 흐름

앞선 10점/1Scene 자산 ZIP을 실제 importer로 읽었다. native 사례는 실제 InstallationMode/NoteEditor/PresentationMode, 이미지 decode/Canvas encode, store 명령·Auto Save·IndexedDB 저장과 package export/import를 사용한다. 모드 진입은 작은 Harness, Scene 복원은 실제 store 명령으로 실행하며 App 전체 탐색이라고 주장하지 않는다. Harness에는 App과 같은 LengthUnitContext를 제공한다. GPU transport만 stand-in이며 포인터에는 합성 좌표/identity CTM을 사용한다.

1. 현재 배치는 설치 작품 9점(숨김 1점 포함)과 미배치 1점이다. 목록에서 숨김/미배치를 구별하고 90° 회전한 B면 작품을 선택한다. 벽면 임시 1,000mm는 **100cm**, 평면의 3,000/4,000mm 두 점은 **500cm**다. 면을 바꾸면 측정과 작품/메모 선택을 초기화한다. 측정 전후 전시 구조/배치와 Undo 이력은 같다.
2. 현재 작품의 메모·체크 항목/완료·설치/조명 확인을 실제 UI로 기록한다. 실제 64×32px PNG 참고 사진을 입력해 WebP로 저장하고 decode/RGBA `[22,107,190,255]`를 확인했다. 원본 단색 `[23,107,190,255]` 대비 채널 오차 1이며 사진은 합성 테스트 입력이다. 설치 완료 집계는 1/10점이다. 이미지/체크 외 구조·위치는 바꾸지 않는다.
3. 저장 큐를 마치고 실제 `readDraft`의 전체 전시가 같음을 확인한다. 현장을 닫고 저장 Scene을 복원하면 첫 작품 폭은 400→777mm로 바뀌지만 최신 메모·사진·체크/설치 상태는 유지된다. 현장을 다시 열어 같은 값을 확인한다.
4. 발표에서 다음/이전 Scene과 시점 초기화를 실행한다. 발표 snapshot/정보에는 비공개 Note/설치 상태를 넣지 않는다. 발표 종료 뒤 **editor 전체 state·시작 프로젝트·저장 문서**는 발표 전과 같다.
5. 전체 ZIP을 export/import해 전시를 정확히 복원하고 공개 payload를 준비한다. 내부 메모가 없고 참고 사진은 공개 upload 목록에 없다. 운영 공개 URL을 발행한 사례는 아니다. 독립 Python ZIP CRC·자산 SHA 및 SVG XML/유한 좌표/`임시 측정 100 cm` 텍스트도 검사했다.

## 검증 범위

새 18개 회귀와 기존 현장 SSR 5개, 최종 **23개 통과**다. 임시 소스 복사본에서 제품 3파일만 이전 main `52f6743bb4e17bac6076fba883b0431e868ee0d7`로 바꾸면 같은 18개는 **14 실패/4 통과**이며 수정 후 모두 통과한다. 이전 발표의 Scene 2개/전체 화면 1개 사례는 기대 화면/종료를 기다리다 실패하고, 이전 native 흐름은 반대 면의 작품 선택 해제에서 중단된다. 모든 후속 단계를 이전 실패 원인으로 분리했다고 주장하지 않는다. 작업 체크아웃을 되돌리지 않았다.

전체 **1,675개 통과/선택 10 제외**(262파일 통과/10 제외), TypeScript·production build 통과다. 전체 실행 후 native Harness의 단위 context만 App과 맞추고 최종 23개/산출물·TS를 통과했다. 제품 소스는 그대로이며 기존 큰 청크 안내는 남는다.

실제 브라우저/GPU·fullscreen/실기기 터치·운영 로그인/계정/이메일/URL·디스크 재시작·실사용자/성능 지표·SketchUp과 원문 24단계 전체 인수는 여전히 미완료다. 운영 인증/브라우저 대기는 재개하지 않고 즉시 배포하지 않는다. 도면 인식은 가벼운 초안과 문·설비 후보까지만, 독립 설비 편집/사진→재질 유료 후속은 기존대로 유지한다.
