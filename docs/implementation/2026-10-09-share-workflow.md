# 공유 발행·목록·중단의 작업 보호 및 UI 흐름

2026-10-09. 원문 1 §28–29/40 및 문서 2의 고정 Presentation/Scene 전달 흐름을 실제 React 창과 Worker 처리 코드로 검증했다. 운영 인증 설정·브라우저 연결 대기는 사용자 결정대로 보류한다.

## 변경

공유 창에서 세션 확인을 기다리는 동안 계정·프로젝트가 바뀌거나 창이 unmount되어도 예전 계정으로 발행·목록·중단 요청을 보내던 오류를 수정했다. 기존 `useProjectDialogScope`와 동기 auth store subscription을 연결한다. 프로젝트 및 계정 A→B→A가 한 React batch 안에서 일어나도 이전 작업을 폐기한다. 이전 완료·오류·finally가 새 계정의 링크·목록·busy 상태를 바꾸지 않는다. 중복 실행도 작업 ref로 막는다.

현재 프로젝트·시점·Scene 선택·공개 옵션은 링크 만들기를 누를 때 복제한다. 세션 응답을 기다리다가 카메라가 움직여도 처음 선택한 시점을 공개한다. 내부 메모와 선택하지 않은 Scene은 기존 공개 allowlist로 제외하고, 원본 프로젝트의 후속 편집을 공개 스냅샷에 반영하지 않는다. 계정이 바뀌면 링크·목록·공개 옵션·Scene 선택을 비운다. 현재 작업의 실패는 오류를 표시하고 재시도를 허용한다.

`publishPublicShare`와 목록 읽기에 선택적 AbortSignal을 추가했다. 목록·이미지 소스 읽기는 중단할 수 있다. 이미 전송한 POST/PUT/DELETE는 HTTP 응답을 강제 중단하지 않는다. 서버 쓰기가 끝나기 전에 DELETE를 보내 자산이 다시 생기는 순서 충돌을 피하기 위해 응답을 기다린다. 취소된 발행은 확인된 공유 ID를 원래 자격 증명으로 정리하고 다음 업로드·발행·복사를 진행하지 않는다. 이미 승인해 보낸 공유 중단도 완료를 기다리되 이전 화면에 결과를 전달하지 않는다. 생성 중 닫기 버튼의 기존 비활성화 정책은 유지하며, unmount/프로젝트·계정 전환 시 작업 폐기를 검증했다.

## 검증

새 `ShareDialog.workflow.test.tsx` 13개는 실제 React createRoot/StrictMode/act, Zustand, ShareDialog, ShareClient 및 공개 데이터 준비 코드를 실행한다. 지연 세션과 HTTP 응답을 제어하며, 마지막 정상 흐름은 실제 Worker router·요청/응답·서버 인증 처리·공개 parser·SQLite schema와 읽기/쓰기를 연결한다. 인증 응답과 R2는 명시적 합성 transport, dialog/clipboard는 jsdom adapter다. Worker 스트림에는 Node native Blob을 사용하며 테스트 전용 migration 경로는 Vite asset URL 변환을 피한다. 실제 로그인·브라우저·운영 HTTP/R2를 실행한 증거가 아니다.

- 지연 credential 뒤 계정 변경·unmount·프로젝트 A→B→A·계정 A→B→A에 새 요청을 보내지 않는다.
- 이전 목록과 중단 작업의 결과가 새 계정에 들어가지 않는다. 새 목록은 정상 표시하며 이전 GET은 취소한다.
- 늦은 생성 응답으로 알려진 공유 ID는 원래 계정으로 DELETE한다. 이전 정리 완료가 새 계정의 작업을 끝내거나 중복 발행을 허용하지 않는다.
- 현재 실패·중복 차단·재시도, 클릭 당시 카메라와 선택한 Scene·치수/상세/댓글 옵션, 목록과 링크 복사를 확인한다.
- 실제 서버 bridge에서 선택 Scene 하나를 발행하고 공개 스냅샷/이미지 200을 확인한다. 편집 원본의 치수 변경 뒤 공개 치수는 고정된다. 공유 중단 후 스냅샷과 이미지 모두 410이다. 내부 메모·미선택 Scene은 없다.

`shareClient.test.ts`에는 취소 회귀 5개를 추가했다. 사전 취소와 지연 소스 읽기 중단, 실제 Worker bridge에서 생성·업로드·최종 발행이 진행 중인 세 경우를 검증한다. 업로드는 서버 쓰기 전, 생성/발행은 서버 처리 후 응답 직전에 기다리게 한다. 취소 직후에는 DELETE를 보내지 않고 응답 완료 후 원래 계정으로 정리한다. 초안은 404, 이미 발행된 스냅샷/이미지는 410이며 이미지 자산이 제거된다. 최종 발행 응답을 기다리는 동안에는 공개 조회가 200이므로 취소가 순간적인 공개를 없애는 트랜잭션이라고 주장하지 않는다.

[검증 기록](../validation/2026-10-09-share-workflow.json)에 명령·개수·범위를 남겼다. 이전 HEAD `871431b`의 두 production 파일을 같은 테스트·transport에 대조한 결과 **15 실패 / 13 통과**, 수정 후 **28 통과**다. 새 회귀는 18개다. 전체 **1,205 통과 / 선택 10 제외**, 221 파일 통과/10 파일 제외. TypeScript와 production build, diff 검사 통과. 기존 Vite 큰 청크 안내는 유지한다.

## 남은 범위

공유 ID 응답을 받지 못한 생성, 네트워크 단절 뒤 서버 쓰기의 완료 여부, DELETE 실패/응답 유실, 브라우저 종료와 credential 만료까지 자동 정리를 보장하지 않는다. 취소된 요청을 강제로 abort하지 않아도 네트워크 자체 장애는 남으며, 정리는 best effort다. 서버 차원의 작업 ID·멱등성·초안 만료/회수 정책은 별도 후속 범위다.

실제 브라우저·GPU·공개 웹 UI/HTTP 왕복·계정/두 기기·원문 24단계 전체 인수·실사용 지표·SketchUp 수신은 계속 남는다. 이번 변경은 Git에 기록하며 즉시 재배포하지 않는다. 직전 공개 배포 기록의 소스는 `8fb69dc`이고 이번 실행에서 운영 배포 상태를 새로 확인하지 않았다.
