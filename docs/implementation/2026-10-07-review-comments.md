# 외부 협업 댓글

제품 계획 1.2 및 문서 2 §50·57의 Comment를 구현했다. 원본 Pages의 §57은 작업자의 내부 Note와 협업자의 외부 Comment를 구분한다. 댓글은 Project/Note/Scene 스키마를 수정하지 않고 발행한 공유 링크 ID에 연결된 별도 D1 레코드로 저장한다. §56의 Owner/Editor/Viewer/Commenter 초대·공동 편집 전체를 구현한 것으로 집계하지 않는다.

## 사용 흐름과 공개 범위

공유 창의 **협업 댓글 허용**은 기본 꺼짐이다. 기존 읽기 전용 링크와 기존 발행 결과는 그대로 유지된다. 켜서 새 링크를 만들면 로그인한 열람자가 의견·답글을 남기고 링크를 가진 모든 사람이 읽는다. 객체 배치는 계속 고정된다. 댓글 허용 여부는 공유 작성자가 인증된 발행 요청의 별도 헤더로 지정하며, 임의 공개 JSON 필드만 넣어 댓글 권한을 켤 수 없다. 발행 후 댓글 공개 설정 변경은 현재 제공하지 않는다.

공유 화면의 **협업 댓글**에서 현재 Scene의 전시 전체·선택 벽/작품/3D 작품/참고 공간 또는 공간 위치를 대상으로 의견을 등록한다. 공간 위치는 표시 단위의 X/Y/Z 숫자로 입력하며 서버가 공개 공간의 외접 범위와 여유 내에 있는지 확인한다. 정확한 메시 표면 부착 검사나 드래그 핀 작성은 아니다. **대상 보기**는 해당 공개 Scene과 객체를 선택하고, 공간 위치는 평면도의 별도 마커로 표시한다. 편집 객체·치수·배치를 바꾸지 않는다.

표시 이름은 직접 입력한다. 로그인 계정 이메일·계정 ID는 댓글 응답에 공개하지 않는다. 이름은 계정 실명 인증이 아니다. 댓글 텍스트는 HTML로 실행하지 않고 일반 텍스트로 표시한다. 내부 메모·메모 사진·원본 도면은 댓글 데이터에 자동으로 복사하지 않는다. 사용자가 직접 적은 의견과 위치는 공유 공개 범위에 속한다.

답글, 자신의 댓글 수정·삭제, 의견 작성자/공유 소유자의 처리 완료·다시 열기·의견 전체 삭제를 지원한다. 공유 소유자는 타인 댓글을 삭제할 수 있지만 타인의 글을 자신의 문장으로 수정할 수 없다. 완료된 의견에는 다시 열기 전 답글을 추가할 수 없다. 삭제한 글은 이름·내용을 지우고 자리만 남긴다. 의견 전체 삭제도 내용을 지운 후 목록에서 제외한다.

공유 창의 링크 목록에 **댓글 관리**를 추가했다. 로그인 작성자는 자기 계정 권한, 기존 작성자 키 링크는 별도 키 권한으로 관리한다. 다른 계정 소유의 링크에 기존 키를 사용하면 거절한다. 댓글 작성에 계정 인증이 필요한 공개 화면은 동일 `/s/<48자리 ID>` 경로로 로그인 복귀를 요청한다. 일반 계정 창의 `/auth/callback`은 유지한다. 운영 provider의 실제 Redirect URL 허용 목록 및 이메일/Google 복귀는 미검증이다.

## 저장·권한·동시 수정

`0004_review_comments.sql`은 `review_threads`와 공유/작성자 인덱스를 추가한다. 고정된 R2 스냅샷과 별개로 D1에 의견 구조·답글·수정 버전을 저장한다. 공개된 Scene/객체 allowlist에서 대상 이름을 다시 구하며, 숨김·미배치·공유하지 않은 Scene과 임의 대상 종류는 받지 않는다. 원본 Project JSON/자산 백업/Archive 안에는 이 링크별 댓글을 넣지 않는다.

읽기는 로그인 없이 가능하고 쓰기는 확인된 계정 또는 해당 기존 링크의 작성자 키만 허용한다. 클라이언트의 mine/canManage 표시는 안내이고 실제 변경 권한은 서버가 확인한다. POST/PATCH는 같은 사이트 요청만 받는다. 계정 전환 시 클라이언트가 이전 목록·입력을 새 컨텍스트에 표시하지 않고 AbortController/계정·요청 epoch 확인으로 이전 응답 적용을 막는다.

댓글 수정은 `expectedRevision` 조건의 단일 D1 UPDATE로 보호한다. 충돌은 409이며 입력을 유지하고 새로고침으로 최신 의견을 읽을 수 있다. 의견/답글의 클라이언트 UUID를 요청 동안 유지해, 커밋 후 응답을 잃고 같은 요청을 다시 보내도 중복으로 추가하지 않는다. 실제 입력을 바꾼 새 의견/답글은 새로운 요청 ID를 쓴다. 작성 중 입력의 영구 오프라인 보관이나 다중 기기 입력 초안 동기화는 구현하지 않았다.

텍스트 2,000자, 표시 이름 80자, 실제 요청 스트림 16KiB, 한 의견의 최초 글·답글 합계 20개, 링크당 의견 100개·작성자당 20개로 제한한다. 삭제도 해당 링크의 저장 개수에 포함해 반복 생성/삭제로 제한을 우회하지 못하게 한다. 10개씩 페이지를 읽고 **이전 의견 더 보기**로 이어간다. 열린 화면은 30초마다 목록을 새로 읽으며 작성 중에는 자동 갱신 요청을 시작하지 않는다.

중단/미발행 링크에는 댓글 읽기·쓰기를 거절한다. 인증/본문 읽기 후와 응답 직전에도 중단을 다시 확인한다. 공유 중단은 댓글 레코드도 정리하며, 정리 실패는 링크 차단을 유지하고 재시도 오류로 알린다. R2의 상태와 D1은 하나의 분산 트랜잭션이 아니므로 마지막 상태 확인 이후 동시에 중단하면 접근 불가능한 고아 레코드가 남을 가능성은 있다. 중단 재시도로 정리할 수 있다. 테스트의 순차 회수는 실제 D1 잔여 0개를 확인했다.

## 검증 및 배포 상태

새 회귀 **20개**로 공개 allowlist/공간 범위·내부 데이터 분리, 작성자/소유자 권한, 페이지·문자/스트림 제한, 삭제 내용 제거, 동시 CAS, 응답 유실 재전송, 인증 지연 중 회수, 실제 API/SQLite 클라이언트 왕복, 안전한 로그인 복귀 경로, 정적 React 권한 제어·텍스트 escaping·평면 위치 마커를 검증했다. 계정 제공자 응답은 명시적 테스트 대역이다.

별도 `127.0.0.1:8816` Wrangler의 실제 로컬 HTTP/R2/D1과 임시 저장소에서 마이그레이션을 적용하고 합성 A/B 및 기존 키로 새 통합 검사 1개를 통과했다. Scene 댓글·답글 중복 재전송·동시 변경 200/409·타인 수정 403·소유자 삭제를 확인했고 R2 스냅샷 본문이 댓글 전후 동일했다. 테스트 공유 2개를 회수해 댓글/스냅샷 모두 410을 확인했고, D1 직접 조회에서 댓글 잔여 **0개**를 확인한 뒤 Worker를 종료했다. [원본 결과](../validation/2026-10-07-review-comments-native.json).

전체 **1,052개 통과 / 선택 통합 검사 8개 제외**, TypeScript·Vite 빌드 통과. 새 통합 검사 1개는 위 로컬 Worker에서 별도로 통과했다. 실제 로그인·이메일 복귀·브라우저 조작·운영 댓글·운영 마이그레이션/배포·전체 제품 인수는 미완료다. 사용자 결정대로 인증·브라우저 대기는 보류했다. 다음 독립 구현은 §56의 역할/초대/공동 작업이며 고급 IES/Lux·AI·유료 사진 생성은 별도 후속 범위로 유지한다.
