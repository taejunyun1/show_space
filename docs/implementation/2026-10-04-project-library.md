# 2026-10-04 프로젝트 목록·독립 로컬 저장

T2의 프로젝트 관리와 오프라인 저장 부분을 구현한다. 상단 프로젝트에서 검색·새 프로젝트·열기·복제·보관·복구를 지원한다. 새 프로젝트는 이름·전시장·실측 너비/깊이/벽 높이·실내/야외를 입력해 작품 없는 네 벽으로 시작한다. mm 정본을 유지하며 단위 선택 Home 화면은 아직 별도 구현하지 않았다.

## 저장과 호환

- IndexedDB `gonggan-project-library-v1`의 documents는 전체 Project, summaries는 목록용 이름/전시장/수정일/createdAt/revision/보관 상태, settings는 마지막 선택을 보관한다. 목록을 열 때 3D 모델과 이미지 전체를 읽지 않는다. 기존 프로젝트 모델은 변경하지 않는다.
- 기존 `gonggan-project-v1` 단일 초안을 최초 한 번 이전하며 원본 키를 삭제하지 않는다. 성공한 이전 후에는 프로젝트 목록의 최신 문서를 사용한다. 기존 Scene·GLB·도면·메모 사진 등 모든 편집 필드를 그대로 보존한다.
- 문서와 목록 메타데이터를 같은 readwrite 트랜잭션으로 저장한다. expectedRevision 비교가 다른 탭의 오래된 덮어쓰기를 차단한다. 충돌한 메모리 작업은 복사본 생성으로 다른 ID에 저장하고 최신 원본은 유지한다. 복사본 생성 전에 탭을 닫으면 저장되지 않은 충돌 작업은 사라질 수 있으므로 이번 단계가 자동 충돌 병합/영속 recovery journal을 구현한 것은 아니다.
- 새로 읽은 프로젝트를 다시 쓰지 않는다. 실제 두 탭 확인에서 불필요한 hydration 자동 저장을 발견해 수정했고 읽기만 한 탭은 revision을 증가시키지 않는 회귀 테스트를 추가했다.
- 전환·생성·복제·가져오기 전에 대기 중 저장을 flush한다. 저장 오류가 있으면 전환을 중단하고 현재 작업 복사본 경로를 제공한다. 읽기/쓰기 중에는 목록 창을 닫아 동시 편집을 시작할 수 없도록 한다.
- JSON·백업 ZIP 복원은 새 프로젝트 ID로 목록에 추가한다. 같은 ID의 기존 작업을 덮어쓰지 않으며 직전 작업은 목록과 별도 JSON 백업 파일에 보존한다. 원본 이름·자산/객체 ID/배치/Scene은 유지한다.
- 보관은 문서/자산을 삭제하지 않는다. 현재/마지막 선택 프로젝트 보관을 막고 보관된 목록에서 복구한다. 영구 삭제 UI는 없다. 저장 공간은 브라우저 한도에 따르며 계정이나 기기 간 동기화는 아직 없다.

## 검증

전체 자동 테스트 669개 통과·선택 벤치마크 2개 제외, TypeScript·프로덕션 빌드 통과. 공식 npm의 테스트 전용 fake-indexeddb로 실제 IndexedDB API/트랜잭션을 실행해 독립 연결의 동시 저장·stale revision·복사본 복구·보관/복구·기존 단일 초안 이전·새로고침 경로를 검증한다. 목록 저장 실패를 주입해 문서와 revision의 원자적 롤백 및 재시도를 확인했다. 기존 편집기 회귀 테스트와 저장 flush도 유지한다.

실제 로컬 브라우저 두 탭에서 기존 초안 이전, 14,000×9,000mm/벽 높이 4,500mm의 새 전시, 복제·검색·보관/복구·열기·저장과 새로고침을 확인했다. 탭 A 저장 후 탭 B의 오래된 저장을 거부하고 B 작업을 복사본으로 저장해 두 버전을 유지한다. 전시장 전체 예제 JSON을 새 항목으로 가져온 뒤 이전 4개 프로젝트가 유지됐고, 원래 전시의 3D 작품·메모 사진(320×180px)을 다시 열었다. 편집기 콘솔 경고/오류 없음.

실기기 모바일·다른 브라우저/기기 간 데이터 이동·실제 다중 계정·대용량 목록 성능은 이번 검증 범위에 포함하지 않는다. `../validation/2026-10-04-project-library.json`과 목록/충돌 화면을 기록한다.

## 계정·클라우드 저장 연결 단계

현재 배포는 로그인 없는 로컬 저장과 기존 작성자 키의 공유 API다. 표준 인증 제공자가 아직 연결되지 않았으며 T2 전체 완료로 집계하지 않는다. Supabase 프로젝트 URL/공개 publishable 또는 anon 키의 유무를 사용자에게 확인 중이다. 인증 서비스 계정 생성/약관 수락이나 비밀 키 발급을 대신 실행하지 않았다.

다음은 표준 SDK의 세션/로그인, Worker의 서버 측 사용자 검증과 소유권 경계, D1의 프로젝트 메타데이터/revision 포인터, R2의 불변 프로젝트 스냅샷/자산, 계정별 목록/저장·충돌 복구 순서다. 원래 계획의 D1 메타데이터/R2 자산 분리를 유지한다. 로컬 초안은 명시적인 클라우드 저장 전까지 서버에 업로드하지 않는다. 구성 후 실제 로그인·타 계정 접근 거부·오프라인 복구·두 기기 저장 충돌을 별도로 검증해야 한다.

공식 참고: [Supabase React Auth](https://supabase.com/docs/guides/auth/quickstarts/react), [공개 키와 사용자 인증](https://supabase.com/docs/guides/api/api-keys). 인증 SDK/클라우드 API는 아직 이번 코드에 추가하지 않았다.
