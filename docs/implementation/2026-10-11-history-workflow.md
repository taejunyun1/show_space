# 버전 기록 저장·비교·복원과 작업 보호

2026-10-11. 프로젝트 전체 복원은 현재 작업과 복원 직전 안전 기록을 보존해야 한다. 기존 버전 기능의 UI·저장 연결을 검증하고 지연 작업 문제를 수정했다.

## 수정

버전 창을 닫거나 프로젝트를 A→B→A로 전환한 뒤에도 이전 읽기·백업·복원이 진행됐다. 같은 프로젝트에 추가 편집이 들어와도 이전 비교 결과와 복원 작업이 살아 있었다. 이미 저장된 복원 응답을 기다리는 사이 새 편집이 들어오면 탭의 저장 revision이 뒤처져 다음 Auto Save도 충돌했다. 다른 프로젝트를 목록에서 복원할 때 부모 창이 두 번 닫혔다.

버전 화면에 기존 프로젝트 작업 scope와 클릭 시점의 편집 객체 검사를 연결했다. 초기 준비와 중복 실행, 목록 응답 순서를 보호하고 선택 대상 프로젝트가 바뀌면 화면을 다시 만든다. 현재 내용이 바뀌면 기존 비교/미리보기를 비운다. 버전 읽기·이미지 검증·ZIP 준비·안전 기록 저장 뒤, 실제 프로젝트 교체 transaction의 요약 조회 뒤에도 검사한다. 새 편집이나 이동·회전 미리보기가 있으면 이전 교체를 거절한다.

복원 직전 자동 보관이 이미 저장된 경우 실패 후 목록을 갱신해 해당 기록을 표시한다. 저장소가 프로젝트 교체를 이미 수락했다면 확정 revision을 먼저 기억한다. 이후 UI 검사가 작업을 취소하더라도 새 편집은 유지하고 다음 Auto Save가 확정 revision에서 이어진다. 다른 프로젝트 복원으로 부모 scope가 이미 종료됐다면 다시 닫지 않는다. 다른 탭 revision 충돌, 보관 프로젝트와 저장 공간 제한 검사는 유지한다.

## 검증

새 `ProjectHistory.workflow.test.tsx` 19개는 실제 React StrictMode/버전 창/부모 프로젝트 목록, Zustand, Auto Save 대기열과 생산용 persistence·project/history repository를 실행한다. 독립 fake-indexeddb와 별도 repository 재읽기를 사용하며 실제 native PNG decode/Canvas encode·ZIP CRC/해시/복원을 연결한다. 합성 전시장 GLB bytes, 재질 PNG/실제 크기·노멀 강도, 비공개 메모/체크리스트/참고 사진, Scene을 포함한 프로젝트를 사용한다.

- 현재 버전 저장→별도 repository 재읽기→기존 버전과 비교→전체 복원→복원 전 최신 내용의 자동 보관→다음 편집/Auto Save를 확인한다. 복원 후 Undo는 새로 시작한다.
- 선택 버전 ZIP을 실제로 다시 가져와 원본과 비교한다. 보관·복구·영구 삭제 확인/취소 및 저장 공간 집계를 확인한다. 삭제 대상은 테스트가 생성한 기록이다.
- 준비 중 unmount/프로젝트 왕복, 지연 버전 읽기·백업·안전 ZIP 준비 후 새 편집에서 이전 다운로드/교체/새 기록 쓰기를 차단한다. 같은 값의 프로젝트 ID로 돌아와도 작업을 재개하지 않는다.
- 비교 결과를 편집 이후 비우고 재선택으로 최신 내용을 비교한다. 실제 checksum이 유효하지만 PNG 본문이 손상된 ZIP은 native decoder에서 거절한다.
- 안전 기록 용량 제한과 별도 repository의 revision 변경에서 현재 프로젝트를 유지한다. 실제 IDB readwrite transaction의 summary query success 중 새 편집을 넣으면 교체 transaction을 abort한다.
- 안전 기록 쓰기가 이미 수락된 뒤 지연 응답 중 추가 편집을 넣으면 안전 기록은 남고 목록에도 표시한다. 프로젝트는 교체하지 않는다.
- 프로젝트 교체가 이미 수락된 뒤 응답 중 새 편집을 넣으면 UI는 새 내용을 유지한다. 확정 revision 3을 기억하고 다음 Auto Save가 유지한 최신 내용을 revision 4로 저장한다.
- 실제 부모 프로젝트 목록→다른 프로젝트 버전 비교/복원을 연결해 원래 편집 프로젝트의 DB 내용 유지와 부모 close 1회를 확인한다.
