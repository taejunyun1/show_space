# 벽·바닥 직접 텍스처 및 실측 반복

2026-10-03. T7 기본 재질의 직접 이미지 적용과 텍스처 크기 인수 조건을 연결했다. 사진에서 재질을 생성하는 Photo to Material은 사용자 결정대로 후속 유료 기능이다. 상단 불러오기는 도면 JPG/PNG/PDF, GLB 참고 모델, 저장 JSON/백업 ZIP을 받으며 원본 SKP는 아직 지원하지 않는다.

## 동작

- 벽 속성의 재질과 바닥 재질 창에서 JPG/PNG/WebP를 선택한다. 입력 20MiB·6,000만 픽셀 이하, 긴 변 2,048px로 축소한 WebP를 저장한다. 격자 예제는 같은 File 디코딩 경로로 처리한다.
- 이미지 한 장의 실제 폭·높이를 1–1,000,000mm 범위로 지정한다. 벽 6면의 UV는 미터 단위이며, 바닥은 전시장 전체 X/-Z 기준으로 연결된다. 길이·높이·바닥 면적이 달라져도 무늬 크기는 유지한다.
- 이미지 처리 중 선택한 벽이 바뀌거나 편집기가 사라지면 결과를 적용하지 않는다. 잠긴 벽에는 텍스처 변경을 적용하지 않는다. 작품은 원래 작품 이미지를 유지한다.
- 비동기 이미지 완료 후 material shader를 갱신한다. 처음의 map 없는 shader에 텍스처가 표시되지 않던 문제를 브라우저에서 발견하고 수정했다. 이미지 로딩 실패는 표면 위에 표시하며 원래 재질은 유지한다. 로더/반복 clone은 해제한다.
- Undo/Redo·Scene·로컬 저장·JSON에 이미지와 실측 크기를 보존한다. 백업 ZIP은 루트/숨긴 벽/모든 Scene의 표면 이미지까지 수집하고 SHA-256로 중복을 제거한다.
- 공유 스냅샷에는 이미지 URL 대신 자산 ID와 크기만 포함한다. Worker는 작품과 표면 이미지의 업로드 완료를 확인하고 허용된 ID만 열람한다. 동일한 표면 이미지는 한 번 업로드한다. 폐기한 공유의 이미지도 열람할 수 없다.
- GLB/glTF는 미터 UV와 RepeatWrapping/KHR_texture_transform을 보존한다. 이미지 긴 변 최대 1,024px. PDF 3D도 같은 export scene을 사용한다.

## 검증

자동 테스트 583개 통과, 2개 생략. 치수/입력 allowlist, 6면 UV, 평면·돌출 바닥 일치, clone 독립/해제, 누락 이미지 거부, JSON·Undo·잠금·Scene·ZIP 복원, 실제 클라이언트와 메모리 Worker 업로드/publish/GET/폐기를 검사했다.

로컬 Wrangler 8798의 R2만 사용했다. 공개 버킷에 새 공유를 게시하지 않았다. 격자 File 처리, 벽 500mm·바닥 1,000mm 렌더, 즉시 추가·제거·재추가, 잠금, 새로고침, 읽기 전용 공유를 실제 조작했다. OS 파일 선택기를 통한 사용자 파일 입력은 이번 브라우저 검증에 포함하지 않았다.

실제 다운로드한 ZIP의 CRC와 모든 자산/프로젝트 해시, 벽/바닥 중복 이미지 한 장과 각각의 치수를 확인했다. GLB와 glTF의 이미지 6개 및 벽 repeat scale [2,2], 반복 sampler를 확인했다. PDF 한 페이지의 1,920×1,519px RGB 이미지를 추출해 벽·바닥 무늬를 확인했다. 자세한 기록과 화면은 `docs/validation/2026-10-03-textures.json` 및 같은 날짜 texture PNG에 있다.

## 남은 범위

기존 이미지를 반복하는 base-color map이다. 사진 원근/밝기 보정, seam 생성, Normal/Bump 자동 생성, 정확한 거울 상은 포함하지 않는다. 3D 작품 GLB/glTF, 계정 저장, Spot/Area와 야외 환경, 대형 전시장/모바일 실기기 검증은 별도로 남아 있다. 전체 제품 목표를 완료 처리하지 않는다.
