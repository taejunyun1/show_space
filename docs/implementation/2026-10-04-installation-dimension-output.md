# 2026-10-04 설치 치수 전달

## 구현

- 편집기·PDF·공유 화면에서 액자/매트·회전을 포함한 동일한 벽면 외곽 계산을 사용한다. 가로/세로 축 간격이며 비스듬한 다각형 간 최단 거리를 의미하지 않는다. 교차축이 겹치는 가까운 이웃만 표시한다.
- PDF 벽면도에는 작품 간격 선을 그리며 작품 번호는 회전 외곽 위로 옮겨 간격과 겹치지 않는다. 치수 목록 옵션을 켜면 각 A/B면의 작품별 바닥·화면 좌우 벽 거리, 이웃 작품 이름과 가로/세로 간격을 추가한다. 긴 목록은 글자를 과도하게 줄이는 대신 줄바꿈/페이지 나눔한다. 기존 내부 메모 제외와 Scene별 배치 선택을 유지한다.
- 공유 링크의 `dimensions` 공개 선택이 있을 때만 선택 작품의 치수선과 선택 정보 목록을 표시한다. 작은 도면 간격은 짧은 숫자, 자세한 이름/의미는 읽기 쉬운 목록에 표시한다. 작품을 선택하면 해당 A/B면으로 전환한다. 입력/이동/회전/삭제 도구는 추가하지 않는다.
- 공개 스냅샷 허용 목록과 형식을 바꾸지 않고 이미 공개한 형상에서 계산한다. 과거 링크도 같은 공개 치수 선택을 따른다. 편집 상태와 그룹 변경 함수를 불러오지 않도록 기하 계산을 분리했다. 콜론을 포함한 가져온 작품 ID가 서로 다른 간격 키를 충돌시키지 않게 처리한다.

## 검증

781개 테스트 통과, 선택 벤치마크 2개 제외. TypeScript/Vite 빌드 통과(기존 큰 청크 경고 유지).

합성 로컬 프로젝트를 실제 입력 메뉴로 불러와 벽면/PDF 목록을 다운로드했다. 최종 PDF는 3페이지·5,460,092 bytes이며 PDF.js 텍스트 추출/렌더에서 A면 세로 250mm, 90° 회전한 B면 가로 250mm, 바닥 1260mm, 화면 왼쪽 2830mm/오른쪽 4390mm를 확인했다. 작품 번호 겹침을 수정한 이미지를 재검증했고 메모는 없다. 긴 이름의 PDF 행은 별도 테스트에서 모든 텍스트가 용지 좌우 여백 안에 위치함을 확인했다.

실제 로컬 두 공유 링크에서 동일한 B면 거리와 읽기 쉬운 목록, 치수 비공개의 선/목록/mm 텍스트 없음, 실제 작품 드래그 후 같은 이미지 위치·같은 치수, 390px clientWidth/scrollWidth 390과 목록을 확인했다. 콘솔 경고/오류는 없다. 합성 검증 링크만 중단하여 사용자 초안/공유는 변경하지 않는다.

증거: `../validation/2026-10-04-installation-dimension-output.json`, `../validation/2026-10-04-installation-output-pdf-text.json`, PDF 1~3 렌더 PNG와 공유/모바일 화면 PNG.
