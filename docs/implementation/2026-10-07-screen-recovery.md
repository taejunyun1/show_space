# 배포 변경 및 화면 오류 복구 — 2026-10-07

배포 뒤 오래 열린 탭이 이전 lazy 화면 파일을 요청하면 오류가 편집기 전체로 전파되어 빈 화면이 됐다. 시작 화면·3D·재질 Library·PDF·발표·현장 설치·시간대 비교·프로젝트 버전 기록에 복구 경계를 추가했다. 개별 화면은 복구 안내를 닫아 다른 편집을 계속할 수 있다. 기존 일반 WebGL 오류의 평면도 전환도 유지한다.

자동 새로고침은 하지 않는다. 사용자가 ‘작업 저장 후 새로고침’을 누르면 기존 저장 큐의 완료를 기다리고, 현재 초안과 저장된 프로젝트를 대조해 필요한 저장을 완료한 뒤 재시작한다. 큐가 실패한 경우 같은 revision 검사 writer로 재시도한다. 저장 용량·다른 탭 충돌·보관 상태·저장 중 추가 수정 등의 실패는 재시작을 중단한다. 편집기가 오류로 unmount된 뒤에도 원래 큐와 최신 프로젝트를 읽는 복구 함수를 유지한다. 저장 성공 후 unload guard 상태를 해제한다.

화면 파일 추가 다운로드에 의존하지 않는 JSON 백업 버튼을 제공한다. 백업에는 현재 프로젝트 전체가 들어가며, 도면·3D 불러오기 → 저장 프로젝트 복원으로 새 항목에 가져올 수 있다. 시작부터 App 파일을 못 읽은 경우 아직 확보하지 않은 작업을 백업했다고 주장하지 않고 화면 새로고침만 제공한다. 복구 영역에 초점을 옮기며 기술 오류의 원문이나 내부 정보를 사용자 화면에 표시하지 않는다.

## 검증

격리된 localhost:8814의 assets 전용 Wrangler와 실제 제품 App/IndexedDB로 확인했다. 재질 화면 및 App 파일을 임시로 옮겨 누락을 만들고, 테스트 전용 UI로 저장/렌더 오류를 주입했다. 운영 앱에는 주입 버튼·테스트 서버 코드를 넣지 않는다. 테스트 파일은 전부 복원했고 서버/탭은 종료했다.

- 재질 화면 누락 → 편집기 유지·복구 영역 초점 → 저장 실패 시 재시작 중단 → JSON 다운로드 → 안내를 닫고 계속 편집.
- 파일 복원·정상 저장 → 새로고침 → 작품 폭 1,350mm와 설치 메모 및 재질 Library 유지.
- 폭 1,400mm 수정 직후 편집기 전체 오류 → 저장·JSON 백업 버튼 유지 → 재시작 뒤 폭·메모 보존.
- App 초기 파일 누락 → 새로고침 안내. 390×844px에서 문서 scrollWidth 390px, 안내 폭 358px.
- 실제 내려받은 복구 JSON을 파일 선택으로 다시 가져오기 → 폭 1,400mm·메모 복원, 이전 항목까지 로컬 목록에 두 프로젝트 유지.

복구 관련 14검사, 전체 960검사 통과/2개 선택 벤치마크 생략. TypeScript·production build·diff 검사를 통과했다. 실제 fake-indexeddb 저장과 CAS로 실패한 큐의 재시도 및 다른 탭 수정 보존을 별도 검증했다. 기존 큰 chunk 경고는 남아 있다. 기록: [검증 JSON](../validation/2026-10-07-screen-recovery.json).

## 한계 및 남은 제품 범위

React bootstrap이 실행되어야 복구 경계가 동작한다. HTML/bootstrap 자체 누락이나 브라우저 전체 실패, 모든 비동기·이벤트 오류를 해결했다는 뜻은 아니다. 공개 배포에 파일 누락/용량 오류를 의도적으로 만들지 않았다. 실제 로그인·두 기기·원문 연속 인수 및 영상/프로젝션 등 요구사항 대조표의 미완료 항목은 남는다. 이번 안정화는 최종 제품 전체 완료가 아니다.

## 공개 배포 검증

소스 `c309195`를 main에 푸시하고 Cloudflare `08d7d1c1-a22b-46cd-bd01-3ea052f7cf73`로 배포했다. 공개 entry는 `/assets/index-CniTehc8.js`다. 실제 브라우저에서 새 버전을 열고 재질 Library·PDF lazy 화면·JPG/PNG/PDF 및 SketchUp GLB 입력 메뉴를 확인했다. 점검한 공개 흐름의 콘솔 경고/오류는 없다. 공개 프로젝트 데이터는 변경하지 않았으며 운영에 실패를 주입하지 않았다. keep-vars로 변수·D1/R2를 유지했고 migration은 필요하지 않았다. 로그인 서비스는 여전히 연결 전이므로 실제 계정 동기화 완료로 집계하지 않는다. 이번 복구 경계가 없는 이전 코드로 이미 열린 탭까지 소급해서 보호하는 것은 아니며 새 버전부터 적용된다.
