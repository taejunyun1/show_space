# 도면 입력·축척 보정과 Scene/이력 복원 연결

2026-10-11. 원문 1 §3–5/24–26/40의 가벼운 도면 입력→직접 편집→Scene/Undo/Redo 흐름에서 남아 있던 작업 상태를 보완했다. 인식 알고리즘이나 도면 완전 복원 범위를 확대하지 않았다.

## 수정한 동작

같은 ID의 프로젝트/Scene/이력을 복원하면 이전 도면 가져오기 창이 계속 활성화돼, 복원된 전시에 옛 초안을 적용할 수 있었다. 페이지 선택 중에도 오래된 진행 메시지와 결과가 도착했다. 축척·도면 좌표가 같으면 이미 클릭한 보정 점이 남아 다음 작업에 재사용됐다.

- 도면 가져오기는 기존 `projectContextVersion`의 복원 전환도 감시한다. 프로젝트 ID가 같아도 문서 로드·Scene·Undo/Redo에서 창을 닫고 배치/초안 적용을 차단한다. 늦게 도착한 decoder 문서는 해제하며 페이지를 렌더하지 않는다.
- PDF 페이지 작업의 AbortController를 즉시 취소한다. 실제 `selectPlanPage`가 전달받는 signal을 중단하고 지연 진행 메시지/페이지는 무시한다. 이미 실행 중인 이미지/PDF decoder 자체를 강제로 종료한다고 주장하지 않는다.
- PlanView도 복원 전환에서 가져오기·후보 창, 축척 보정 점, 미확정 그리기/드래그 상태를 정리한다. 같은 도면/축척의 확대·Hand 위치는 유지한다. 중단한 Hand의 오래된 move/up은 무시하고 새 드래그는 가능하다. 도면 좌표/축척 변경 시 화면 맞춤은 기존 동작대로 유지한다.
- 이름/메모 같은 일반 수정이나 Scene 저장만으로는 입력·보정 작업을 폐기하지 않는다. 초안 적용은 최신 메타데이터를 유지한다. 새 공간 초안을 채택하면 이전 내용이 대체되는 기존 규칙은 유지하며, 한 번의 Undo로 이전 Scene과 작업을 복구한다.

`useProjectDialogScope`에 선택적인 복원 감시를 추가했으며 도면 가져오기에서만 켰다. 출력·공유·버전 기록·Library 창의 스냅샷 정책은 변경하지 않았다. 새 데이터 schema/API/의존성을 추가하지 않았다.

## 검증

실제 React/jsdom StrictMode, PlanImportDialog·PlanView·NumberField 및 store에서 새 13개를 추가했다. 문서 로드·Scene·Undo/Redo 각각에서 준비된 옛 입력을 거절하고 같은 좌표의 보정 점을 폐기한다. 두 StrictMode decoder의 지연 도착 해제, PDF signal/지연 메시지, 일반 수정 중 배치/보정 지속과 Hand 중단/재시작을 확인했다. 지연 decoder/PDF/분석과 DOM 좌표는 제어 가능한 transport이며 실제 브라우저 포인터/Worker 실행 근거가 아니다.

같은 최종 27개를 임시 소스 복사본에서 이전 main `5a9c0e647571605a6e8c35d69cc3298ca206e8b8`의 제품 3파일로 실행하면 **10 실패/17 통과**, 변경 후 전부 통과한다. 원 작업 폴더를 되돌리지 않았다. 공유 node_modules의 PDF worker URL을 Vite가 거절하던 임시 검증 설정을 allow 목록으로 수정했으며, 그 첫 0개 실행은 제품 실패로 집계하지 않는다. 새 테스트의 타입에 맞지 않던 patchProject 호출도 실제 commit/renameProject 명령으로 수정했다.

기존 실제 JPEG 픽셀→가벼운 벽 초안 검증과 같은 App 전시의 PDF 입력→보정→벽 연결/Hand→10점 배치→재질/Note/조명→Scene A/B→PNG/PDF/GLB/ZIP→로컬 Worker 공유 발행·회수도 현재 코드에서 통과한다. 이것은 합성 입력/native Canvas/SQLite/R2 연결 근거다. GPU transport·3D preview renderer 및 OCR은 해당 테스트의 기존 adapter 범위를 유지한다. 새로운 실제 사용자 도면 성공률이나 운영 URL 검증으로 집계하지 않는다.

명령과 최종 테스트/빌드·동일 소스 해시는 [검증 기록](../validation/2026-10-11-plan-restoration-workflow.json)에 보존한다. 기존 큰 청크 안내는 유지한다.

## 남은 범위

실제 브라우저/GPU·3D PNG/PDF 픽셀, 운영 인증·계정/두 기기와 공유 URL, 사용자 도면/모델 및 SketchUp 수신, 성능·사용자 성공 지표와 원문 24단계 전체 인수는 완료되지 않았다. 유보한 문·설비·설치 제외 영역 직접 편집 및 유료 사진→재질 생성은 확대하지 않는다. 이번 변경은 Git에 기록하고 즉시 배포하지 않는다.

다음은 같은 전시의 도면 재입력/재분석과 저장된 Scene 사이에서 도면 이미지·축척·공간이 함께 복원되는지 확인한다. 기존 연속 테스트는 같은 도면을 유지하는 경우를 다루므로, 서로 다른 도면의 복원까지 증명하지 않는다.
