# 서로 다른 도면의 Scene 저장·복원과 백업

2026-10-11. 원문 1 §3–5/24–29/40의 도면→공간→Scene→전달 흐름을 보완했다. 도면 인식 자체를 강화하거나 완전 복원 범위를 늘리지 않았다.

## 발견한 문제와 수정

Scene이 벽 구조만 저장하고 도면 이미지·축척·분석 근거를 저장하지 않았다. 도면 A에서 Scene을 만든 뒤 B를 불러오면 A 복원 시 벽은 A, 참고 이미지·축척은 B인 상태가 됐다. 축척 보정 함수도 모든 Scene 좌표를 바꾸어 다른 도면의 저장된 공간까지 확대했다.

- 새 `SceneStructure.plan`에 도면 이미지/투명도, 축척/원점/크기, 표기·분석, 원본 도면과 편집 초안의 원본 벽을 함께 캡처한다. 썸네일 생성 중 입력이 바뀌어도 캡처를 시작한 source의 도면을 저장하고 현재 편집 내용은 유지한다.
- 편집기 복원과 출력·공유용 `sceneProject`가 같은 도면 복원 함수를 사용한다. 새 Scene의 빈 `{}`는 도면 없이 저장했다는 뜻이므로 이후 도면 필드를 모두 제거한다. 예전 파일의 필드 부재는 기존처럼 현재 도면을 유지하며, 원래 Scene의 도면을 추측해 채우지 않는다.
- 미보정 초안 Scene을 복원하면 PlanView로 돌아가 기존 3D 제한을 지킨다. 복원은 한 번의 Undo/Redo이고 최신 프로젝트 이름·메모 정책도 유지한다.
- 프로젝트/Scene은 같은 validator로 각자의 도면 크기를 기준으로 표기·선·축척·원본·초안을 검사한다. Scene의 알 수 없는 도면 필드는 거절한다. 현재 도면 B가 작아져도 A의 표기를 B 크기로 검사하지 않는다.
- 편집 초안 보정은 새 Scene의 원본 근거/이미지/좌표 체계가 현재 초안과 같은 경우에만 좌표와 저장 축척·원본 벽을 함께 바꾼다. 다른 도면과 도면 없는 Scene은 유지한다. 기존 Scene의 필드 부재는 기존 단일 도면 보정 정책을 유지한다.
- 자산 백업 walker가 Scene의 도면/원본 이미지와 초안 원본 벽의 자산도 처리한다. 이미지별 SHA 자산으로 중복 제거해 저장하고 import/decode 목록에서도 같은 경로를 복구한다. 프로젝트 schemaVersion 및 ZIP manifest version은 1을 유지하는 선택적 필드 확장이다. 이번 코드가 기존 파일을 읽는 경로를 유지하며, 오래된 앱이 새 Scene 도면 기능을 수행한다는 뜻은 아니다.

## 하나의 입력 작업으로 검증한 결과

기존 PlanImport.workflow의 native JPEG 사례를 확장했다. 실제 React/jsdom PlanView·가져오기 창·NumberField·store, 실제 `loadPlanFile`/`analyzePlan`의 이미지/Canvas·로컬 벽/설비 픽셀 알고리즘을 실행한다. Worker 메시지/DOM 좌표 transport를 연결하고 이 합성 입력의 OCR은 빈 결과다.

1. 소유한 합성 JPEG A(1000×800)의 벽 픽셀을 읽어 초안으로 적용한다. 실제 두 점·100cm 숫자 입력으로 10mm/px를 보정하고 도면 A Scene을 저장한다.
2. JPEG B(800×1000)를 실제 파일 입력으로 읽어 참고 도면으로 배치한다. 벽 끝점·전시 이름을 수정하고 도면 B Scene을 저장한다.
3. A/B를 실제 store로 복원한다. 각자의 이미지·축척·분석·초안·벽과 SVG background href가 일치한다. A 복원을 한 번의 Undo/Redo로 왕복하고 최신 이름을 유지한다.
4. 같은 현재 프로젝트에서 두 Scene의 detached 출력 입력을 만들고 각자의 도면/벽을 검사한다. 전체 ZIP을 실제 export/import해 프로젝트를 정확히 복구한다. ZIP JSON의 모든 도면 참조는 자산 포인터이고 이미지 자산은 서로 다른 PNG 2개다. CRC와 내장 이미지 원본 바이트가 일치한다.

별도 domain 19개는 캡처 source/현재 편집 분리, 도면 없는 새 Scene/기존 Scene 호환, 미보정 Scene 제한, 잘못된 필드 11종, 독립 크기의 표기 검증, 다른 도면을 유지하는 두 번의 보정, Scene에만 남은 도면/원본 PNG 3자산 백업과 공개 준비의 비공개 도면 제외를 확인한다.

실제 저장 PNG 2개는 각각 1000×800/800×1000이다. 별도 Sharp decoder로 JPEG와 PNG의 벽 내부/배경 **RGB 표본 8개**를 비교해 최대 오차 **0**을 확인했고, ZIP 내 PNG의 SHA/바이트를 파일과 대조했다. 전 픽셀 비교·복잡한 실제 사용자 도면 정확도·최종 브라우저 화면 인수를 주장하지 않는다.
