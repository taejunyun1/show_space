# 저장 보호 및 연속 출력 검증

ANCA 공식 PDF를 가져온 기존 테스트 프로젝트에서 작업을 이어갔다. 17개 벽 초안, 실제 이미지 파일 1개를 복제한 10개 작품, 두 Scene을 사용했다. 서로 다른 사용자 작품 10장을 사용한 검증으로 집계하지 않는다.

## 수정

- 저장 대기·실패 중에는 beforeunload 보호를 등록한다. 숨김·pagehide·편집 종료 시 250ms 대기를 건너뛰고 저장 큐를 시작한다. 저장이 끝나면 이탈 보호를 제거한다. 비동기 IndexedDB는 브라우저 강제 종료나 모바일 프로세스 종료까지 보장하지 않는다.
- 바닥 경계 안내를 3D 형상 내부에서 Workspace의 고정 안내로 옮겼다. 캡처에 포함되지 않고, 390px에서도 보기·품질 버튼을 가리지 않는다. 알림은 보기 버튼 위로 이동하고 닫기 버튼 외에는 포인터를 가로채지 않는다.
- 10개 작품의 긴 PDF 벽면도 목록이 페이지 밖으로 넘치는 현상을 실제 출력에서 발견했다. 벽면도 목록은 8pt를 유지하고 여백 안에서 말줄임한다. 전체 이름은 치수 목록에서 줄바꿈해 보존한다. 다른 단일 행도 최소 글꼴 크기에서 폭을 넘으면 말줄임한다.

## 실제 결과

같은 프로젝트에서 PNG(1920×1519), 현재 배치·Scene A/B PDF(18페이지), JSON과 GLB 파일을 브라우저 버튼으로 저장했다. PDF 벽면도에는 100mm 작품 간격이 표시되고, 긴 목록은 여백 안에 있으며 10번째 작품 전체 이름은 치수 목록에 남는다. JSON에는 편집 메모와 Scene 구조/시점이 유지된다. PDF·GLB에는 테스트 비공개 메모가 없다. GLB 헤더·JSON/바이너리 크기는 확인했지만 SketchUp 등 외부 수신 도구 재수입은 검증하지 않았다.

로컬 Worker의 로컬 D1/R2에 합성 작성자 키로 공유 링크를 만들었다. 수신 화면에서 공개한 Scene A로 전환하고 작품의 0.4m×1.2m×0.03m 및 0.1m 간격을 확인했다. 비공개 메모·미선택 Scene B·편집 입력/삭제 버튼은 없다. 실제 계정 인증이나 운영 공유 생성으로 집계하지 않는다.

841개 테스트 통과, 선택 벤치마크 2개 생략, 빌드 통과. 저장 수명주기 4개 회귀 테스트와 실제 PDF 장문 목록 회귀 테스트를 포함한다. 데스크톱 및 390×844 브라우저에서 화면을 확인했다. 실제 모바일 기기 성능 검증은 별개다.

검증 수치·파일 해시: [출력 기록](../validation/2026-10-06-autosave-output.json). 화면 증거는 같은 접두사의 capture, pdf-elevation, mobile, share PNG다.

## 남은 인수 범위

ANCA는 원본에 Not to scale이 표시된 도면이다. 두 점 보정 후 벽 초안을 사용했지만, 완전한 외곽·바닥이나 물리적으로 정확한 전시장 복원을 달성한 결과로 집계하지 않는다. 사용자의 인식 범위 축소를 유지한다.

원문 1 §40 전체 연속 인수는 아직 미완료다. 실제 로그인/두 계정·두 기기, 같은 흐름의 Snap 드래그·독립 벽면도 위치 편집·사진 텍스처·Spot/Kelvin·야외 시간·편집 Scene 복원/비교 및 외부 GLB 수신 검증이 남는다. 대표 실기기 성능과 사용자 성공 지표, 문서 2의 후속 확장은 기존 요구 대조표에서 계속 추적한다.
