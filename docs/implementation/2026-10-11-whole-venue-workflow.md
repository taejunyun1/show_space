# 전체 전시장 보존·부분 변환 보호와 Scene 전달

2026-10-11. [복잡한 모델 입력](2026-10-11-model-preflight.md)에 이어 같은 30개 방 모델을 벽/바닥 후보·Scene·백업·공유 데이터·GLB/glTF 전달에 연결했다. 원문 1 §6–10/24–35, 원문 2 §9–18/46/48–55/68의 연결 검증이다. 벽 자동 복원 범위를 확대하지 않는다.

## 제품 수정

이 모델의 실제 원본에는 450 Mesh·중정 30개와 바닥이 있지만, 기존 추출기는 직선 벽 30개만 찾고 바닥 경계는 만들지 못했다. 기존 전환은 원본을 숨기므로 일부 벽만 남아 공간이 불완전하게 보였다. 추출 결과에 ‘바닥 후보가 있으나 경계를 만들지 못함’을 구분하고, 이 경우 기존 전시장을 그대로 유지하며 3D 참고 모델 사용 안내를 표시한다. 전체 모델/기존 벽·작품·Scene·Undo를 바꾸거나 백업 다운로드를 시작하지 않는다. 원래 바닥 후보가 없는 벽 전용 입력이나 정상 경계가 추출된 입력의 전환은 그대로 지원한다. T-junction/복잡한 바닥을 완전 복원한 개선으로 집계하지 않는다.

변환 요청은 화면 수명·프로젝트·원본/배치·전환이 교체하는 공간 데이터에 묶는다. 프로젝트/모델/벽 편집 A→B→A, 제거·unmount, 새 이동/회전, 백업 다운로드 중 프로젝트 변경 뒤의 늦은 결과·오류·finally가 새 작업을 덮지 않는다. 새 모델 작업은 이전 결과를 기다리지 않고 시작할 수 있고 기존 중복 클릭 보호도 유지한다. 프로젝트 이름·전시장 이름 등 유지 가능한 추가 편집은 최신 상태로 백업/전환한다. 공간 비교는 업로드 문자열을 JSON으로 다시 직렬화하지 않는다.

전환이 가능하면 기존 작품은 미배치 목록으로 옮기고 원본은 숨겨 보관한다. 실제 React에서 최신 초안 JSON 백업, legacy Scene의 기존 구조 부착과 한 번의 Undo 복원을 확인했다. 이 성공 전환의 지연 결과는 transport를 제어한 데이터이며 임의 복잡한 사용자 모델의 자동 변환 성공으로 확대하지 않는다.

## 같은 전체 모델의 전달

원본 바이트 32,764개/72×3×40m의 소유한 합성 모델을 실제 File/GLTFLoader/벽 추출 경로로 읽는다. 부분 결과는 벽 30개·삼각형 5,400개/바닥 경계 미해결이며 UI가 원본을 유지하는 실제 연결 검사를 추가했다. 다섯 기존 작품의 미배치 데이터와 비공개 Note를 포함해 다음 흐름을 검증했다.

- Scene A는 원래 배치, B는 [3000,100,-2000]mm/30°/1.2배로 저장한다.
- ZIP은 원본 모델 한 개·공통 PNG 한 개로 중복 제거하고 CRC32·원본 SHA·JSON의 정확한 복원과 미배치 5점을 확인한다.
- 생산용 `prepareSharePresentation`이 공개 Scene 두 개와 모델 한 개를 만들고 비공개 Note·원본 데이터 URL·미배치 자료를 제외한다. 같은 공개 모델을 실제로 읽고 두 배치의 world bounds/450 Mesh를 확인한다. 운영 URL 발행으로 집계하지 않는다.
- 각 Scene을 실제 GLTFExporter로 GLB 출력하고 GLTFLoader로 다시 읽는다. 소스 vertex 기반 독립 yaw/scale/원점 수식으로 world bounds를 비교하고, 각 배치의 중정 30개는 아래 방향 Ray가 비어 있으며 바닥 30곳은 닿는지 확인한다.
- Scene B의 glTF ZIP도 실제 패키지 파서로 다시 묶어 같은 형상/배치·Ray를 확인한다. 입력 파일과 편집 프로젝트는 변경되지 않는다.

새 검사 11개를 같은 최종 파일로 이전 제품 코드 `44bd04f`에 적용하면 9 실패/2 통과, 변경 후 11 통과다. 기존 실제 추출/공간 전환/공개 참고 모델과 합친 대상 5파일 28개 통과. 전체 1,382 통과/선택 10 제외·237파일 통과/10 제외, TypeScript/production build·diff 검사 통과. 초기 테스트 작성 중 Node/jsdom typed-array realm·전시장 문자열의 fixture 형식·공유 Scene 준비 함수 선택을 바로잡은 실패는 제품 오류 전후 근거에서 제외한다. 큰 청크 안내는 유지한다.

## 독립 수신

실제 GLB 두 개를 Blender 4.4.1 importer에 전달했다. 각 파일에서 450 Mesh/5,400 삼각형, world bounds 최대 약 0.005mm 오차, 중정 30개가 비어 있음·바닥 30곳의 hit를 확인했다. 기대 치수를 100mm 틀리게 만든 대조는 import 뒤 실패한다. 현재 GLB SHA가 연속 검증 및 Blender 기록과 모두 일치한다.

두 배치를 Cycles CPU/16 samples/1000×700으로 렌더하고 확인했다. 형상·배치·구멍을 실제 독립 수신기로 확인한 근거이며 서비스 브라우저/GPU 화면 캡처는 아니다.
