# 로그인 계정 공유 연결

개인 프로젝트/Library 로그인과 공개 공유 작성자 인증이 따로였던 흐름을 연결했다. 로그인한 사용자는 공용 작성자 키를 다시 입력하지 않고 자신의 세션으로 링크를 만든다. 수신자는 로그인 없이 고정 배치를 본다.

## 변경

- 기존 서버 `authenticatedUser`/Supabase getUser 검증을 재사용한다. 계정 UUID는 검증된 세션에서만 가져온다. 비로그인·invalid·anonymous는 작성할 수 없고 인증 서비스 오류는 503이다.
- private 메타데이터의 ownerId와 R2 `owners/<UUID>/<share-id>.json` 인덱스로 자신의 링크만 나열한다. 공개 snapshot과 작성자 목록 응답에는 ownerId·이메일·세션이 없다.
- 이미지/모델/영상 업로드·발행·회수 전 소유권을 검사한다. 다른 계정과 기존 공용 키는 계정 링크에 접근할 수 없으며 404를 받는다. 계정도 기존 키 링크를 관리할 수 없다.
- 기존 ownerId 없는 링크의 키 인증 경로를 유지한다. 임의 소유권 이전이나 인증 우회는 추가하지 않았다. 계정 인덱스 저장 실패는 만든 초안/인덱스를 정리하고 오류를 반환한다. 초안 취소는 인덱스도 제거하며 발행/회수 기록은 본인 인덱스에 남는다.
- 공유 화면은 로그인 계정을 기본으로 쓰고 로그아웃 상태는 계정 로그인으로 연결한다. ‘기존 작성자 키로 관리’로 이전 링크를 관리한다. 계정/방식 전환에서 이전 목록·새 링크와 늦게 끝난 결과를 새 계정에 표시하지 않는다. 로그인만으로 원본 전시를 업로드하지 않는다.
- 프로젝터 원본 보존 상한 5MiB와 공유 이미지 상한 5,000,000 bytes의 차이를 발견했다. 입력 기준도 5,000,000 bytes로 맞춰 그보다 큰 파일은 기존 최적화 경로를 사용한다. 20MiB 입력 한도는 유지한다.

## 검증

서버 테스트는 인증 제공자 응답만 모의하고 기존 authenticatedUser 검증을 통과시켰다. A/B/기존 키 목록 분리, 교차 주체의 다섯 변경 경로 차단, 공개 owner 정보 제외, invalid·anonymous·다른 origin 요청 거절, 인증/인덱스 실패를 확인했다. 기존 공유 테스트도 통과한다.

별도 `shareAccount.fixture.ts`는 localhost/127.0.0.1과 fixture 변수를 동시에 요구하며 운영 entry에서 import하지 않는다. 실제 로컬 Wrangler/R2에서 A/B/기존 키로 발행하고 공개 원본 이미지 바이트 동일, 본인 목록만 열람, 교차 회수 404와 본인 회수 후 410을 확인했다. 같은 R2에서 두 번 실행하고 만든 링크를 모두 회수했다. 실제 Supabase 로그인이나 운영 발행 검증을 뜻하지 않는다.

```sh
# 별도 로컬 fixture Worker가 포트 8815에 실행 중일 때
GONGGAN_ACCOUNT_SHARE_NATIVE=1 npx vitest run scripts/account-share-native.test.ts
```

SSR 검증은 로그인 시 키 없이 발행 가능, 로그아웃 시 로그인 안내/발행 비활성, 설정 없음 시 기존 키 경로, 축척·Scene·정보 공개 조건을 확인한다. 실제 DOM 클릭·계정 전환·파일 선택 검증으로 집계하지 않는다.

## 남은 상태

운영 인증 설정은 직전 조회에서 HTTP 200·enabled false였다. 로컬 운영 작성자 키도 없어 운영 발행을 시도하거나 키를 교체하지 않았다. Supabase URL·공개 publishable key 요청은 대기 중이다. 브라우저 도구 초기화는 같은 kernel assets 오류로 실패했다.

실제 로그인 두 계정·두 기기·공유 UI·발표/프로젝터 출력 및 운영 배포는 미완료다. 코드는 Git에 보존하되 브라우저 인수 전에 배포하지 않는다. 공동 편집/Comment 권한은 별도 후속 범위이며 이 단독 소유자 링크로 대체하지 않는다.
