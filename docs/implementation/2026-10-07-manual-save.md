# 실제 Save 단축키와 로컬 저장 · 2026-10-07

문서 2 §67의 Save를 대조하니 기존 ⌘/Ctrl+S는 내보내기 대화상자를 열었다. 실제 로컬 저장으로 바꾸고 상단에 로컬 저장 아이콘을 연결했다. 내보내기 버튼은 출력/백업 경로로 유지한다.

## 동작

- ⌘/Ctrl+S 또는 상단 로컬 저장은 IndexedDB 자동 저장 대기열의 같은 writer를 사용한다. 250ms debounce를 기다리지 않고 pending 변경을 저장한다.
- 현재 snapshot의 pending/in-flight write를 재사용하고, 확인된 snapshot을 반복 저장해 revision을 증가시키지 않는다. 반복 클릭/단축키는 프로젝트당 진행 중 요청 하나로 합친다.
- 이미 실패한 자동 저장은 명시적 Save에서 재시도한다. 기존 local revision 검사와 원자적 document/summary 저장을 그대로 사용하며 다른 탭의 작업을 덮어쓰지 않는다.
- 실제 write 완료를 기다린 뒤 로컬 저장 완료를 표시한다. 도중에 작업/프로젝트가 바뀌면 새 내용에 대한 성공을 주장하지 않으며 최신 초안·자동 저장 대기를 유지한다.
- 아직 불러오는 중/이동·회전 중/저장 handler가 종료된 경우 거절한다. Save는 진행 중인 배치를 확정하거나 취소하지 않는다.
- 프로젝트 객체·자산·내부 Note·Undo/Redo는 바꾸지 않는다. 클라우드 연결/동기화는 기존 기능으로 남으며 로컬 성공을 클라우드 성공으로 표시하지 않는다.
- 입력란/편집 가능한 글/대화상자에서는 기존 단축키 보호 정책대로 편집기 Save를 처리하지 않는다. Shift/Alt가 붙은 별도 조합 및 키 반복/IME를 새 Save 명령으로 처리하지 않는다.

## 검증

fake-indexeddb의 실제 document/summary transaction 및 실제 `writeDraft`/revision 경로를 사용한 새 회귀 **6개**:

1. 60초 debounce 대기 중 최신 크기/Note/이미지 자산을 즉시 저장, 히스토리/프로젝트 불변, 별도 클라우드 queued 상태 유지. 같은 snapshot 재저장 시 revision 불변.
2. 지연 write 중 요청 합치기, durable 저장 전 성공 메시지 금지.
3. 저장 공간 실패 후 동일 writer 재시도, 다른 탭 revision 변경 시 거절 및 양쪽 원본 보존.
4. 저장 중 추가 수정은 성공으로 오인하지 않고 최신 초안 재저장.
5. hydration/transform/종료 writer 보호.
6. 프로젝트 전환 뒤 이전 저장의 성공 알림이 새 전시에 표시되지 않음.

관련 autosave lifecycle/recovery 포함 13개 통과. 최종 전체 **1,093 통과 / 선택 실행 10 제외**, TypeScript/Vite 빌드와 `git diff --check` 통과. 브라우저의 실제 키 입력·클릭/기기 IndexedDB 검증을 대신하지 않는다. 운영 인증·브라우저 연결 대기는 사용자 결정대로 보류한다.

## 다음 원문 누락

문서 2 §48 캡처의 해상도/화면 비율/격자/치수/도면 옵션은 존재하지만 **Transparent Background 및 Environment 포함 여부** 입력은 없다. 실제 출력 경로에 이를 추가해야 하며 화면·캡처 이후 렌더 상태 복원도 검증해야 한다. 이 누락 발견을 구현 완료로 집계하지 않는다. 전체 24단계 사용자 인수·실계정/실기기·운영 배포와 프로젝터 픽셀은 별도 잔여 항목이다.
