# 계정 작품·재질 라이브러리

작품·재질 라이브러리에 선택 항목 계정 저장, 계정 목록, 로컬 가져오기, 보관/복구를 추가했다. 연결된 항목을 가져오면 동일한 로컬 ID를 갱신하며, 양쪽 수정이 충돌하면 덮어쓰지 않고 명시적인 새 계정/로컬 복사본으로 보존한다. 프로젝트와 분리된 라이브러리이며 가져온 후 배치·적용은 기존 동작을 사용한다.

## 보존과 격리

- 작품 이미지와 GLB, 제목·작가·연도·치수·분류·재료·액자, 재질 텍스처·노멀 맵 및 독립 반복 크기/강도를 보존한다. 작품 설치 위치·회전·그룹·잠금·비공개 메모는 portable design에서 제외한다.
- 표준 계정 인증의 실제 사용자 ID를 모든 SQL 조건과 R2 경로에 적용한다. 공개 공유 저장소를 쓰지 않는다. 새 `0003_cloud_library.sql`은 기존 테이블을 바꾸지 않는 추가 migration이다.
- 계정당 작품 500개/재질 200개, 항목당 작품 32MiB/재질 16MiB, 합계 1GiB. 보관된 항목도 한도에 포함한다. CAS와 한도는 최종 SQL 게시 시점에 확인한다. 로컬 한도는 기존 작품 80MiB/재질 32MiB를 유지한다.
- 전송 SHA-256 및 크기를 검증하고 모든 이미지·GLB를 검증한 후 로컬에 반영한다. 서버는 인증된 소유자의 제한된 파일을 불투명 자산으로 스트리밍 보관하며, JSON schema와 실제 media decode는 클라이언트가 수행한다. 손상된 파일은 로컬 변경 전에 거부한다.
- 계정·종류·로컬/원격 ID별 연결을 IDB에 보존한다. 첫 저장/가져오기 ID는 계정별로 결정되어 응답·연결 저장이 유실돼도 재시도 시 항목이 중복되지 않는다. 로컬 수정 중인 항목과 다른 탭에서 변경된 연결을 강제로 덮어쓰지 않는다.
- 로컬 쓰기와 연결 DB는 서로 다른 트랜잭션이다. 연결 저장이 실패한 가져오기는 실제 내용·보관 상태가 같은지 비교해 재시도에서 연결을 복구한다. 명시적 새 계정/로컬 복사본은 새로운 ID를 사용하며 기존 항목은 남긴다. 복사본 저장 자체가 결과 불명 상태로 끊겼다면 계정 목록을 확인하고 다시 복사할지 판단해야 한다.

## 검증

실제 SQLite, HTTP 클라이언트, SHA 검증 저장소 및 독립 fake IDB 연결을 사용하는 18개 통합 테스트가 계정/종류 격리, 동시 CAS, 한도, 네트워크/D1/연결 응답 유실, 로컬 수정 경합, 손상/잘못된 payload, 기존 항목 보존, 이미지·GLB·노멀·텍스처 왕복을 검사한다. Node에서는 브라우저 media decode를 대체하며 아래 네이티브 브라우저에서 별도로 확인했다.

네이티브 브라우저는 localhost 8810/8812의 서로 다른 로컬 저장소와 실제 로컬 Wrangler D1/R2를 사용했다. 인증만 명시적인 모의 provider로 대체했다. 운영 코드에 시험 provider 또는 자격 증명을 넣지 않았다.

- 이미지 작품: 첫 기기 저장 → 다른 origin의 계정 조회/가져오기 → 반복 가져오기 1개 유지. 너비 1100mm 보존 후 작품 배치, 프로젝트 작품 5→6개.
- 충돌: 로컬 보관 변경 후 가져오기 거부. 새 복사본으로 이전 보관 항목과 활성 항목을 모두 보존, 1→2개. 새 계정 복사본 저장 후 기존 계정 재질과 새 항목 2개가 남는 것을 확인했다. 계정 B 목록은 비어 있고 계정 A 데이터에 접근하지 못한다.
- 재질: 실제 PNG 텍스처+노멀 백업을 브라우저에서 decode → 계정 저장 → 두 번째 origin에서 decode/가져오기 → 재질 백업 다운로드. 내려받은 template가 입력과 정확히 같고 두 이미지의 SHA-256도 일치한다. 벽에 적용한 텍스처 800×400mm, 노멀 200×100mm 및 강도 200%를 UI에서 확인했다.
- 390px viewport의 dialog 폭 351px, client/scroll 폭 349px, 문서 폭 390px로 가로 넘침 없음.

근거: `../validation/2026-10-07-cloud-library.json` 및 같은 접두사의 PNG 10개. 시험 중 로컬 fixture 빌드를 교체한 이전 탭의 lazy module이 사라져 한 번 로딩 오류가 났다. 새 빌드로 reload한 뒤 재질 작업을 끝냈다. 장시간 열려 있는 탭의 배포 버전 교체 오류 복구는 별도 후속 검증 항목이다. 두 로컬 Wrangler가 같은 persist DB를 열고 재빌드할 때 첫 프로세스가 SQLite BUSY로 종료된 로그도 정리 시 확인했다. 초기 두 origin 왕복과 이후 두 번째 origin의 복사본 검증은 성공했으나, 운영 동시성 증거로 이 시험 환경을 확대 해석하지 않는다. 차후 한 Worker의 두 호스트 origin 또는 실제 배포된 인증 환경으로 검증한다.

## 남은 범위

운영 로그인 provider는 아직 설정되지 않아 공개 웹에서는 로컬 저장/백업과 명확한 로그인 미연결 안내가 표시된다. 실제 hosted 로그인·두 물리 기기·로그인 세션 교체 검증은 미완료다. 모든 로컬 항목을 무조건 업로드하거나 완전 자동 양방향 동기화하지 않는다. 계정 항목 영구 삭제와 원격 thumbnail preview도 현재 범위 밖의 후속 기능이다. 협업/댓글·미디어/프로젝션·고급 조명·전체 autosave 영구 이력·실제 SketchUp/전체 인수는 별도 진행해야 한다. 최종 구현 목표 전체의 완료를 의미하지 않는다.

최종 검증: 전체 174 test files / 950 tests 통과, 선택 벤치마크 2 files / 2 tests 제외. `npm run build` 성공. 제품 dist에 모의 provider·시험 token·모의 인증 UI가 포함되지 않은 것을 확인했다.
