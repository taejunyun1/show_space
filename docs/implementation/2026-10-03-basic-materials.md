# 기본 재질 1차 연결

## 근거와 범위

문서 1의 15번에 있는 15개 재질 프리셋과 scalar PBR 속성을 먼저 연결한다. 사용자 결정대로 Photo to Material / 사진에서 재질 생성은 후속 유료 기능이다. 도면 인식과 문·설비·설치 제외 직접 편집을 다시 확대하지 않는다.

화이트/무광 페인트, 콘크리트, 목재, 금속, 스테인리스, 유리, 아크릴, 거울, 천, 무광/유광 사진용지, 바리타지, 캔버스, 에폭시 바닥. 기본 색과 반사·투과 속성만 제공한다. 목재 결이나 천 무늬를 합성했다고 표현하지 않는다. 이미지 텍스처 업로드와 실측 텍스처 스케일은 남아 있어 **T7 전체 완료가 아니다**.

## 구현 계약

- `SurfaceMaterial`은 프리셋 ID, roughness/metalness/opacity/transmission, thicknessMm/ior, clearcoat/sheen을 저장한다. 색은 기존 벽/바닥 색을 사용한다. 작품 색은 흰색으로 유지해 작품 원본 이미지에 착색하지 않는다.
- 프리셋을 바꾸면 기본 색과 속성을 적용한다. 개별 숫자는 거칠기/금속성/불투명도/투과율·광학 두께·굴절률을 편집한다. 투과를 높이면 opacity 1, opacity를 낮추면 transmission 0. 광학 두께는 실제 벽/작품 치수가 아니며 mm를 m로 바꿔 renderer에 전달한다.
- 기존 프로젝트에 재질이 없으면 기존 MeshStandardMaterial/roughness를 유지한다. 새로운 물리 재질은 MeshPhysicalMaterial을 사용한다. 프리셋/유한 범위/투과-불투명 조건을 JSON과 공유 입력에서 검증한다.
- 잠긴 객체는 재질도 변경하지 못한다. 벽·작품·바닥 변경은 기존 Undo에 포함된다. 새 Scene은 바닥 색/재질을 함께 저장·복원한다. 새 Scene의 기본 재질 복원은 이후 재질을 제거한다. 옛 Scene의 바닥 필드가 없으면 현재 바닥 설정을 유지한다.
- 공유는 허용 필드만 복사하며 임의 재질 메모/속성을 공개하지 않는다. Worker publish/GET에 같은 검증기를 적용한다. 기존 공유 스냅샷과의 호환을 유지한다.
- GLB와 glTF는 PBR 및 지원되는 transmission/volume/clearcoat/sheen 확장 값을 포함한다. 외부 프로그램의 조명/확장 지원에 따라 외관은 달라진다. neutral environment는 파일에 내보내지 않는다.
- RoomEnvironment→PMREM은 재질이 사용된 경우에만 생성하고 해제한다. 환경 강도는 0.35. 거울은 환경 반사 근사이며 전시장 객체의 거울 상을 만들지 않는다. API/외부 HDR 요청이나 사진 기반 생성 없음. PDF는 ACES 색 처리와 sRGB를 적용해 화면과의 과도한 밝기 차이를 줄인다.

## 검증

`docs/validation/2026-10-03-materials.json`과 화면/추출 PDF 이미지에 기록한다. 15개 프리셋, 유효하지 않은 값, JSON·Scene·Undo·잠금·ZIP 복원·공유 allowlist·실제 GLB exporter/loader 확장을 검사한다. Worker publish/GET은 메모리 버킷으로 검증하며 새 공개 공유 링크는 만들지 않았다. 공유 뷰어에 재질 렌더 컴포넌트를 연결했지만 새 재질 공유를 공개 브라우저에서 끝까지 검증한 것은 아니다.

로컬 실제 조작은 유리 벽, 에폭시 바닥, 유광 작품, 잠금 상태, 투과/불투명 충돌 처리, Scene 저장/재질 변경/복원/새로고침. 실제 JSON과 GLB/glTF/PDF 다운로드를 검사한다. PDF 첫 출력의 과도한 밝기는 발견·수정 후 재출력했다. 테스트 환경에서 Python PDF/PIL 도구가 없어서 pdf-lib로 PDF 이미지 스트림을 읽고 원래 RGB를 PNG에 담아 확인했다.
