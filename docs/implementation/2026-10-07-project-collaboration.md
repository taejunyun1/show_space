# 프로젝트 역할·초대·공동 작업

문서 2 §56의 Owner·Editor·Viewer·Commenter를 비공개 계정 프로젝트에 연결했다. 앞선 외부 Comment는 공개된 잠금 스냅샷의 의견이고, 이번 공동 작업은 원본 비공개 프로젝트에 계정별 접근 권한을 부여한다. 실시간 Cursor·Object Lock은 원문의 후순위 범위로 유지한다. 운영 인증·브라우저 연결 대기는 사용자의 결정대로 보류했다.

## 역할과 실제 권한

| 역할 | 원본 읽기 | 원본 배치 저장 | 협업 의견 | 보관·초대·참여자 관리 |
|---|---|---|---|---|
| 소유자 | 가능 | 가능 | 작성·본인 수정·소유자 관리 | 가능 |
| 편집자 | 가능 | 버전 조건 저장 | 작성·본인 수정 | 불가 |
| 열람자 | 가능 | 불가 | 읽기 | 불가 |
| 댓글 참여자 | 가능 | 불가 | 작성·본인 수정 | 불가 |

원본 읽기에는 이미지·3D 자산·내부 Note·체크리스트·사진·Scene을 포함한 프로젝트 ZIP 전체가 포함된다. 초대 생성 및 수락 화면에 이 범위를 먼저 안내한다. 공개된 읽기 전용 공유 링크는 그대로 별도이다. 기존 프로젝트의 소유자 ID는 변경하지 않으며 편집자의 저장도 소유자 R2 경로를 사용한다. Library와 클라우드 버전 기록 관리 권한을 참여자에게 자동으로 확장하지 않는다.

프로젝트 창에서 **클라우드 목록 새로고침**은 자기 프로젝트와 초대받은 프로젝트를 함께 표시한다. 소유자만 공동 작업 관리·보관·버전 관리 버튼을 제공한다. **열람·의견**은 편집기와 분리한 기록/Scene/읽기 전용 3D/의견 화면이다. 열람자와 댓글 참여자를 편집 가능한 원본 연결 화면으로 열지 않는다. 서버도 모든 저장 요청을 역할에 따라 거절한다.

소유자/편집자의 **편집기로 열기**는 현재 작업을 먼저 저장하고 새 로컬 ID에 원본을 복사한다. 원래 로컬 작업은 보존하고, 클라우드 원본 ID와 저장 버전만 연결한다. ZIP 검증/가져오기 후에도 최신 버전·역할을 다시 확인한다. 원본 저장은 프로젝트 revision CAS로 보호한다. 업로드 중 역할이 바뀌면 해당 membership revision과 editor 권한을 D1 UPDATE 조건에 포함해 커밋을 차단한다. 403/404/409인 자동 저장 대기는 로컬에서 보존·차단하며 자동으로 권한 있는 쓰기를 계속 시도하지 않는다. 수동 재시도 또는 새 클라우드 복사본으로 보존할 수 있다.

## 초대

소유자가 역할·이메일을 지정해 **7일 유효 초대 링크**를 만들고 직접 복사해 전달한다. 자동 이메일 전송은 추가하지 않았다. 초대 링크는 `/join/<UUID>#token=<48hex>`다. 24바이트 CSPRNG 비밀의 SHA256만 D1에 보관하고, 목록·서버 응답·URL query에 비밀 원문을 넣지 않는다. 생성 화면의 비밀은 메모리에만 보관하므로 닫기 전에 복사해야 한다.

수락자는 Supabase의 서버 `getUser`로 확인한 이메일 및 `email_confirmed_at`이 필요하다. 클라이언트가 보낸 수락자 이메일은 신뢰하지 않는다. trim/lowercase만 적용하며 Gmail 점/plus alias 등을 같은 계정으로 임의 합치지 않는다. 다른 계정/잘못된 토큰에 프로젝트 정보를 공개하지 않는다. 만료·취소·보관 프로젝트는 새 참여를 거절한다.

초대 수락 페이지는 인증 전후에 초대 토큰을 최대 7일의 해당 탭 sessionStorage에 임시 보존한다. PKCE 로그인 복귀가 fragment를 대체할 수 있기 때문이다. 처음 읽은 토큰 fragment는 주소 표시에서 제거하며 인증 return path는 UUID가 있는 같은 사이트 `/join/`만 허용한다. 토큰은 서버의 이메일·만료 검사도 통과해야 한다. 저장소가 차단되거나 다른 브라우저로 로그인했다면 원래 초대 링크로 다시 열 수 있다. 실제 provider Redirect URL 허용 설정·이메일/Google 복귀는 아직 검증하지 않았다.

D1 batch에서 참여자 grant와 초대 소비를 같은 트랜잭션으로 처리한다. 동일 UUID/비밀 생성 재시도 및 수락 응답 유실 재시도는 중복 참여자를 만들지 않는다. 수락된 옛 토큰은 현재 참여 상태만 확인하고 권한을 재부여하지 않는다. 참여 제외 후 같은 토큰은 410이며 다시 참여하려면 새 초대가 필요하다. 새 초대로 재참여해도 membership revision은 증가한다. 역할 변경·참여 제외·미수락 초대 취소도 각각 CAS로 보호한다.

활성 참여자 프로젝트당 20명, 미만료 수락 대기 초대 20개, 계정별 참여 프로젝트 200개다. 관리 목록은 최근 200개와 잘림 표시를 제공한다. 과거 초대/제외 기록의 관리 페이지네이션, 참여자의 직접 탈퇴·소유권 양도는 추가하지 않았다. 초대 본문은 실제 스트림 4KiB로 제한한다.

## 비공개 협업 의견

`/api/projects/<id>/comments`는 참여자만 읽으며 원본 Project Notes와 공개 링크의 Comment 모두에서 분리된다. D1 `review_threads.share_id`에 `project:<UUID>` namespace를 사용한다. 첫 단계는 전시 전체 의견이며 비공개 객체/Scene 위치 핀 작성은 구현하지 않았다. 전시 이름은 서버가 원본 metadata에서 구한다. 기존 공개 댓글의 Scene·객체·위치 대상은 유지한다.

소유자/편집자/댓글 참여자는 의견·답글을 쓰고 자신의 글을 수정·삭제한다. 소유자는 의견 처리를 관리할 수 있지만 타인 글을 수정하지 못한다. 열람자는 작성자의 이전 글이라도 쓰기를 할 수 없다. 보관 프로젝트는 의견을 읽기만 한다. 쓰기 SQL에도 현재 active membership revision/role과 보관 상태를 포함한다. 원본 배치 revision이나 ZIP을 댓글로 수정하지 않는다. 기존 댓글의 길이/개수/페이지·내용 삭제·재시도/CAS 제한을 적용한다.

역할/초대/의견은 프로젝트 ZIP·공개 snapshot·Archive 복사본으로 옮기지 않는다. 이미 합법적으로 내려받은 프로젝트·Notes를 권한 회수로 삭제할 수 있다고 주장하지 않는다. 열린 공동 열람은 30초마다 서버 접근 상태를 확인하고 실패 시 캐시 화면을 숨긴다. 실제 화면 조작·상태 전환 인수는 미완료다.

## 검증·운영 상태

새 일반 회귀 23개: 실제 SQLite/트랜잭션의 역할·소유권·수신자·확인된 이메일·만료/취소·한도·동시 수락·롤백·응답 유실·옛 토큰·본문 제한·업로드 중 강등·비공개 의견 권한, 클라이언트 왕복, 초대/return path, 정적 React 안내/escaping, 자동 저장 대기 보존, 실제 ZIP/IndexedDB 원본 유지와 편집 권한 변경 차단을 검증했다. 정적 React 검사는 실제 UI 클릭 검증이 아니다.

실제 로컬 Wrangler HTTP/R2/D1 + batch의 별도 통합 1개도 통과했다. 합성 확인 이메일 A/B/C로 다른 계정 초대 404, 동시 수락 200/200 및 참여자 1명, ZIP/내부 Note 읽기, 편집자 저장, 소유자 전용 보관 403, 별도 비공개 의견, 열람자로 강등 후 배치/댓글 403, 참여 제외 후 읽기 404와 옛 토큰 410을 확인했다. 최종 D1에서 프로젝트 보관·revision 3, 열람자/제외·membership revision 3, 초대 accepted를 확인했다. 임시 서버 종료 코드 130 및 포트 connection refused를 확인했다. 합성 데이터는 분리된 `/tmp` 저장소에 보관돼 재현할 수 있다. 운영 데이터는 사용하지 않았다.

전체 1,075개 통과 / 선택 통합 9개 제외, TypeScript/Vite 빌드 통과. 새 로컬 통합 1개는 따로 실행했다. 운영 `0005_project_collaboration.sql` 적용·실제 로그인/리디렉션·두 실제 계정/기기·새 UI 브라우저 인수·운영 배포는 미완료다. 설정된 상태에서 동작할 구현이며 현재 공개 서비스에서 로그인 초대가 사용 가능하다고 주장하지 않는다. 실시간 동시 편집/Cursor/Object Lock, IES/Lux·AI 및 후속 유료 생성은 별도 범위다. 다음 독립 작업은 남은 프로젝터/GLB 전달 검증과 원문 요구 누락 점검이다.
