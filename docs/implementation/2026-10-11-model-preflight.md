# 복잡한 전시장 모델의 입력 검사와 정상 형상 호환

2026-10-11. [외부 PBR 입력·출력 보존](2026-10-11-external-model-workflow.md)에 이어 전체 전시장 GLB와 독립 작품의 로딩 전 구조 검사를 보완했다. 원문 1 §6–10/31–38, 원문 2 §18/54/63–69의 입력·복잡도·호환 범위에 해당한다. 도면 인식을 확대하거나 사용자 확인 절차를 추가하지 않았다.

## 문제와 변경

12MB 파일/약 20만 삼각형 제한과 개별 정점 수 검사만으로는 잘못된 모델을 충분히 거르지 못했다. 정점의 offset·stride·실제 바이트 범위 및 POSITION/NORMAL/UV 등 속성 개수 불일치가 로더까지 넘어갔다. 정상 크기로 열린 뒤 속성 일부가 누락되거나 영어 TypedArray 오류가 표시될 수 있었다.

이제 기존 형식/객체/삼각형·반복 형상 제한에 이어 정점 요소의 실제 범위·정렬·간격, 속성 연결/개수, 참조된 중복 버퍼의 복사량을 검사한다. 실패하면 로더/텍스처 decode를 시작하기 전에 원본 재출력 안내를 반환한다. 원본 파일이 작더라도 여러 bufferView가 같은 큰 바이트 구간을 겹쳐 참조하면 GLTFLoader는 각 구간을 복사한다. 이 정점 버퍼 복사량은 패딩 포함 48MiB로 제한했다. 새 제한은 CPU 정점 버퍼용이며 전체 메모리나 GPU VRAM 보장이 아니다. 일반적으로 원본 내 구간을 겹치지 않게 저장한 12MB 모델의 정점 복사량은 이 제한 안에 들어간다.

기존 그룹 계층 검사도 보완했다. 자식이 먼저 나열됐을 때 이미 검사한 자식에서 탐색을 멈춰 깊은 계층을 놓치던 캐시를 각 객체의 실제 아래 계층 높이로 바꿨다. 같은 파일의 객체 순서에 관계없이 기존 60단계 제한을 적용한다. 순환/여러 부모/잘못된 자식 연결 검사는 유지한다.

반대로 정상적인 interleaved 데이터에서 마지막 줄의 빈 바이트를 생략한 입력은 Three.js 0.180.0이 `count*stride` 배열을 만들다가 실패했다. 검사한 원본 바이트 구간은 유지하고 GLTFLoader의 사적인 bufferView 복사본에만 마지막 패딩을 더한다. 형상·원본 GLB·백업/공개 바이트를 다시 쓰지 않는다.

범위·stride·정렬 및 마지막 패딩의 근거는 [Khronos glTF 2.0 buffer/accessor 규격](https://github.com/KhronosGroup/glTF/blob/main/specification/2.0/Specification.adoc#accessing-data-from-buffer-views)이며 실제 로더의 복사/배열 생성 코드는 설치된 Three.js로 확인했다. 전체 glTF validator를 대신한다고 주장하지 않는다.

상단 불러오기 안내에 정적 모델/약 20만 삼각형 조건과 장식·가구를 줄이는 준비 방법을 표시했다. `.skp` 직접 지원이나 압축/스킨 지원으로 표시하지 않는다.

## 검증

새 입력 검사 15개와 기존 Header 흐름의 새 연결 검사 하나를 추가했다. 정점 범위 초과/속성 개수 불일치/누락/잘못된 stride/정렬은 `GLTFLoader.parseAsync`가 호출되지 않음을 확인했다. 깊은 계층의 순방향·역방향 나열은 같은 기준으로 거르고 60단계의 정상 계층은 실제로 읽는다. 정상 interleaved position/normal/UV를 원본 Float32 값과 비교했고 마지막 패딩 생략 모델도 정상으로 읽는다. 중복 구간 복사량 검사는 선언 문서에만 적용한 대조라 이전 코드에서 의도적인 큰 복사를 실행하지 않았다.

원래 소유한 전체 전시장 fixture를 30개 방으로 반복한 합성 입력도 생산용 File→GLTFLoader→실제 bounds·데이터 URL로 읽었다. 450 Mesh/geometry 자원 1개, 실제 72×3×40m와 기준점 [-40,-2,-21]m, 원본 32,764바이트 보존이 확인됐다. 이는 실제 사용자 전시장이나 렌더 성능 인수가 아닌 복잡한 정적 입력의 CPU 호환 근거다.

실제 React StrictMode Header에서 잘못된 NORMAL 수를 가진 전체 전시장 GLB를 선택했다. 설명 가능한 오류, 기존 초안/Undo 이력 유지·불러오기 재활성화, 뒤이은 정상 모델 입력 및 Undo 복원을 연결했다. jsdom/FileReader·IndexedDB transport로 확인한 것이며 OS 파일 선택/브라우저 GPU 근거는 아니다.

동일 최종 두 파일 33개를 이전 제품 코드 `28b3917`에 적용하면 12 실패/21 통과, 변경 후 통과다. 대상 5파일 54개 통과. 전체 1,371 통과/선택 10 제외·235파일 통과/10 제외, TypeScript/production build 및 diff 검사 통과. 초기 마지막 패딩 fixture 작성 중 사용하지 않는 UV accessor가 잘못된 구간을 가리키던 실패는 제품 버그 전후 근거에서 제외했다. 큰 청크 안내는 유지한다.

## 남은 범위

이번 변경은 배포하지 않는다. 실제 사용자 대형 전시장·기기·전체 CPU/GPU 메모리/FPS/p95, 브라우저 캡처·운영 인증/외부 URL·원문 24단계/사용자 지표·SketchUp 인수는 남아 있다. 인증/브라우저 대기와 유료 사진→재질·IES/AI 등 후속 범위를 유지한다. 다음은 복잡한 전체 전시장의 Scene·편집 가능한 벽/바닥 전환·백업/공유/GLB 전달 연결이다. 완전한 벽 자동 복원은 요구하지 않는다.
