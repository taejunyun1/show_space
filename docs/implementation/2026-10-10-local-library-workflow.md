# 재질·작품 라이브러리의 저장·재사용과 지연 작업 보호

2026-10-10. 원문 2의 작품 Library(14–18절)·재질 Library(27–28절)에서 기존 로컬 저장·적용 화면의 연결과 작업 수명을 확인했다. 도면 자동 인식·문/설비 직접 편집·사진 생성/결제 범위는 확장하지 않는다.

## 수정

라이브러리에서 항목을 읽거나 썸네일/백업을 준비한 뒤 프로젝트가 A→B→A로 바뀌거나 창이 없어져도 이전 결과를 적용하거나 다운로드했다. 준비가 끝난 이후 새 저장·복원을 시작하기도 했다. 재질의 선택 대상·잠금 상태가 왕복하면 이전 대상의 작업도 살아 있었다. 여러 목록 요청이 다른 순서로 끝나면 예전 보관 상태를 다시 표시했다.

두 화면이 `useLocalLibraryWorkflow`를 사용한다. 프로젝트 전환은 기존 `useProjectDialogScope`의 실제 store 구독으로 동기적으로 감지하며, unmount와 함께 해당 창의 작업을 폐기한다. 읽기·이미지 준비·복원 decode 이후 다음 작업 직전에 유효성을 확인한다. 재질은 첫 선택 및 고정 대상의 존재/잠금 변경도 감지한다. 바닥은 객체 선택과 독립적이다. 작품 라이브러리는 같은 프로젝트에서 선택을 바꾸어 다른 작품을 저장할 수 있으며, 배치 버튼을 누를 때의 벽을 사용한다.

목록 응답은 마지막 요청만 반영하고 창이 끝난 이후의 오류·처리 상태·알림 갱신도 막는다. 초기 목록 준비와 기존 작업 중에는 새 작업을 시작하지 않는다. 프로젝트가 복구되지 않았거나 이동·회전 미리보기 중이면 적용을 거절한다. 동작이 끝난 뒤 재시도할 수 있다.

이미 storage에 전달한 저장·보관·복원 transaction은 취소하거나 롤백하지 않는다. 이 경우 저장 항목은 남을 수 있으며, 창의 후속 메시지/다운로드/적용을 막는다. 이미지 decode 계산을 강제로 중단하지 않는다. 다른 탭은 기존 BroadcastChannel과 focus 목록 갱신을 사용한다.

## 검증

새 `Library.workflow.test.tsx` 22개는 실제 React StrictMode의 두 dialog와 생산용 Zustand command, domain, 미디어 처리 및 repository를 사용한다. 정상 사례는 실제 native PNG decode/Canvas 썸네일과 독립 `fake-indexeddb` factory로 생성한 DB를 사용한다.

- 재질/작품 각각 프로젝트 왕복과 unmount 뒤 늦은 항목 적용을 차단한다.
- 창이 없어진 뒤 백업 다운로드를 시작하지 않는다.
- decode/준비 완료 전에 창이 없어지거나 프로젝트가 바뀌면 새 복원/저장을 시작하지 않는다.
- 실제 재질의 색·물성·2000×1000mm 텍스처, 별도 500×250mm 노멀/강도 1.5를 저장한다. 같은 DB를 사용하는 다른 repository로 항목을 다시 읽어 내용 일치를 확인한다.
- 백업 Blob JSON과 실제 native 자산 decode를 거쳐 두 항목을 서로 다른 새 ID로 복원하고, 검색·보관·복구·벽 재질 적용·기존 벽 형상/메모 보존·Undo/Redo·JSON parser를 확인한다.
- 작품의 이미지·작가·연도·재료·900×1200mm 치수를 저장하고 다른 repository로 다시 읽는다. 설치 메모/위치/회전은 template에서 제외한다. 실제 백업·새 ID 복원·검색·보관·복구 뒤 선택한 벽 B에 별도 작품을 설치한다. 원본 작품/비공개 프로젝트 메모 유지와 한 번의 Undo/Redo를 확인한다.
- 손상 PNG bytes가 든 재질/작품 백업을 실제 decoder가 거절하며 DB에 새 행이 들어가지 않는다.
- 두 focus 목록 갱신이 역순으로 끝나도 최신 보관 상태를 유지한다.
- 이동·회전 미리보기 중 적용은 프로젝트/히스토리를 바꾸지 않으며 끝난 뒤 재시도할 수 있다.
- 재질 대상 선택/잠금이 한 batch에서 왕복하면 이전 작업을 폐기한다.
- 실제 저장이 이미 완료됐지만 응답이 늦은 상태에서 unmount해도 저장 행은 남고 닫힌 창의 후속 처리는 실행하지 않는다.

지연 사례는 완료 시점을 제어한다. File/Image/Canvas/dialog는 Node/native/jsdom adapter이며 다운로드는 Blob payload까지만 검증한다. CloudLibraryPanel은 제외한 로컬 사례다. 이 파일은 3D 모델/영상 라이브러리의 UI 전체 인수를 추가로 증명하지 않는다. 실제 DB 요청/행/재읽기는 확인하지만 브라우저 종료 후 디스크 내구성이나 두 실제 기기 저장을 확인한 것은 아니다.
