## 2026-09-28 — 열린 바닥 재현과 연결 벽 이동 수정

- 기본 예제에서 벽 C를 3D로 한 번 이동하면 **연결된 벽 함께 수정**이 켜져 있어도 이웃 끝점은 제자리에 남아 바닥이 사라지는 현상을 재현했다. 벽 전체 이동/회전에도 공유 끝점을 함께 변환하고, 연결된 잠금 벽이 있으면 편집을 거부한다.
- 3D 벽 이동은 다른 벽의 가까운 자유 끝점에 우선 맞추고, 아니면 100mm 단위로 이동한다. 기존 예제 공간이 이미 깨졌다면 3D의 **기본 공간 배치 복원**으로 네 경계 벽을 되돌린다. 이 작업은 작품과 추가 벽을 유지하고 한 번에 Undo할 수 있다. 도면을 가져온 프로젝트에는 예제 복원 버튼을 표시하지 않는다.
- 도면 자동 인식은 정확한 전체 공간·계단·설치 제외 범위의 강제 생성 대신 편집 가능한 벽·치수 초안과 문·주요 설비 위치 후보에 집중한다. 요소별 체크를 늘리지 않는다.

## 2026-09-27 — E4 3D 회전·벽 사이 이동·미배치 보관

- 선택한 작품의 3D 파란 점으로 15°씩 회전한다. 조작 중 궤도 카메라를 멈추고, 놓을 때 한 번 기록한다. 잠긴 작품에는 핸들을 표시하지 않는다.

## 2026-09-27 — E4 작품 면내 회전 1차

- 작품 중심을 기준으로 -180°~180° 각도를 입력하거나 90°씩 회전한다. 기존 프로젝트는 회전값이 없으면 0°로 표시한다. 3D·벽면도·공유 뷰어의 3D·벽면도에서 같은 각도를 보여준다.
- 회전된 외곽 크기로 벽 이탈 경고, 바닥에서 작품 하단 높이, 드래그 경계, 다중 작품 간격을 계산한다. 잠긴 작품은 회전할 수 없다.
- 로컬 브라우저에서 90° 버튼·30° 숫자 입력, 벽면도와 3D 표시, 회전 후 벽 높이 경고, 회전된 작품 드래그와 Undo, 새로고침 복원을 확인했다. 공유 스냅샷은 단위 테스트에서 각도 보존과 비정상 값 거부를 검증했다. 마우스로 회전 핸들을 잡는 동작과 다른 벽으로 직접 드래그·미배치 보관·설비 편집은 남아 있다.
- 자동 테스트 464개 통과(선택형 2개 제외), 프로덕션 빌드 통과. Cloudflare 공개 페이지와 새 3D 자산의 200 응답, 새 회전 제어 표시 및 콘솔 오류 없음을 확인했다.

## 2026-09-27 — E4 작품 3D 직접 이동 1차

## 벽 후보 검토 및 추가 — 실험 기능

- 평면도에 **벽 후보 찾기** 추가. 로컬 Web Worker에서 어두운 수평/수직 선을 찾고 인접 픽셀 줄을 합쳐 중심선 후보를 만든다.
- 분석 작업은 최대 1400px 작업 이미지, 후보 최대 100개로 제한. 원래 도면 픽셀 좌표로 돌려 검토 화면에 표시한다. 대비/최소 길이 설정 및 다시 분석 제공.
- 초기 선택은 0개. 선 또는 목록 체크박스로 선택하며, 축척 설정 전에는 벽 추가를 막는다. 알려진 길이의 후보 하나를 골라 실제 mm 길이를 입력해 축척을 설정할 수도 있다.
- 사용자가 선택한 후보만 내부벽으로 추가한다. 높이/두께는 입력값이며 자동 측정이라고 표현하지 않는다. 원래 벽/작품 유지, 중복 후보 제거(끝점 5mm 이내), 200벽 제한, 한번의 Undo/Redo 지원.
- 실제 JICA 43쪽을 이전 단계에서 회전/자른 1200×530 도면으로 브라우저 분석: 28개 직선 후보. 치수선 오검출과 일부 벽 누락/분절도 시각적으로 확인했다. 후보 수는 정확도나 정답 벽 개수를 뜻하지 않는다.
- 합성 800×500 검증 도면의 400/200/180px 선 3개 검출. 400px 선을 알려진 4000mm로 설정하여 4000mm 내부벽 생성, 3D 렌더, Undo 검증. 검증 변경을 되돌려 기존 실제 도면으로 복원했다.

## 자동 인식 목표 보완 — 사용자 범위 지정
벽 길이·높이·두께, 출입구, 에어컨, 소화전 등 설비와 계단/설치 제한 영역을 **도면 입력 시 자동 인식할 대상**으로 확정했다. 기존 계획의 계단 인식 제외 문구를 수정했다. 치수별 근거·미확인 상태, 객체 점유와 접근 공간 구분, 벽 양면별 설치 가능 구간, 시설 지침 확인을 설계에 반영했다. 이 변경은 인식 명세 업데이트이며 현재 구현된 선 후보 기능이 해당 의미 인식 기능을 수행한다는 뜻은 아니다. OCR/기호·범례 분석 처리기와 검토·제한 영역 계산 구현이 필요하다.

## 문자 기반 설비·치수 후보 인식 (2026-09-11)

- PDF 텍스트 좌표를 도면 픽셀 좌표로 변환하고, 텍스트가 없는 페이지·이미지는 브라우저의 한국어+영어 OCR로 읽는다. OCR은 로컬 모델을 사용하며 도면을 외부 API로 전송하지 않는다. 취소·90초 시간 제한·재인식을 제공한다.
- 출입구/문/에어컨/소화전/소화기/계단/기둥/단위가 있는 치수 표기를 후보로 분류한다. 단위 없는 숫자는 치수로 확정하지 않는다.
- 평면도에 표기 상자를 표시하고 종류 수정, 표기 확인, 오인식 제외를 지원한다. JSON/로컬 저장에 원문·상자·출처·검토 상태를 포함한다. 회전·자르기에 상자를 변환하며 잘린 문자는 제외한다.
- **상자는 문자 위치이며 설비 실체나 설치 금지 면적이 아니다.** 확인 상태 역시 문자 종류·위치 확인만 뜻한다. 문 기호/계단 범위/설비 점유 및 접근 영역, 벽과 치수 연결·높이/두께 추정, 벽 양면 설치 가능 구간 계산은 남아 있다.
- PDF에 일부 텍스트만 있고 본문이 스캔이면 자동 OCR이 생략될 수 있으므로 ‘문자 다시 읽기’를 사용할 수 있다. 이 동작은 현재 가져오기 미리보기의 문자 후보를 새 OCR 결과로 교체한다.
- 실제 Japan Foundation 도면 6페이지: PDF 텍스트 후보 9개(Up/Dn, Entrance, Sliding Folding Door, 2m wide Door, 치수 표기 등). 후보 수는 실제 설비 개수나 정확도가 아니다.
- 합성 영문 이미지: 7개 표기 추출, 확인/제외/평면도 반영/Undo 브라우저 검증. 합성 한국어 이미지(AppleGothic): 6개 표기 중 5개 추출, ‘출입구’ 누락. 한국어 OCR의 누락 가능성을 확인했으며 실제 저해상도·기호 전용 도면에 대한 정확도 검증은 아직 없다.
- 빌드 및 자동 테스트 100개 통과. 기존 사용자 도면은 테스트 후 복원했다.

## 숫자 인식 집중 개선 (2026-09-11)

사용자 결정: 설비 이름 OCR 개선은 후순위로 두고 숫자 인식 단계를 먼저 마무리한다.

- 단위 없는 숫자, H/T/W/L 표기, 전각 숫자, 연속 치수 숫자를 후보에 포함한다. 단위는 임의로 mm로 가정하지 않는다. 쉼표의 천 단위/소수 해석을 둘 다 보존하며 저점수 OCR과 여러 숫자를 별도 안내한다.
- 축척 1:100, A101 같은 번호, 날짜·레벨 표기 등은 숫자 판독기에서 제외한다. 단독 숫자는 페이지/실 번호일 수도 있어 검토 후보로만 남는다. O/0, I/1 등을 자동 치환하지 않는다.
- ‘숫자 정밀 다시 읽기’: 영문 모델과 최대 2배 확대·3600px 입력 사용. 문자 화이트리스트로 비숫자를 강제 변환하지 않는다. 새 숫자 후보로 교체하고 기존 비치수 설비 후보를 유지한다. 확대는 원본의 손실된 정보를 복원하지 않는다.
- 숫자 검토 화면에 해당 원본 부분을 확대 표시한다. ‘숫자 정정 저장’은 원문을 유지한 채 correctedText를 저장하며 검토 상태를 초기화한다. 저장/회전/자르기에서도 정정값을 보존한다.
- 브라우저 합성 이미지 검증: 3200, H=2800, 200 mm, 3,200, 1200 2400 3600의 5개 표기 인식. 1:100/A101 제외. 정밀 읽기 후에도 동일 표기 판독. 3,200 → 3200 mm 정정·확인·Undo 검증. 이는 실제 저해상도 도면 정확도 수치가 아니다.
- 실제 Japan Foundation 6쪽: 이전 9개에서 단위 없는 숫자 후보가 추가되어 총 53개 표기 후보. 증가 수는 정확도 개선율이나 실제 치수 수가 아니다. 원본 파일이나 사용자 작업은 변경하지 않았다.
- 빌드 성공, 자동 테스트 107개 통과. 숫자 단계는 이 범위에서 마무리한다.

다음 구현 단계: 검토한 숫자와 치수선/벽 후보의 연결. 단위·대상 벽·길이/높이/두께를 확인한 뒤 적용하며 현재는 자동 벽 치수 변경을 수행하지 않는다. 복잡한 기호 인식이나 설비 이름 OCR 개선으로 이번 숫자 단계의 범위를 확대하지 않는다.

## 확인한 숫자 → 벽 치수 연결 (2026-09-11)

- 숫자 검토 화면에 ‘벽 치수에 연결’을 추가했다. 확인된 단일 숫자에 대해 대상 벽·길이/높이/두께·단위를 선택하면 기존 값과 변경 값을 미리 보여준다.
- 높이·두께는 선택 벽에 적용한다. 길이는 시작점과 방향을 유지하고 끝점을 움직이며 연결된 벽 모서리도 함께 변경한다. 도면 축척은 바꾸지 않는다. 변경 후 작품 배치 경고 수를 표시한다.
- 모호한 쉼표·연속 숫자·가로×세로 표기는 하나로 정정해야 적용할 수 있다. 명시된 단위나 H/T 역할과 선택이 다르면 차단한다. 잠긴 벽과 연결된 잠긴 모서리를 보호한다. 입력 한도는 길이 200m, 높이 20m, 두께 2m다.
- 적용 원문·정정값·치수·출처는 벽 메모에 기록하며, 한 번의 Undo로 해당 적용을 복원한다. 기록은 적용 당시의 이력이며 이후 숫자 수정에 따라 벽 치수를 자동 갱신하지 않는다.
- 브라우저 검증: OCR H=2800 → 벽 A 높이 3200→2800mm, 3200 → 벽 A 길이 8000→3200mm. 이후 모든 테스트 변경을 되돌려 길이 8000/높이 3200과 기존 도면을 복원했다. 빌드 및 자동 테스트 111개 통과.

현재 대상 벽 연결은 사용자가 선택한다. 치수선/벽 위치에 따른 자동 대응, 자동 전체 축척 보정, 설비·계단 점유 및 설치 제한 영역은 아직 구현하지 않았다.

## 도면 위치 기반 벽 추천 (2026-09-11)

- ‘벽 치수에 연결’에서 숫자 표기 중심과 기존 벽 선분의 거리를 비교해 최대 3개 벽을 추천한다. 추천 버튼으로 대상 벽을 선택한 뒤 기존 치수 미리보기/적용 흐름을 사용한다. 자동 선택·일괄 적용은 하지 않는다.
- 축척 보정된 도면에서만 동작한다. 벽과 도면은 사용자가 정렬해 두어야 한다. 숫자/추천 벽을 같은 도면에 표시하며 선택한 벽을 강조한다.
- 모호한 숫자·가로×세로·제외된 표기는 추천하지 않는다. 화면 밖/숨긴 벽, 벽 끝을 벗어난 연장선, 멀리 있는 벽은 후보에서 제외한다. 비슷한 거리의 벽은 중복 후보 안내를 표시한다. 잠긴 벽은 표시하되 선택 버튼을 비활성화한다.
- 자동 테스트: 수평벽 거리, 모서리 모호성, 사선벽, 연장선 제외, 미보정/먼 표기/숨김/화면 밖 벽 검증. 전체 115개 통과, 빌드 성공.
- 별도 localhost 저장 공간의 합성 도면 브라우저 검증: 7000 mm 표기와 28px 거리의 테스트 벽 1 추천, 도면 겹침 표시, 추천 선택 → 대상 벽/길이 적용 미리보기 연결 확인. 원래 127.0.0.1 사용자 프로젝트는 변경하지 않았다.

한계: 문자와 벽의 근접도에 따른 추천이다. 치수 보조선·화살표·벽 의미나 전체 치수와 부분 치수의 관계를 해석하지 않는다. 실제 복잡한 도면의 자동 대응 정확도를 검증한 결과가 아니며, 추천이 없어도 수동 연결은 가능하다.

## 치수선·보조선 근거 비교 (2026-09-11)

- 벽 치수 연결에 ‘주변 치수선 분석’을 추가했다. 로컬 이미지의 얇은 수평/수직 선을 검출하고, 숫자 근처 평행선의 양 끝과 벽 양 끝이 맞으며 두 수직 보조선이 연결되는 경우를 후보로 제시한다.
- 주황색은 검출한 선·보조선, 파랑은 대상 벽이다. ‘길이 연결’로 대상 벽과 길이 항목을 선택하고 기존 확인/미리보기/적용을 사용한다. 분석 자체는 프로젝트 치수를 변경하지 않는다.
- 미보정 축척, 모호한 숫자, 가로×세로, H/T 표기, 부분 길이, 한쪽 보조선만 있는 경우를 제외한다. 기존 거리 추천과 수동 연결을 유지한다. 취소와 기존 20초 선 검출 제한을 사용한다.
- 선 검출은 최대 1400px 입력·100개 후보로 제한하며 이 기능에 한해 1px 선도 허용한다. 기존 벽 후보 찾기의 2px 기본값은 유지한다.
- 자동 테스트 121개 통과, 빌드 성공. 순수 좌표 조건과 실제 RGBA 얇은 선 검출 연동, 수평/수직, 뒤집힌 끝점, 부분 치수·누락 보조선 제외를 검증했다.
- localhost 합성 도면 브라우저 검증: 8000 mm와 선·보조선의 근거가 맞는 벽 1개 검출, 강조 표시 및 길이 연결 버튼으로 대상 벽/종류 선택 확인. 127.0.0.1의 사용자 프로젝트는 변경하지 않았다.

한계: 화살표 기호 자체는 판독하지 않는다. 문자로 끊긴 치수선, 사선 치수, 희미한 선, 전체/부분 치수 계층, 연결되는 다른 구조선을 치수선으로 오인하는 경우를 아직 해결하지 않았다. 실제 복잡한 도면의 정답률 검증이 아닌 검토용 구조 근거 후보 기능이다.

## 숫자 자리에서 끊긴 치수선 (2026-09-11)

- 숫자 상자의 양쪽에서 끝나는 동일 축 선분을 치수선 후보로 묶는다. 틈 위치가 숫자 상자와 맞고, 선이 숫자 영역을 지나며, 양 끝 보조선과 벽 끝점까지 맞아야 한다.
- 검출된 원본 선분은 유지하고 추정 연결 구간은 보라 점선으로 별도 표시한다. 이미지나 프로젝트 벽을 분석만으로 수정하지 않는다. 연속 선 근거가 있으면 추정 연결보다 우선한다.
- 큰 틈, 다른 축, 숫자 영역 밖의 단절, 보조선 누락은 제외한다. 수평/수직 및 반대 방향 끝점을 지원한다.
- 빌드 성공, 전체 자동 테스트 124개 통과. 브라우저의 합성 단절 치수선 이미지에서도 벽 1개 검출 및 추정 점선/안내를 확인했다. 기존 127.0.0.1 프로젝트는 변경하지 않았다.

한계: 숫자 밖의 손상·여러 단절·사선·화살표는 아직 처리하지 않는다. OCR 문자 상자가 부정확하면 후보를 놓치거나 잘못 묶을 수 있다. 실제 복잡한 도면에서의 정답률 검증은 별도 과제다.

## M0-A1 — 자동 가져오기 분석 통합 1차

- 도면 가져오기에서 선택/렌더된 페이지에 대해 PDF 텍스트 또는 OCR과 구조 선 검출을 자동 실행한다. 두 처리는 병렬로 진행하고 개별 분석 버튼을 요구하지 않는다. 이미 추출된 PDF 문자는 재사용한다.
- 숫자 수·구조 선 후보 수와 핵심 문제를 한 화면에 모은다. 일부 처리 실패는 다른 결과를 보존하면서 표시하고, 취소된 작업의 늦은 결과는 반영하지 않는다. 재실행 및 수동 문자/숫자 인식은 고급 도구로 제공한다.
- 분석된 선과 처리 상태/진단을 프로젝트의 planAnalysis에 저장한다. 도면 배치·로컬 저장·JSON 복원에서 유지하고 치수선 근거 화면에서 다시 검출하지 않고 재사용한다. 다른 도면으로 교체·제거하면 분석 결과도 교체·제거하며 회전/자르기는 새 이미지로 재분석한다.
- 브라우저: 숫자 테스트 이미지 업로드 후 버튼 추가 조작 없이 숫자 5개/구조 선 후보 77개 표시, 배치 및 새로고침 후 표기/분석 결과 재사용 확인. 선 77개는 문자 획을 포함하며 벽 77개라는 뜻이 아니다. 원래 127.0.0.1 작업은 변경하지 않았다.
- 빌드 성공, 자동 테스트 129개 통과. 부분 실패, PDF 텍스트 재사용, 취소, 분석 좌표 저장 검증 포함.

M0는 여전히 미완료다. 이 단계는 한 페이지의 자동 분석 통합이며 여러 PDF 페이지의 자동 선택·방향/영역 판단·자동 축척·전체 공간 초안 생성은 아직 연결하지 않았다. 현재 배치 동작은 기존 프로젝트의 참고 도면을 바꾸며 별도 전체 공간 초안을 생성하지 않는다. 다음 우선 작업은 자동 축척/구조 구성에 필요한 결과 결합과 별도 초안 생성이며, 페이지 선택 자동화도 병행해 사용자 개입을 줄인다.

도면 분석 후 닫힌 경계와 서로 다른 벽 치수 2개(단위·치수선·보조선 근거)를 검사해 축척과 벽/바닥 초안을 자동 생성한다. 결과는 원본 위 미리보기로 표시하고 적용 시 한 번의 실행 취소로 기존 프로젝트를 복원한다. 숫자 단위 누락, OCR 신뢰도 90 미만, 축척 차이 2% 초과, 끊긴/분기된 경계는 적용 보류한다. 높이 3 m와 두께 150 mm는 명시적인 임시값이다.

## 내부 벽을 포함한 자동 공간 초안

닫힌 외곽에서 열린 가지를 분리하고, 바닥 안에 전부 포함되는 선만 내부 벽 후보로 유지한다. 독립 칸막이와 외곽에서 안으로 뻗은 벽을 지원한다. 미리보기는 외곽 파랑/내부 후보 주황으로 표시한다. 오목한 외곽 밖을 통과하거나 중정을 가로지르는 선, 외부 가지, 외곽 자체가 불명확한 순환 분기는 보류한다. 가구/벽 의미 분류와 출입구·설비 영역은 여전히 미완료다.

검증: 143개 테스트. 기존 축척 검증과 프로젝트 유효성 검사까지 내부 벽을 유지하는 통합 사례 포함. 실제 복잡 도면 성공률은 아직 검증하지 않았다.

## 공간 복원 1차 — 공유 벽·접합·짧은 연결부

## 개구부 경계 모델 및 자동 연결

문/창문을 실제 벽과 분리된 개구부로 저장하고 벽 끝점에 연결했다. 바닥 경계에만 가상 연결을 사용하며, 작품 설치면이나 3D 벽 메시로 생성하지 않는다. 2D/3D는 개구부를 점선으로 표시한다. 벽 수정 시 연결점을 따라가고, 삭제 시 해당 개구부를 제거하며 Undo/Redo로 복원한다. JSON 검증은 잘못된 참조/중복 ID/0 길이를 거부한다.

문·창문 표기와 같은 선상에서 서로 마주 보는 벽 끝점의 틈이 유일하게 연결될 때 자동 후보를 생성한다. OCR 90 미만, 여러 후보 충돌, 다른 선과 교차, 검증 범위 밖 폭은 보류한다. 폭은 문자 상자가 아니라 실제 벽 끝점으로 계산한다. 문짝 회전호·창틀·상인방/창턱 높이는 아직 추론하지 않는다. 문·창문 후보 유형과 위치도 3회 자체 검증 결과 비교에 포함했다.

169개 자동 테스트와 빌드 통과. 별도 로컬 포트의 브라우저에서 개구부 프로젝트 불러오기, 3D의 열린 출입구와 이어진 바닥, 평면 전환 및 오류 없음 확인. 공개 도면 3페이지 재검증은 여전히 완전 생성 0/3이다. `docs/validation/2026-09-11-openings-retest.json` 참조. 웹 배포하지 않음. 전체 다섯 목표는 계속 미완료 상태이며 다음 구현은 이중선·선 후보 유실 처리다.


## 후보 보존·이중선·전체 단위 선언

자동 분석은 최대 500개 선 후보를 보존하고 수동 도구는 기존 100개 기본값을 유지한다. 저장 검증도 500개까지 허용한다. 양끝을 잇는 선이 유일하게 확인되는 평행 이중선만 중심선 후보로 변환한다. 끝이 열린 평행선, 복도 폭의 간격, 경쟁하는 끝단 근거는 합치지 않는다. 이 판정은 구조 후보 판정이며 길쭉한 가구/창틀의 의미 분류까지 해결한 것은 아니다.

페이지 전체의 명시적 단위 선언(예: All measurements in cm, 단위: mm)을 표기로 보존하고 단위 없는 숫자의 자동 축척 계산에 적용한다. 원래 숫자와 개별 명시 단위를 유지하며 서로 충돌하는 전체 단위, 낮은 OCR 점수, 특정 객체 치수 문구는 기본 단위로 사용하지 않는다. Espacio 실제 두 페이지에서 cm 선언 보존을 확인했다.

179개 테스트와 빌드 통과. 동일 공개 도면 재검증은 전체 생성 0/3으로 유지되며, 일부 입력은 500개 상한에도 도달했다. 후보 수 증가는 정확도 개선으로 집계하지 않는다. `docs/validation/2026-09-11-paired-units-retest.json`에 결과를 보존했다. 외부 API와 웹 배포는 사용하지 않았다. 다음은 세로/회전 숫자와 구조선 근거 보완이다.


## 세로·회전 숫자 자동 보완

래스터 OCR 입력을 0° 일반 인식 후 90°/180°/270° 숫자 인식으로 보완한다. 회전·확대 좌표를 원본으로 되돌리고, 겹친 같은 숫자는 중복 제거한다. 다른 값은 원문과 충돌 플래그를 보존하며 자동 축척/치수선 연결에서 제외한다. 낮은 점수의 추가 인식은 채택하지 않는다. 회전별 실패/취소를 처리하고 기존 PDF 문자 근거는 불필요한 회전 OCR로 대체하지 않는다.

185개 테스트 및 빌드 통과. 공개 Espacio 1페이지에서 시각적으로 선택한 세로 치수 7개를 정답 영역으로 기록했으며, 자동 사용 가능한 정확한 값이 기본 OCR 0/7 → 회전 보완 5/7로 증가했다. 60은 반대 방향의 09와 충돌해 제외, 125는 미확보다. 선택한 7개에 대한 결과이지 전체 페이지 정확도가 아니다. 원본 PDF SHA-256과 좌표/정답을 `docs/validation/espacio-selected-numbers.json`에, 결과를 `docs/validation/2026-09-11-rotated-numbers.json`에 보존했다. Node Canvas/Tesseract로 실제 래스터를 검증했으며 브라우저 렌더링 전체 흐름 재검증은 별도다.

전체 공간 생성은 여전히 0/3으로 다섯 목표는 미완료다. 외부 API 및 웹 배포는 사용하지 않았다. 다음은 전체/부분 치수 연결과 구조선 단절 근거 보완이다.


## 전체/부분 치수 연결 및 두꺼운 선 교차점 보정

연속된 여러 벽의 전체 치수, 하나의 벽 중간에 놓인 부분 치수를 치수선 및 양끝 보조선으로 연결한다. 실제 벽이 없는 구간은 연결하지 않는다. 부분 치수가 전체 구간을 빈틈없이 구성할 때 합계를 대조하고 2%를 넘는 불일치를 보류한다. 겹치거나 경쟁하는 부분 치수는 합산하지 않는다. 자동 공간 생성과 축척 검증에 통합했다.

두꺼운 래스터 선 끝의 외곽 픽셀과 수직 벽 중심선 사이 오프셋을 선 두께와 상한 12px로 보정한다. 수평·수직 방향을 유지하고, 경쟁하는 교차점/문 크기의 틈/선분 붕괴는 보정하지 않는다. 고정 4px 근접 연결 전에 처리한다.

193개 테스트와 빌드 통과. 동일한 공개 도면 재검증은 전체 생성 0/3이다. Espacio에서 구조 후보가 늘었지만 정답 구조 재현율이나 성공률 향상으로 집계하지 않는다. 결과는 `docs/validation/2026-09-11-dimension-spans-retest.json`에 보존했다. 다음은 외곽 후보와 가구·범례 선 분리 및 사선 검출이다. 전체 다섯 목표는 미완료이며 외부 API/웹 배포는 사용하지 않는다.


## 래스터 벽 띠 병합·회전 시설 표기·계단 검출 범위

두꺼운 벽이 여러 평행 띠로 분리되었을 때 원본 이진 픽셀의 97% 이상이 채워진 구간만 병합한다. 16px 두께 상한, 길이 90% 이상 겹침과 끝점 차이 제한을 적용하며 빈 간격이 있는 평행선은 유지한다. 회전 OCR에서 얻은 90점 이상 시설 표기도 보존한다.

계단 표기 주변의 규칙적인 반복 단 선 3개 이상으로 검출 범위를 만든다. 문자 상자를 면적으로 사용하지 않는다. 최소 두 분석 조건이 일치하고 나머지 검출 결과에 모순이 없어야 분석 화면과 평면도에 표시한다. JSON 저장/불러오기에서 선·표기 참조와 범위를 검증한다. 현재는 검출한 단 선의 범위 표시이며 계단 전체 외곽 복원, 3D 계단 모델, 작품 배치 차단은 아직 구현하지 않았다.

202개 자동 테스트 및 빌드 통과. 실제 Espacio 1페이지에서 출입문·창문·계단 표기를 얻었고 계단 영역 1개가 세 조건에서 일치했다. 공개 도면 3페이지의 전체 공간 자동 생성은 여전히 0/3이다. 결과는 `docs/validation/2026-09-11-stair-regions-retest.json`에 저장했다. 로컬 Node Canvas/OCR 검증이며 이번 표시 변경의 브라우저 검증은 별도다. 외부 인식 API 및 웹 배포 없이 구현했다.

다음 우선순위는 실제 도면 외곽의 누락 선 복원과 가구·계단 단 선의 벽 오분류 제거다. 이후 사선, 완전한 설치 제외 영역 및 자동 페이지 선택을 검증한다. M0와 다섯 세부 목표는 계속 미완료다.


## 계단 단 선의 벽 오분류 제거

계단 표기와 규칙적 단 선의 결합 근거가 있을 때, 가운데 단 선을 이중벽 병합·구조 그래프 구성 전에 벽 후보에서 제외한다. 양쪽 끝 선은 계단실 벽일 수 있어 유지하며 다른 선으로 같은 방향으로 이어지는 단 선도 제거하지 않는다. 원본 분석 선은 보존한다. 자동 공간 채택에는 기존의 여러 검출 조건 간 일치 검증이 계속 적용된다.

204개 테스트와 빌드를 통과했다. 실제 Espacio 1페이지에서 세 조건 모두 가운데 계단 선 1개가 벽 후보에서 빠져 후보 수가 32/34/39 → 31/33/38로 변했다. 다른 두 페이지는 변하지 않았다. 전체 공간 생성은 여전히 0/3이며 후보 수 감소를 전체 구조 정확도로 집계하지 않는다. 결과는 `docs/validation/2026-09-11-stair-tread-retest.json`에 보존했다. 외부 API·웹 배포 없이 진행했으며 다음 핵심 과제는 외곽 누락 선과 사선 검출이다.


## 사선 래스터 검출과 모서리 연결

수평·수직 띠를 제거한 잉크의 연결 성분에 주축 직선을 맞춰 사선 후보를 검출한다. 길이·폭·횡방향 편차·연속 구간 조건을 함께 확인하며 서로 떨어진 성분을 합치지 않는다. 꺾인 선 묶음은 직선으로 바꾸지 않는다. 이것은 사선 후보 검출이며 가구와 벽의 의미 구분이나 서로 연결된 복잡한 사선망 전체의 분해까지 해결한 것은 아니다.

전체 페이지를 동시에 보관하지 않고 가장 좋은 결과만 유지해 메모리를 제한한다. 취소/닫기 및 오래된 요청 결과의 반영을 차단한다. 모든 인식이 실패해도 읽을 수 있었던 원본을 보존하며 즉시 같은 실패 분석을 무한 반복하지 않는다. 단일 페이지 흐름과 수동 페이지 변경은 유지한다.

## 변환된 도면 레이어와 이미지 준비

`prepareMappedVenue`는 구간별 좌표 변환으로 벽을 나누고 개구부의 벽 끝점 참조를 새 조각에 연결한다. 숫자·설비 표기, 계단 영역과 검출 근거 선을 동일한 스칼라 도면 좌표로 옮겨 기존 프로젝트 형식을 사용할 수 있게 한다. 범위 밖 표기/선은 별도 결과로 반환하고 계단 영역 또는 근거 선이 누락되면 변환을 보류한다. 원본 페이지는 호출자가 보존해야 한다. 선 굵기는 표시용 보정이며 벽 두께 측정이 아니다.

## 개별 치수 복원을 자동 가져오기와 3D에 연결

`prepareConstrainedVenue`가 닫힌 구조·개구부·전체/부분 치수·인접 숫자를 모아 좌표를 풀고 변환 레이어를 준비한다. `analyzePlan`은 기존 단일 축척 방식이 실패할 때 이 결과를 사용하며, 서로 다른 조건에서 두 개 이상 일치하고 다른 성공 결과와 충돌하지 않을 때만 이미지를 변환한다. 렌더링 실패/취소 시 적용하지 않는다. 원본 이미지·해상도·표기는 검증되는 `sourcePlan` 필드로 저장한다. 숫자/선/크기가 바뀌면 기존 변환 결과를 재사용하지 않는다.

미리보기는 변환된 이미지와 같은 좌표를 사용한다. 변환 전 원본을 펼쳐볼 수 있고 적용 후에도 원본 저장이 가능하다. 도면을 교체/제거하면 이전 원본 연결도 제거한다. 서로 다른 분석 결과 비교에 벽 높이·두께와 계단 설치 제외 영역도 포함했다.

## 분리된 치수 묶음 사이의 배치 모순 검증

## 손상된 PDF 문자 자동 OCR 전환과 이종 도면 검증

PDF 문자 항목이 존재해도 제어문자·대체문자·사설 영역 문자가 3개 이상이면서 비공백 문자의 1% 이상이면 해당 문자층을 재사용하지 않고 로컬 OCR로 전환한다. 정상 다국어와 소수 특수기호는 유지한다. 사용자 확인 절차나 외부 API는 추가하지 않았다. 이 검사는 명백한 인코딩 손상 감지이며 모든 잘못된 문자 매핑을 판별하지는 못한다.

## 정상 PDF 문자층과 이미지 설비 표기의 혼합 인식

## PDF 원본 표지 이미지 해상도 복원

페이지 렌더링에서 작아지는 비상구 표지를 PDF 내장 이미지에서 원본 해상도로 추출하고 회전·이동 행렬을 복원한다. 작은 컬러 이미지 중 렌더링된 페이지와 표본 색상이 일치하는 후보만 읽는다. 이 비교는 근사적인 가시성 확인이며 PDF 클리핑·선택 레이어 전체를 해석한 것은 아니다. RGB/RGBA 및 bitmap 이미지를 지원하고 동일 이미지의 OCR은 재사용한다. OCR 결과는 도면 좌표로 되돌려 기존 숫자·단위를 보존하면서 고신뢰 설비 표기만 병합한다. 추출 실패 시 기존 페이지 OCR을 유지한다.

Paragon 실제 PDF에서 후보 이미지14개를 추출했다. 별도 Node 검증의 선택한 큰 초록색 비상구 표지7개는 기존5/7에서7/7로 개선됐다. 브라우저도 이미지 표지4개에서7개로 늘었으며 기존 문자층3개·숫자2개를 포함해 총12표기였다. 문자층 표기와 이미지 표지는 같은 문을 가리킬 수 있으므로 실제 출입구 수로 합산하지 않는다. 소방호스 표지 인식은 여전히0개다. 원본을 읽어도 작은 캡션이 확정되지 않았으며 언어를 영어만으로 바꾼 진단도 개선하지 못했다.

변환 행렬·반복 이미지 OCR 재사용·좌표 복원 테스트와 실제 PDF 벤치마크, 브라우저 배치/되돌리기를 검증했다. 브라우저 경고/오류는 없었고 원래 프로젝트를 복원했다. 기존 닫힌 경계 판정은 유지됐으며 전체 자동 생성은 평면 도면0/4, 사시도0/1로 미완료다. 결과: `docs/validation/2026-09-12-native-sign-retest.json`. 다음 우선 과제는 벽 경계와 치수 적용 범위의 충돌 해결, 전체 공간 복원 성공 사례 확보이며 표지 캡션 보완·설비 점유 범위 연결도 남아 있다. 웹 배포 없이 커밋·푸시한다.


## 실제 공간 생성과 치수 검증 경로 통일

실제 공간 생성에서 문·창문 양쪽의 평행 벽 축 일치 근거를 치수 해석기에 전달하지 않던 누락을 수정했다. 기존 corpus 계산은 이 근거를 사용하고 있어 앱보다 강한 조건으로 측정하고 있었다. `venueDimensions`를 양쪽 경로에서 공유해 벽 표기·개구부 치수·치수선·축 일치 근거가 같도록 했다. 알려진 개구부와 평행한 양쪽 벽, 최대2px의 오차가 있어야 축을 연결하며 모서리 문이나 단순 근접은 근거로 삼지 않는다.

## 벽 옆에 붙은 가구와 실제 K2 도면

## 회색 벽과 이어진 가구 선의 부분 분리

## 복수 치수의 공유 단위와 잘못된 단일 길이 연결 수정

K2 창턱의 `Window sill: 2,68 x 0,38m`에서 앞의 단위 없는 숫자가 누락돼0.38m만 남고, 이를 수평 벽에380mm로 연결하는 오류를 재현했다. 곱하기로 연결된 치수 묶음 끝에 단위가 한 번 있으면 앞의 숫자에도 적용해2.68m와0.38m를 모두 보존한다. 복수 치수는 기존의 단일 벽 연결 조건을 통과하지 않는다. 이 표기가 폭·깊이 중 무엇인지 자동 확정한 것은 아니다.

## 문자 영역 보존과 구조 분석 영역 자동 선택

정상 PDF 문자층에서 의미 분류된 설비·치수뿐 아니라 제목·방 이름 등 전체 문자 영역도 원본 좌표로 보존한다. 구조 선 정리 후 문자 영역 안에 완전히 들어가는 얇은 선만 제외한다. 영역을 통과하는 긴 선, 문자 크기에 비해 두꺼운 선, 원래 두꺼운 띠의 일부라는 근거가 있는 선은 유지한다. 손상된 문자층은 이 근거로 사용하지 않으며 원본 이미지·문자 표기를 지우지 않는다. 현재 이 추가 근거는 정상 PDF 가져오기 경로에 적용하며 수동 회전·자르기 후에는 이전 좌표의 문자 영역을 재사용하지 않는다.

구조 후보에서 큰 벽망과 연결된 얇은 선을 묶어 분석 영역을 선택한다. 일정 면적과 두꺼운 선4개 이상, 명시 단위를 가진 치수3개 이상, 모든 인식된 공간 표기의 포함을 요구한다. 다른 큰 망이나 긴 구조선이 영역 바깥에 있으면 전체 분석을 유지한다. 여백 안의 약간 떨어진 창문 선은 별도 도면으로 오인하지 않도록 했다. 원본을 자르는 UI 기능이 아니라 자동 구조 계산에 쓰는 후보 영역이며 실내 바닥 경계를 확정한 것이 아니다.

실제 K2 조건155에서 분석 영역(x284.48,y347.14,폭1124.32,높이1780.29px)을 선택해 위쪽 로고 선4개를 제외했고94→90개가 됐다.125는 벽망 근거가 부족해72개 유지,190은 영역 선택을 보류하면서 문자 선1개를 제외해101→100개가 됐다. 기존 벽 위치 변경이나 새 선 추가는 없었고 다른 실도면 구조 후보도 유지됐다. 내부 안내 상자 및 문 표시와 벽이 겹친 부분은 여전히 미해결이며 전체 생성은 평면 도면0/5, 사시도0/1이다.

## 색상 안내 상자의 가짜 구조 선 분리

정상 PDF 문자 영역과 렌더링 픽셀을 함께 사용해 작고 가로로 긴 색상 안내 상자를 찾는다. 배경색 픽셀의 연결성·채움 비율, 대표 색상 비율, 내부 문자의 크기와 배치, 바깥의 밝은 여백을 함께 확인한다. 흰 글자 가장자리 보간 때문에 전체 색상 분산만으로 판정하면 실제 상자가 탈락하는 것을 확인했고, 대표 색상 점유율로 배경의 균일함을 판단하도록 했다. 큰 방의 색상 채움·연한 가구 배경·복잡한 색상 이미지·문자 없는 상자는 제외한다.

## 대각선 이중선 벽의 중심선 복원

양끝 마감선이 관측된 이중선 벽을 수평·수직뿐 아니라 임의 각도에서도 하나의 중심선으로 복원한다. 관측된 선 방향에 좌표를 투영해 평행성, 간격, 길이, 양끝 마감선의 유일성을 기존 기준으로 검사한다. 열린 끝, 벌어지는 선, 중복 마감선은 합치지 않는다. 픽셀 간격을 실제 벽 두께로 확정하지 않으며 높이·두께의 임시값 처리는 유지한다.

여러 각도와 역방향 끝점, 열린 틈·비평행선·중복 근거를 검증했다. 회전된 사각 방의 이중선16개에서 벽4개와 닫힌 경계를 복원하는 생산 경로 통합 테스트도 통과했다. 치수가 없는 해당 방은 실제 축척의 공간으로 자동 확정하지 않는다.

실제5개 PDF/6개 대상 페이지의3개 임계값 재검증에서 구조 좌표와 후보 개수는 모두 이전과 같았다. 따라서 이번 배치는 회전된 합성 도면의 지원 범위 확장이며 실도면 성공률 향상으로 보고하지 않는다. 전체 생성은 평면0/5, 사시도0/1이며, 회색 벽 위 문 표시·창틀 경계와 세로 치수 연결은 남아 있다. 결과: `docs/validation/2026-09-12-diagonal-wall-pairs-retest.json`. 웹 배포 없이 커밋·푸시한다.


## 충돌 치수의 자동 확대 재인식

회전 OCR 판독값이 충돌하거나 같은 벽의 같은 구간에 서로 다른 치수가 연결되면 해당 숫자 영역만 자동으로 잘라 두 방향으로 다시 읽는다. 그래프 탐색에서 마지막으로 발견된 표기뿐 아니라 같은 구간의 상충하는 양쪽 표기를 재검증 대상으로 선택한다. 최대8개 표기·16회 판독으로 제한하며 수정·제외된 사용자 표기는 재해석하지 않는다. 이 단계는 API 없이 기존 로컬 OCR 엔진을 사용한다.

원본 숫자 상자와 절반 이상 겹치는 높은 점수의 판독만 해당 표기의 근거로 취급한다. 인접 숫자나 여러 숫자를 포괄하는 큰 OCR 상자는 제외한다. 결과는 기존 숫자와 일치·다른 숫자 발견·판독 불가·실행 실패로 구분하며 원본과 대안 숫자를 덮어쓰지 않는다. 판독의 일치가 벽 연결 또는 실측 길이 검증이라는 뜻은 아니다. 결과 요약은 자동 분석 안내에 표시하고 상세 근거는 가져온 페이지에 유지한다. 상세 재인식 기록은 프로젝트 저장 스키마에 추가하지 않았으며 원본 좌표를 사용하는 가져오기 분석 기록이다.

실제 Espacio1의3개 표기와Espacio2의5개 표기를 자동 재검증했다.60/09는 방향에 따라 모두OCR96점 이상으로 읽혀6개 표기를 미확정으로 유지했다. Espacio2의같은 벽에 연결된180과225는 각각96점으로 다시 읽혔다. 이 경우 재인식만으로 하나를 올바른 벽 길이로 선택할 수 없으며, 표기의 적용 대상·범위를 구분하는 후속 복원이 필요하다. 다른4개 대상 페이지는 재인식 대상이 없었다.

## 문자로 읽히지 않는 호스 릴 표지의 기호 대조

Paragon PDF의 소화전 표지는 하단 문자를2배·4배 확대하고 대비를 바꿔도 안정적인OCR판독을 확보하지 못했다. 따라서 보이는 호스 릴 캐비닛 기호의32×32 특징을 기준으로 알려진 기호 계열을 대조하는 경로를 추가했다. 붉은 바탕, 세로형 비율, 캐비닛·호스의 내부 모양을 함께 확인한다. 작은 PDF 이미지 중 렌더링된 페이지에서 실제로 보이는 것으로 검증된 이미지에만 적용한다.

## 페이지 이미지에서 누락 소화전 표지 복원

PDF 내부 원본 이미지 추출 여부에 의존하지 않고, 렌더링된 페이지에서 알려진 호스 릴 표지를 찾는 경로를 추가했다. 붉은 연결 영역의 크기·형태로 후보를 찾고, 주변 자르기 위치를 소폭 바꿔 기호 모양과 밝기 패턴, 아래쪽 붉은 문구 패널을 대조한다. 단순히 붉은색이라는 이유로 설비로 분류하지 않는다. 일반 이미지 도면도 같은 분석 경로를 사용한다. 현재 지원 기호 계열은 기존과 같은 한 종류다.

별도 Web Worker에서 최대2400px이미지를 처리하며 분석 취소·시간 제한·오류 시 문자와 기존 근거 유지 처리를 연결했다. 원본 PDF 기호와 페이지 기호를 중복 추가하지 않고 출처`symbol`을 유지한다. 표지 상자를 실제 소화전의 점유 범위나 안전거리로 확정하지 않는다.

Node검증에서는 먼저12개가 검출됐지만 브라우저 앱에서는9개만 표시되는 차이가 있었다. 별도 렌더링 진단으로 일부 붉은 테두리의 채움 비율이29.93%라 후보 필터30%에서 탈락함을 확인했다. 후보 기준에 여유를 주고 최종 기호 판정은 유지했다. 기호와 문구 배경이 이어진 세로형 연결 영역도 지원하고 회귀 테스트를 추가했다.

## 문과 맞닿은 유리창을 설치 벽에서 분리

Espacio 1의 `Glass Front Window`가 가느다란 연속선이라 일반 벽으로 남는 사례를 처리했다. 명시적인 유리창 표기, 높은 OCR 점수, 구간 대부분에 걸친 표기 위치, 얇은 원본 선, 인접한 문 끝점, 반대편의 두꺼운 벽 근거를 함께 요구한다. 표기만 있는 일반 벽이나 중간에 분기하는 구조를 창문으로 바꾸지 않는다.

문과 창 사이에 실제 벽이 없는 경우를 위해 관측된 공통 접점을 개구부 연결 모델에 추가했다. 접점은 두 개구부가 공유하고 연결망이 실제 벽에 닿아야 한다. 저장 검증, 단일 축척 및 개별 치수 변환, 벽 이동, 벽 삭제 시 연결 정리를 연결했다. 작품 설치 면은 만들지 않고 바닥 경계만 유지한다. 사용자 체크나 외부 API는 추가하지 않았다.

실제 5개 PDF/6개 페이지 재검증에서 Espacio 1의 밝기 조건 125·155는 유리창을 분리했고 기존 닫힌 경계를 유지했다. 원본 이미지에서 확인한 선택 구간 양끝과 오차 4px 이내다. 190에서는 출입문 연결 근거가 없어 보류한다. 다른 개구부와 원본 구조 좌표는 모두 유지됐다. 전체 공간 생성은 평면 0/5, 사시도 0/1로 아직 미완료다. 현재 사례로 조정한 규칙이므로 일반화 정확도로 간주하지 않는다.

## 회색 벽 위에 덧그린 문 기호 분리

K2 도면의 문은 회색 벽 위에 짙은 닫힘 막대, 직각으로 열린 문짝, 안쪽 사선으로 표시되어 있다. 기본 밝기 조건에서는 막대가 긴 벽에 합쳐졌다. 기존 자동 재검사의 어두운 조건125에서 세 도형 근거를 찾고,155/190의 구조 벽과 대조하도록 연결했다. 추가 외부 API나 사용자 확인 단계는 없다.

기호 위치 두 곳을 `source:symbol` 출입문 표기로 보존한다. OCR 점수를 만들어 붙이지 않으며 실제 폭·높이로 확정하지 않는다. 중복 표기와 사용자의 제외 상태를 존중한다. 분석 재실행에서는 근거를 새로 계산하고, 이미지 회전·자르기 시 이전 기호 근거를 재사용하지 않는다.

겹친 구간은 단일 벽이 표시 전체를 포함하고, 교차·분기·중복 평행 경계가 없을 때만 분리한다. 양쪽 벽을 유지하고 문짝을 설치 벽에서 제외한다. 문 구간은 개구부 모델로 바닥을 연결한다. 숫자 해석에도 분리한 벽 구간을 사용해 문을 가로지르는 전체 벽에 치수가 연결되지 않도록 했다. 가로 글씨를 세로 벽 치수로 연결하는 추가 개선은 아직 남아 있다.

실제5개 PDF/6개 페이지 재검증: K2 문 기호2곳, 왼쪽 문은155/190에서 각각1개구부 분리.125는 긴 벽 근거가 없어 분리하지 않는다. 아래쪽 문은 창틀 등 평행 경계가 겹쳐 위치 표기만 유지하고 구조 분리는 보류했다. 어두운 조건의 기호 근거를 공유하므로 이를 독립적인 기호 검증2회로 집계하지 않는다. 다른 페이지의 기존 개구부와 원본 구조 좌표는 모두 유지됐다. 전체 공간 생성은 평면0/5·사시도0/1로 미완료다. 이 도면에 맞춰 개발한 규칙이며 별도 출처의 일반화 검증은 남아 있다.

## 식별번호별 부분 치수와 총 전시 길이 대조

K2의 A1~A7 및 B1~B4와 `Hanging Space` 합계를 자동 대조했다. 명시적인 식별번호=치수 형태와 총 길이 문구만 사용한다. 단위, 숫자 해석, OCR 점수를 검사하고 같은 번호의 중복 판독은 한 번만 합산한다. 번호 사이 누락, 같은 번호의 값 충돌, 여러 묶음에 겹치는 총 길이, 일치하지 않는 합계를 별도로 기록한다. 숫자를 임의로 수정하지 않으며 사용자 확인 단계를 추가하지 않는다.

실제 K2에서 B 부분 길이 합11160mm와 총11160mm, A 부분 길이 합16370mm와 총16370mm가 일치했다. 이는 숫자들의 산술 관계이며 공간 이름이나 각 물리적 벽과의 대응을 입증하지 않는다. 총 길이는 유일하게 일치하는 합계로 대응시키므로 독립적인 방 식별 근거로 사용하지 않는다. 마지막 번호 이후의 미검출까지 배제한 완전성 검증도 아니다. 공간 생성 판정이나 축척 조건을 이 결과만으로 완화하지 않았다.

분석 파이프라인은 합계 결과를 보존하고 일치 사실과 벽 연결의 미완료를 구분해 안내한다. 재분석은 이전 결과를 버리고 다시 계산한다. 실제5개 PDF/6개 페이지 재검증에서 K2의 두 묶음이 일치했고 다른5페이지는 적용 가능한 묶음이 없었다. 전체 생성은 평면0/5·사시도0/1로 미완료다.

388개 테스트·빌드 통과. 별도 브라우저 UI 검증과 배포는 하지 않았다. 결과: `docs/validation/2026-09-12-dimension-totals-retest.json`. 다음 단계는 이 식별번호의 길이를 문으로 분리한 실제 벽 구간에 연결하고, 방향과 대상이 모호한 경우를 기하 근거로 구분하는 것이다.

## 문으로 분리된 세로 벽에 가로 식별번호 치수 연결

가로로 적힌 B3 같은 식별번호 치수를 세로 벽에 연결하는 제한적 경로를 추가했다. 글자 방향과 벽 방향이 같다는 기존 가정만으로 누락시키지 않되, 새 경로는 관측된 문 기호를 근거로 실제 분리한 벽 구간에만 적용한다. 문을 포함한 원래 긴 벽은 대상에 넣지 않는다.

## 2026-09-13 — PDF 원본 면 기반 구조 후보

## 2026-09-28 — 손 도구와 3D Scene 시점

- H/손 버튼을 공통 시점 이동 도구로 연결했다. 3D에서는 왼쪽 드래그로 카메라를 수평·수직 이동하고, 평면도·벽면도에서는 드래그로 뷰포트를 이동한다. 이 도구가 켜져 있는 동안 벽·작품 드래그는 객체를 수정하지 않는다. V 또는 선택 버튼으로 돌아간다.
- 3D에서 저장한 Scene은 카메라 위치·주시점·확대율을 작품 배치와 함께 기록한다. Scene을 다시 열면 3D 화면으로 돌아가 해당 시점을 복원한다. 예전 Scene에는 시점 필드가 없어도 그대로 열 수 있다. 다른 프로젝트의 Scene 시점이 새 프로젝트에 적용되지 않도록 요청을 프로젝트 ID로 제한했다.
- 포인터 검증: 3D 작품 위, 평면도 벽 위, 벽면도 작품 위에서 각각 드래그해 시점만 이동하고 치수·배치·Undo 이력이 그대로임을 확인했다. Scene 시점을 저장한 뒤 기본 시점으로 돌리고 다시 열거나 새로고침 후 평면도에서 다시 열어 복원되는 경로를 확인했다. 브라우저 콘솔 오류는 없었다.
- 자동 테스트 485개 통과(선택형 벤치마크 2개 제외), TypeScript 검사와 프로덕션 빌드 통과.
- 여전히 남은 E5 작업은 구조까지 포함한 Scene, 그룹 편집, 관람객 눈높이 원근 촬영과 미리보기다. 문·주요 설비의 가벼운 자동 후보 추출과 실도면 검증은 별도로 유지한다.

## 2026-09-28 — 구조별 Scene 배치안

- 새 Scene에 벽 전체 구조·문 개구부·저장 치수선·미배치 작품을 작품 배치와 함께 저장한다. 벽을 추가·삭제하거나 작품이 미배치로 옮겨진 뒤에도 당시 Scene을 복원할 수 있다. 복원은 한 번의 Undo로 되돌리고 다시 실행할 수 있다.
- 예전 Scene에는 구조 스냅샷이 없으므로 기존 작품·벽 표시 복원 방식으로 읽는다. 새 스냅샷은 현재 벽과 독립적으로 벽·작품·개구부 참조를 검증한다. 축척 미정 도면을 보정할 때 저장된 구조·문 접점·치수 좌표도 함께 변환한다.
- 별도 로컬 브라우저에서 기본 4벽 Scene A를 저장하고 내부벽을 추가해 5벽 Scene B를 저장했다. A→B 전환 시 구조와 작품이 함께 바뀌었고, Undo 한 번으로 이전 구조가 돌아왔다. 새로고침 후 두 Scene이 남아 있고 B를 다시 열어 내부벽을 복원했으며 콘솔 오류는 없었다.
- 자동 테스트 489개 통과(선택형 벤치마크 2개 제외), TypeScript 검사·프로덕션 빌드 통과. Cloudflare 공개 HTTPS에 배포해 Scene 설명·3D 렌더와 콘솔 오류 없음을 확인했다.
- 그룹 편집, 관람객 눈높이 원근 촬영·미리보기, 실제 도면 수정 비용과 모바일 실기기 성능 검증은 남아 있다. 공유 링크에는 다른 Scene을 보내지 않는 기존 범위를 유지한다.

## 2026-10-03 — 모델 벽·바닥을 편집 공간으로 전환
- GLB의 실제 삼각형 면을 원본 노드 변환·모델 위치/회전/배율과 함께 분석한다. 연결된 수직 면이 사각형을 채우고 평행한 양쪽 면과 양끝 면이 존재하는 직선 벽에서 중심선·길이·높이·두께를 읽는다. 떨어진 면을 임의 벽으로 연결하지 않으며, 빈 문 공간·곡면·기울어진 면·낮은 가구는 사각형으로 메우지 않는다.
- 바닥은 바닥 높이 부근의 위쪽 수평 삼각형 면에서 외곽과 구멍 경계를 추출한다. 실제 모델 바닥을 별도 `importedFloor` 경계로 보존하여 열린 벽 구조에서도 표시한다. 바닥 경계는 이후 벽 이동에 따라 바뀌지 않는다. 중정 구멍을 유지하며 자체 교차·접촉·과도한 꼭짓점은 거부한다. 원본 mesh 위치·형상은 변경하지 않는다. glTF 좌표와 노드 변환 기준: [Khronos glTF 2.0](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html).
- **모델 벽으로 공간 만들기** 한 번으로 편집 벽을 생성한다. 실제 바닥을 기준으로 전시장 안쪽을 A면으로 맞추고 내부벽은 자동 숨김에서 제외한다. 기존 작업은 JSON 백업, 원본 모델은 숨김 보관, 기존 작품은 미배치 보관하며 한 번의 Undo로 전체 구조를 복원한다. 기존 잠금·모델 변경을 검증하고 예전 구조 없는 Scene도 원래 벽을 복원할 수 있게 보존한다. 오래된 도면/개구부/치수 참조는 새 구조에 연결하지 않는다.
- 바닥 경계를 로컬·JSON·구조 Scene·공개 공유 허용 목록에 연결했다. 공유 서버는 좌표와 외곽을 다시 검증하고 원본 GLB·메모·미배치 작품·다른 Scene은 공개하지 않는다. 변환 후의 편집 벽·바닥·설치 작품만 기존 읽기 전용 링크에서 제공한다.
- 531개 테스트 통과·선택 벤치마크 2개 제외, TypeScript·빌드 통과. 형상 검증은 직육면체 벽·바닥·낮은 가구, 노드 변환/90도 회전/2배 배율, 떨어진 벽, 연결 없는 평행 면, 기울어진 면, 중정이 있는 바닥 등을 포함한다.
- 로컬 브라우저: 시험 GLB의 실제 12,000×8,000mm 바닥과 벽 3개(높이 3,000mm·두께 200mm) 전환, 기존 작품 설치, 벽 표면 드래그/Undo, 새로고침 후 Scene 복원, 평면 바닥, 실제 1920×1519 PNG 및 JSON 출력 확인. 공개 공유 API로 검증용 배치를 게시해 3D 벽·바닥·작품, 평면 경계와 읽기 전용 화면·콘솔 오류 없음을 확인했다. 검증용 링크는 이후 중단하고 410을 확인했다. 공개 편집 초안은 변경하지 않았다.
- 남은 요구사항: 원본 SKP 변환 서버, 실제 SketchUp 내보내기 파일에 대한 검증, 결합된/구멍 있는 벽·곡면·설비 의미 인식, 여러 층·높이가 다른 바닥, 모델 전체의 공개 공유, 대형 모델·모바일 실기기 검증. 이 단계는 정적 직선 벽과 단일 층 수평 바닥의 보수적 추출이며 일반 CAD 모델 변환이나 전체 제품 완료로 집계하지 않는다. 분석은 삼각형 20만 개·편집 벽 200개 이내로 제한한다.
