PDF는 로컬 처리하며 원본 대신 선택 페이지의 이미지가 프로젝트에 저장된다. PDF 30MB/200페이지, 이미지 20MB, PDF 렌더 최대 변 2400px.

## 도면 회전·평면 영역 선택
- 가져오기 창에서 좌/우 90도 회전, 드래그 사각 영역 선택과 픽셀 좌표 입력, 선택 영역 자르기, 원래 페이지 복원을 추가했다.
- 변환은 PNG로 처리하고 재확대하지 않는다. 회전 후 좌표 기준으로 자르며 이미지 밖/너무 작은 수치 입력은 거절한다. 자르기 전 품질 안내임을 표시한다.
- 페이지/렌더 해상도를 바꾸면 해당 원본 페이지를 새로 불러와 변환을 초기화한다. 변환 중 다른 편집·배치를 막는다.
- 실제 JICA 43쪽을 90도 회전 후 첫 평면 1200×530px로 자르는 브라우저 검증 수행. 배치 시 비율 1200:530 유지, 축척 미보정 상태에서 두 점 보정 진입 확인.
- 회전된 색상 픽셀의 실제 위치와 영역 추출, 경계/역방향/잘못된 입력 자동 테스트 추가.
- 임의 각도 기울기/원근 보정, 여러 평면을 각각 프로젝트에 저장, OCR·벽 자동 인식은 남아 있다. 원래 페이지로 복원은 가져오기 창을 열어 둔 동안만 가능하며 원본 파일 영구 저장은 아직 아니다.

## 벽 후보 검토 및 추가 — 실험 기능

- 평면도에 **벽 후보 찾기** 추가. 로컬 Web Worker에서 어두운 수평/수직 선을 찾고 인접 픽셀 줄을 합쳐 중심선 후보를 만든다.
- 분석 작업은 최대 1400px 작업 이미지, 후보 최대 100개로 제한. 원래 도면 픽셀 좌표로 돌려 검토 화면에 표시한다. 대비/최소 길이 설정 및 다시 분석 제공.
- 초기 선택은 0개. 선 또는 목록 체크박스로 선택하며, 축척 설정 전에는 벽 추가를 막는다. 알려진 길이의 후보 하나를 골라 실제 mm 길이를 입력해 축척을 설정할 수도 있다.
- 사용자가 선택한 후보만 내부벽으로 추가한다. 높이/두께는 입력값이며 자동 측정이라고 표현하지 않는다. 원래 벽/작품 유지, 중복 후보 제거(끝점 5mm 이내), 200벽 제한, 한번의 Undo/Redo 지원.
- 실제 JICA 43쪽을 이전 단계에서 회전/자른 1200×530 도면으로 브라우저 분석: 28개 직선 후보. 치수선 오검출과 일부 벽 누락/분절도 시각적으로 확인했다. 후보 수는 정확도나 정답 벽 개수를 뜻하지 않는다.
- 합성 800×500 검증 도면의 400/200/180px 선 3개 검출. 400px 선을 알려진 4000mm로 설정하여 4000mm 내부벽 생성, 3D 렌더, Undo 검증. 검증 변경을 되돌려 기존 실제 도면으로 복원했다.

한계: 사선·곡선·희미하거나 기울어진 벽, 벽의 의미 분류, OCR 치수, 이중 선의 벽 두께 추정, 자동 접합/폐합은 미구현이다. 치수선/가구/표제란도 검출될 수 있다. 건물 전체를 자동 복원하는 기능이 아니라 수동 검토를 전제로 한 선 후보 입력 도구다. 현재 기본 샘플 공간을 자동 삭제하거나 대체하지 않는다.


## 자동 인식 목표 보완 — 사용자 범위 지정
벽 길이·높이·두께, 출입구, 에어컨, 소화전 등 설비와 계단/설치 제한 영역을 **도면 입력 시 자동 인식할 대상**으로 확정했다. 기존 계획의 계단 인식 제외 문구를 수정했다. 치수별 근거·미확인 상태, 객체 점유와 접근 공간 구분, 벽 양면별 설치 가능 구간, 시설 지침 확인을 설계에 반영했다. 이 변경은 인식 명세 업데이트이며 현재 구현된 선 후보 기능이 해당 의미 인식 기능을 수행한다는 뜻은 아니다. OCR/기호·범례 분석 처리기와 검토·제한 영역 계산 구현이 필요하다.

## 문자 기반 설비·치수 후보 인식 (2026-09-11)

- PDF 텍스트 좌표를 도면 픽셀 좌표로 변환하고, 텍스트가 없는 페이지·이미지는 브라우저의 한국어+영어 OCR로 읽는다. OCR은 로컬 모델을 사용하며 도면을 외부 API로 전송하지 않는다. 취소·90초 시간 제한·재인식을 제공한다.
- 출입구/문/에어컨/소화전/소화기/계단/기둥/단위가 있는 치수 표기를 후보로 분류한다. 단위 없는 숫자는 치수로 확정하지 않는다.
- 평면도에 표기 상자를 표시하고 종류 수정, 표기 확인, 오인식 제외를 지원한다. JSON/로컬 저장에 원문·상자·출처·검토 상태를 포함한다. 회전·자르기에 상자를 변환하며 잘린 문자는 제외한다.
- **상자는 문자 위치이며 설비 실체나 설치 금지 면적이 아니다.** 확인 상태 역시 문자 종류·위치 확인만 뜻한다. 문 기호/계단 범위/설비 점유 및 접근 영역, 벽과 치수 연결·높이/두께 추정, 벽 양면 설치 가능 구간 계산은 남아 있다.
- PDF에 일부 텍스트만 있고 본문이 스캔이면 자동 OCR이 생략될 수 있으므로 ‘문자 다시 읽기’를 사용할 수 있다. 이 동작은 현재 가져오기 미리보기의 문자 후보를 새 OCR 결과로 교체한다.
- 실제 Japan Foundation 도면 6페이지: PDF 텍스트 후보 9개(Up/Dn, Entrance, Sliding Folding Door, 2m wide Door, 치수 표기 등). 후보 수는 실제 설비 개수나 정확도가 아니다.
- 합성 영문 이미지: 7개 표기 추출, 확인/제외/평면도 반영/Undo 브라우저 검증. 합성 한국어 이미지(AppleGothic): 6개 표기 중 5개 추출, ‘출입구’ 누락. 한국어 OCR의 누락 가능성을 확인했으며 실제 저해상도·기호 전용 도면에 대한 정확도 검증은 아직 없다.
- 빌드 및 자동 테스트 100개 통과. 기존 사용자 도면은 테스트 후 복원했다.

## 숫자 인식 집중 개선 (2026-09-11)

사용자 결정: 설비 이름 OCR 개선은 후순위로 두고 숫자 인식 단계를 먼저 마무리한다.

- 단위 없는 숫자, H/T/W/L 표기, 전각 숫자, 연속 치수 숫자를 후보에 포함한다. 단위는 임의로 mm로 가정하지 않는다. 쉼표의 천 단위/소수 해석을 둘 다 보존하며 저점수 OCR과 여러 숫자를 별도 안내한다.
- 축척 1:100, A101 같은 번호, 날짜·레벨 표기 등은 숫자 판독기에서 제외한다. 단독 숫자는 페이지/실 번호일 수도 있어 검토 후보로만 남는다. O/0, I/1 등을 자동 치환하지 않는다.
- ‘숫자 정밀 다시 읽기’: 영문 모델과 최대 2배 확대·3600px 입력 사용. 문자 화이트리스트로 비숫자를 강제 변환하지 않는다. 새 숫자 후보로 교체하고 기존 비치수 설비 후보를 유지한다. 확대는 원본의 손실된 정보를 복원하지 않는다.
- 숫자 검토 화면에 해당 원본 부분을 확대 표시한다. ‘숫자 정정 저장’은 원문을 유지한 채 correctedText를 저장하며 검토 상태를 초기화한다. 저장/회전/자르기에서도 정정값을 보존한다.
- 브라우저 합성 이미지 검증: 3200, H=2800, 200 mm, 3,200, 1200 2400 3600의 5개 표기 인식. 1:100/A101 제외. 정밀 읽기 후에도 동일 표기 판독. 3,200 → 3200 mm 정정·확인·Undo 검증. 이는 실제 저해상도 도면 정확도 수치가 아니다.
- 실제 Japan Foundation 6쪽: 이전 9개에서 단위 없는 숫자 후보가 추가되어 총 53개 표기 후보. 증가 수는 정확도 개선율이나 실제 치수 수가 아니다. 원본 파일이나 사용자 작업은 변경하지 않았다.
- 빌드 성공, 자동 테스트 107개 통과. 숫자 단계는 이 범위에서 마무리한다.

다음 구현 단계: 검토한 숫자와 치수선/벽 후보의 연결. 단위·대상 벽·길이/높이/두께를 확인한 뒤 적용하며 현재는 자동 벽 치수 변경을 수행하지 않는다. 복잡한 기호 인식이나 설비 이름 OCR 개선으로 이번 숫자 단계의 범위를 확대하지 않는다.

## 확인한 숫자 → 벽 치수 연결 (2026-09-11)

- 숫자 검토 화면에 ‘벽 치수에 연결’을 추가했다. 확인된 단일 숫자에 대해 대상 벽·길이/높이/두께·단위를 선택하면 기존 값과 변경 값을 미리 보여준다.
- 높이·두께는 선택 벽에 적용한다. 길이는 시작점과 방향을 유지하고 끝점을 움직이며 연결된 벽 모서리도 함께 변경한다. 도면 축척은 바꾸지 않는다. 변경 후 작품 배치 경고 수를 표시한다.
- 모호한 쉼표·연속 숫자·가로×세로 표기는 하나로 정정해야 적용할 수 있다. 명시된 단위나 H/T 역할과 선택이 다르면 차단한다. 잠긴 벽과 연결된 잠긴 모서리를 보호한다. 입력 한도는 길이 200m, 높이 20m, 두께 2m다.
- 적용 원문·정정값·치수·출처는 벽 메모에 기록하며, 한 번의 Undo로 해당 적용을 복원한다. 기록은 적용 당시의 이력이며 이후 숫자 수정에 따라 벽 치수를 자동 갱신하지 않는다.
- 브라우저 검증: OCR H=2800 → 벽 A 높이 3200→2800mm, 3200 → 벽 A 길이 8000→3200mm. 이후 모든 테스트 변경을 되돌려 길이 8000/높이 3200과 기존 도면을 복원했다. 빌드 및 자동 테스트 111개 통과.

현재 대상 벽 연결은 사용자가 선택한다. 치수선/벽 위치에 따른 자동 대응, 자동 전체 축척 보정, 설비·계단 점유 및 설치 제한 영역은 아직 구현하지 않았다.

## 도면 위치 기반 벽 추천 (2026-09-11)

- ‘벽 치수에 연결’에서 숫자 표기 중심과 기존 벽 선분의 거리를 비교해 최대 3개 벽을 추천한다. 추천 버튼으로 대상 벽을 선택한 뒤 기존 치수 미리보기/적용 흐름을 사용한다. 자동 선택·일괄 적용은 하지 않는다.
- 축척 보정된 도면에서만 동작한다. 벽과 도면은 사용자가 정렬해 두어야 한다. 숫자/추천 벽을 같은 도면에 표시하며 선택한 벽을 강조한다.
- 모호한 숫자·가로×세로·제외된 표기는 추천하지 않는다. 화면 밖/숨긴 벽, 벽 끝을 벗어난 연장선, 멀리 있는 벽은 후보에서 제외한다. 비슷한 거리의 벽은 중복 후보 안내를 표시한다. 잠긴 벽은 표시하되 선택 버튼을 비활성화한다.
- 자동 테스트: 수평벽 거리, 모서리 모호성, 사선벽, 연장선 제외, 미보정/먼 표기/숨김/화면 밖 벽 검증. 전체 115개 통과, 빌드 성공.
- 별도 localhost 저장 공간의 합성 도면 브라우저 검증: 7000 mm 표기와 28px 거리의 테스트 벽 1 추천, 도면 겹침 표시, 추천 선택 → 대상 벽/길이 적용 미리보기 연결 확인. 원래 127.0.0.1 사용자 프로젝트는 변경하지 않았다.

한계: 문자와 벽의 근접도에 따른 추천이다. 치수 보조선·화살표·벽 의미나 전체 치수와 부분 치수의 관계를 해석하지 않는다. 실제 복잡한 도면의 자동 대응 정확도를 검증한 결과가 아니며, 추천이 없어도 수동 연결은 가능하다.

## 치수선·보조선 근거 비교 (2026-09-11)

- 벽 치수 연결에 ‘주변 치수선 분석’을 추가했다. 로컬 이미지의 얇은 수평/수직 선을 검출하고, 숫자 근처 평행선의 양 끝과 벽 양 끝이 맞으며 두 수직 보조선이 연결되는 경우를 후보로 제시한다.
- 주황색은 검출한 선·보조선, 파랑은 대상 벽이다. ‘길이 연결’로 대상 벽과 길이 항목을 선택하고 기존 확인/미리보기/적용을 사용한다. 분석 자체는 프로젝트 치수를 변경하지 않는다.
- 미보정 축척, 모호한 숫자, 가로×세로, H/T 표기, 부분 길이, 한쪽 보조선만 있는 경우를 제외한다. 기존 거리 추천과 수동 연결을 유지한다. 취소와 기존 20초 선 검출 제한을 사용한다.
- 선 검출은 최대 1400px 입력·100개 후보로 제한하며 이 기능에 한해 1px 선도 허용한다. 기존 벽 후보 찾기의 2px 기본값은 유지한다.
- 자동 테스트 121개 통과, 빌드 성공. 순수 좌표 조건과 실제 RGBA 얇은 선 검출 연동, 수평/수직, 뒤집힌 끝점, 부분 치수·누락 보조선 제외를 검증했다.
- localhost 합성 도면 브라우저 검증: 8000 mm와 선·보조선의 근거가 맞는 벽 1개 검출, 강조 표시 및 길이 연결 버튼으로 대상 벽/종류 선택 확인. 127.0.0.1의 사용자 프로젝트는 변경하지 않았다.

한계: 화살표 기호 자체는 판독하지 않는다. 문자로 끊긴 치수선, 사선 치수, 희미한 선, 전체/부분 치수 계층, 연결되는 다른 구조선을 치수선으로 오인하는 경우를 아직 해결하지 않았다. 실제 복잡한 도면의 정답률 검증이 아닌 검토용 구조 근거 후보 기능이다.

## 숫자 자리에서 끊긴 치수선 (2026-09-11)

- 숫자 상자의 양쪽에서 끝나는 동일 축 선분을 치수선 후보로 묶는다. 틈 위치가 숫자 상자와 맞고, 선이 숫자 영역을 지나며, 양 끝 보조선과 벽 끝점까지 맞아야 한다.
- 검출된 원본 선분은 유지하고 추정 연결 구간은 보라 점선으로 별도 표시한다. 이미지나 프로젝트 벽을 분석만으로 수정하지 않는다. 연속 선 근거가 있으면 추정 연결보다 우선한다.
- 큰 틈, 다른 축, 숫자 영역 밖의 단절, 보조선 누락은 제외한다. 수평/수직 및 반대 방향 끝점을 지원한다.
- 빌드 성공, 전체 자동 테스트 124개 통과. 브라우저의 합성 단절 치수선 이미지에서도 벽 1개 검출 및 추정 점선/안내를 확인했다. 기존 127.0.0.1 프로젝트는 변경하지 않았다.

한계: 숫자 밖의 손상·여러 단절·사선·화살표는 아직 처리하지 않는다. OCR 문자 상자가 부정확하면 후보를 놓치거나 잘못 묶을 수 있다. 실제 복잡한 도면에서의 정답률 검증은 별도 과제다.

## M0-A1 — 자동 가져오기 분석 통합 1차

- 도면 가져오기에서 선택/렌더된 페이지에 대해 PDF 텍스트 또는 OCR과 구조 선 검출을 자동 실행한다. 두 처리는 병렬로 진행하고 개별 분석 버튼을 요구하지 않는다. 이미 추출된 PDF 문자는 재사용한다.
- 숫자 수·구조 선 후보 수와 핵심 문제를 한 화면에 모은다. 일부 처리 실패는 다른 결과를 보존하면서 표시하고, 취소된 작업의 늦은 결과는 반영하지 않는다. 재실행 및 수동 문자/숫자 인식은 고급 도구로 제공한다.
- 분석된 선과 처리 상태/진단을 프로젝트의 planAnalysis에 저장한다. 도면 배치·로컬 저장·JSON 복원에서 유지하고 치수선 근거 화면에서 다시 검출하지 않고 재사용한다. 다른 도면으로 교체·제거하면 분석 결과도 교체·제거하며 회전/자르기는 새 이미지로 재분석한다.
- 브라우저: 숫자 테스트 이미지 업로드 후 버튼 추가 조작 없이 숫자 5개/구조 선 후보 77개 표시, 배치 및 새로고침 후 표기/분석 결과 재사용 확인. 선 77개는 문자 획을 포함하며 벽 77개라는 뜻이 아니다. 원래 127.0.0.1 작업은 변경하지 않았다.
- 빌드 성공, 자동 테스트 129개 통과. 부분 실패, PDF 텍스트 재사용, 취소, 분석 좌표 저장 검증 포함.

M0는 여전히 미완료다. 이 단계는 한 페이지의 자동 분석 통합이며 여러 PDF 페이지의 자동 선택·방향/영역 판단·자동 축척·전체 공간 초안 생성은 아직 연결하지 않았다. 현재 배치 동작은 기존 프로젝트의 참고 도면을 바꾸며 별도 전체 공간 초안을 생성하지 않는다. 다음 우선 작업은 자동 축척/구조 구성에 필요한 결과 결합과 별도 초안 생성이며, 페이지 선택 자동화도 병행해 사용자 개입을 줄인다.
