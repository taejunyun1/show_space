## 도면 회전·평면 영역 선택
- 가져오기 창에서 좌/우 90도 회전, 드래그 사각 영역 선택과 픽셀 좌표 입력, 선택 영역 자르기, 원래 페이지 복원을 추가했다.
- 변환은 PNG로 처리하고 재확대하지 않는다. 회전 후 좌표 기준으로 자르며 이미지 밖/너무 작은 수치 입력은 거절한다. 자르기 전 품질 안내임을 표시한다.
- 페이지/렌더 해상도를 바꾸면 해당 원본 페이지를 새로 불러와 변환을 초기화한다. 변환 중 다른 편집·배치를 막는다.
- 실제 JICA 43쪽을 90도 회전 후 첫 평면 1200×530px로 자르는 브라우저 검증 수행. 배치 시 비율 1200:530 유지, 축척 미보정 상태에서 두 점 보정 진입 확인.
- 회전된 색상 픽셀의 실제 위치와 영역 추출, 경계/역방향/잘못된 입력 자동 테스트 추가.
- 임의 각도 기울기/원근 보정, 여러 평면을 각각 프로젝트에 저장, OCR·벽 자동 인식은 남아 있다. 원래 페이지로 복원은 가져오기 창을 열어 둔 동안만 가능하며 원본 파일 영구 저장은 아직 아니다.

## 벽 후보 검토 및 추가 — 실험 기능

- 평면도에 **벽 후보 찾기** 추가. 로컬 Web Worker에서 어두운 수평/수직 선을 찾고 인접 픽셀 줄을 합쳐 중심선 후보를 만든다.
- 분석 작업은 최대 1400px 작업 이미지, 후보 최대 100개로 제한. 원래 도면 픽셀 좌표로 돌려 검토 화면에 표시한다. 대비/최소 길이 설정 및 다시 분석 제공.
- 초기 선택은 0개. 선 또는 목록 체크박스로 선택하며, 축척 설정 전에는 벽 추가를 막는다. 알려진 길이의 후보 하나를 골라 실제 mm 길이를 입력해 축척을 설정할 수도 있다.
- 사용자가 선택한 후보만 내부벽으로 추가한다. 높이/두께는 입력값이며 자동 측정이라고 표현하지 않는다. 원래 벽/작품 유지, 중복 후보 제거(끝점 5mm 이내), 200벽 제한, 한번의 Undo/Redo 지원.
- 실제 JICA 43쪽을 이전 단계에서 회전/자른 1200×530 도면으로 브라우저 분석: 28개 직선 후보. 치수선 오검출과 일부 벽 누락/분절도 시각적으로 확인했다. 후보 수는 정확도나 정답 벽 개수를 뜻하지 않는다.
- 합성 800×500 검증 도면의 400/200/180px 선 3개 검출. 400px 선을 알려진 4000mm로 설정하여 4000mm 내부벽 생성, 3D 렌더, Undo 검증. 검증 변경을 되돌려 기존 실제 도면으로 복원했다.

한계: 사선·곡선·희미하거나 기울어진 벽, 벽의 의미 분류, OCR 치수, 이중 선의 벽 두께 추정, 자동 접합/폐합은 미구현이다. 치수선/가구/표제란도 검출될 수 있다. 건물 전체를 자동 복원하는 기능이 아니라 수동 검토를 전제로 한 선 후보 입력 도구다. 현재 기본 샘플 공간을 자동 삭제하거나 대체하지 않는다.


## 자동 인식 목표 보완 — 사용자 범위 지정
벽 길이·높이·두께, 출입구, 에어컨, 소화전 등 설비와 계단/설치 제한 영역을 **도면 입력 시 자동 인식할 대상**으로 확정했다. 기존 계획의 계단 인식 제외 문구를 수정했다. 치수별 근거·미확인 상태, 객체 점유와 접근 공간 구분, 벽 양면별 설치 가능 구간, 시설 지침 확인을 설계에 반영했다. 이 변경은 인식 명세 업데이트이며 현재 구현된 선 후보 기능이 해당 의미 인식 기능을 수행한다는 뜻은 아니다. OCR/기호·범례 분석 처리기와 검토·제한 영역 계산 구현이 필요하다.

## 문자 기반 설비·치수 후보 인식 (2026-09-11)

- PDF 텍스트 좌표를 도면 픽셀 좌표로 변환하고, 텍스트가 없는 페이지·이미지는 브라우저의 한국어+영어 OCR로 읽는다. OCR은 로컬 모델을 사용하며 도면을 외부 API로 전송하지 않는다. 취소·90초 시간 제한·재인식을 제공한다.
- 출입구/문/에어컨/소화전/소화기/계단/기둥/단위가 있는 치수 표기를 후보로 분류한다. 단위 없는 숫자는 치수로 확정하지 않는다.
- 평면도에 표기 상자를 표시하고 종류 수정, 표기 확인, 오인식 제외를 지원한다. JSON/로컬 저장에 원문·상자·출처·검토 상태를 포함한다. 회전·자르기에 상자를 변환하며 잘린 문자는 제외한다.
- **상자는 문자 위치이며 설비 실체나 설치 금지 면적이 아니다.** 확인 상태 역시 문자 종류·위치 확인만 뜻한다. 문 기호/계단 범위/설비 점유 및 접근 영역, 벽과 치수 연결·높이/두께 추정, 벽 양면 설치 가능 구간 계산은 남아 있다.
- PDF에 일부 텍스트만 있고 본문이 스캔이면 자동 OCR이 생략될 수 있으므로 ‘문자 다시 읽기’를 사용할 수 있다. 이 동작은 현재 가져오기 미리보기의 문자 후보를 새 OCR 결과로 교체한다.
- 실제 Japan Foundation 도면 6페이지: PDF 텍스트 후보 9개(Up/Dn, Entrance, Sliding Folding Door, 2m wide Door, 치수 표기 등). 후보 수는 실제 설비 개수나 정확도가 아니다.
- 합성 영문 이미지: 7개 표기 추출, 확인/제외/평면도 반영/Undo 브라우저 검증. 합성 한국어 이미지(AppleGothic): 6개 표기 중 5개 추출, ‘출입구’ 누락. 한국어 OCR의 누락 가능성을 확인했으며 실제 저해상도·기호 전용 도면에 대한 정확도 검증은 아직 없다.
- 빌드 및 자동 테스트 100개 통과. 기존 사용자 도면은 테스트 후 복원했다.

## 숫자 인식 집중 개선 (2026-09-11)

사용자 결정: 설비 이름 OCR 개선은 후순위로 두고 숫자 인식 단계를 먼저 마무리한다.

- 단위 없는 숫자, H/T/W/L 표기, 전각 숫자, 연속 치수 숫자를 후보에 포함한다. 단위는 임의로 mm로 가정하지 않는다. 쉼표의 천 단위/소수 해석을 둘 다 보존하며 저점수 OCR과 여러 숫자를 별도 안내한다.
- 축척 1:100, A101 같은 번호, 날짜·레벨 표기 등은 숫자 판독기에서 제외한다. 단독 숫자는 페이지/실 번호일 수도 있어 검토 후보로만 남는다. O/0, I/1 등을 자동 치환하지 않는다.
- ‘숫자 정밀 다시 읽기’: 영문 모델과 최대 2배 확대·3600px 입력 사용. 문자 화이트리스트로 비숫자를 강제 변환하지 않는다. 새 숫자 후보로 교체하고 기존 비치수 설비 후보를 유지한다. 확대는 원본의 손실된 정보를 복원하지 않는다.
- 숫자 검토 화면에 해당 원본 부분을 확대 표시한다. ‘숫자 정정 저장’은 원문을 유지한 채 correctedText를 저장하며 검토 상태를 초기화한다. 저장/회전/자르기에서도 정정값을 보존한다.
- 브라우저 합성 이미지 검증: 3200, H=2800, 200 mm, 3,200, 1200 2400 3600의 5개 표기 인식. 1:100/A101 제외. 정밀 읽기 후에도 동일 표기 판독. 3,200 → 3200 mm 정정·확인·Undo 검증. 이는 실제 저해상도 도면 정확도 수치가 아니다.
- 실제 Japan Foundation 6쪽: 이전 9개에서 단위 없는 숫자 후보가 추가되어 총 53개 표기 후보. 증가 수는 정확도 개선율이나 실제 치수 수가 아니다. 원본 파일이나 사용자 작업은 변경하지 않았다.
- 빌드 성공, 자동 테스트 107개 통과. 숫자 단계는 이 범위에서 마무리한다.

다음 구현 단계: 검토한 숫자와 치수선/벽 후보의 연결. 단위·대상 벽·길이/높이/두께를 확인한 뒤 적용하며 현재는 자동 벽 치수 변경을 수행하지 않는다. 복잡한 기호 인식이나 설비 이름 OCR 개선으로 이번 숫자 단계의 범위를 확대하지 않는다.

## 확인한 숫자 → 벽 치수 연결 (2026-09-11)

- 숫자 검토 화면에 ‘벽 치수에 연결’을 추가했다. 확인된 단일 숫자에 대해 대상 벽·길이/높이/두께·단위를 선택하면 기존 값과 변경 값을 미리 보여준다.
- 높이·두께는 선택 벽에 적용한다. 길이는 시작점과 방향을 유지하고 끝점을 움직이며 연결된 벽 모서리도 함께 변경한다. 도면 축척은 바꾸지 않는다. 변경 후 작품 배치 경고 수를 표시한다.
- 모호한 쉼표·연속 숫자·가로×세로 표기는 하나로 정정해야 적용할 수 있다. 명시된 단위나 H/T 역할과 선택이 다르면 차단한다. 잠긴 벽과 연결된 잠긴 모서리를 보호한다. 입력 한도는 길이 200m, 높이 20m, 두께 2m다.
- 적용 원문·정정값·치수·출처는 벽 메모에 기록하며, 한 번의 Undo로 해당 적용을 복원한다. 기록은 적용 당시의 이력이며 이후 숫자 수정에 따라 벽 치수를 자동 갱신하지 않는다.
- 브라우저 검증: OCR H=2800 → 벽 A 높이 3200→2800mm, 3200 → 벽 A 길이 8000→3200mm. 이후 모든 테스트 변경을 되돌려 길이 8000/높이 3200과 기존 도면을 복원했다. 빌드 및 자동 테스트 111개 통과.

현재 대상 벽 연결은 사용자가 선택한다. 치수선/벽 위치에 따른 자동 대응, 자동 전체 축척 보정, 설비·계단 점유 및 설치 제한 영역은 아직 구현하지 않았다.

## 도면 위치 기반 벽 추천 (2026-09-11)

- ‘벽 치수에 연결’에서 숫자 표기 중심과 기존 벽 선분의 거리를 비교해 최대 3개 벽을 추천한다. 추천 버튼으로 대상 벽을 선택한 뒤 기존 치수 미리보기/적용 흐름을 사용한다. 자동 선택·일괄 적용은 하지 않는다.
- 축척 보정된 도면에서만 동작한다. 벽과 도면은 사용자가 정렬해 두어야 한다. 숫자/추천 벽을 같은 도면에 표시하며 선택한 벽을 강조한다.
- 모호한 숫자·가로×세로·제외된 표기는 추천하지 않는다. 화면 밖/숨긴 벽, 벽 끝을 벗어난 연장선, 멀리 있는 벽은 후보에서 제외한다. 비슷한 거리의 벽은 중복 후보 안내를 표시한다. 잠긴 벽은 표시하되 선택 버튼을 비활성화한다.
- 자동 테스트: 수평벽 거리, 모서리 모호성, 사선벽, 연장선 제외, 미보정/먼 표기/숨김/화면 밖 벽 검증. 전체 115개 통과, 빌드 성공.
- 별도 localhost 저장 공간의 합성 도면 브라우저 검증: 7000 mm 표기와 28px 거리의 테스트 벽 1 추천, 도면 겹침 표시, 추천 선택 → 대상 벽/길이 적용 미리보기 연결 확인. 원래 127.0.0.1 사용자 프로젝트는 변경하지 않았다.

한계: 문자와 벽의 근접도에 따른 추천이다. 치수 보조선·화살표·벽 의미나 전체 치수와 부분 치수의 관계를 해석하지 않는다. 실제 복잡한 도면의 자동 대응 정확도를 검증한 결과가 아니며, 추천이 없어도 수동 연결은 가능하다.

## 치수선·보조선 근거 비교 (2026-09-11)

- 벽 치수 연결에 ‘주변 치수선 분석’을 추가했다. 로컬 이미지의 얇은 수평/수직 선을 검출하고, 숫자 근처 평행선의 양 끝과 벽 양 끝이 맞으며 두 수직 보조선이 연결되는 경우를 후보로 제시한다.
- 주황색은 검출한 선·보조선, 파랑은 대상 벽이다. ‘길이 연결’로 대상 벽과 길이 항목을 선택하고 기존 확인/미리보기/적용을 사용한다. 분석 자체는 프로젝트 치수를 변경하지 않는다.
- 미보정 축척, 모호한 숫자, 가로×세로, H/T 표기, 부분 길이, 한쪽 보조선만 있는 경우를 제외한다. 기존 거리 추천과 수동 연결을 유지한다. 취소와 기존 20초 선 검출 제한을 사용한다.
- 선 검출은 최대 1400px 입력·100개 후보로 제한하며 이 기능에 한해 1px 선도 허용한다. 기존 벽 후보 찾기의 2px 기본값은 유지한다.
- 자동 테스트 121개 통과, 빌드 성공. 순수 좌표 조건과 실제 RGBA 얇은 선 검출 연동, 수평/수직, 뒤집힌 끝점, 부분 치수·누락 보조선 제외를 검증했다.
- localhost 합성 도면 브라우저 검증: 8000 mm와 선·보조선의 근거가 맞는 벽 1개 검출, 강조 표시 및 길이 연결 버튼으로 대상 벽/종류 선택 확인. 127.0.0.1의 사용자 프로젝트는 변경하지 않았다.

한계: 화살표 기호 자체는 판독하지 않는다. 문자로 끊긴 치수선, 사선 치수, 희미한 선, 전체/부분 치수 계층, 연결되는 다른 구조선을 치수선으로 오인하는 경우를 아직 해결하지 않았다. 실제 복잡한 도면의 정답률 검증이 아닌 검토용 구조 근거 후보 기능이다.

## 숫자 자리에서 끊긴 치수선 (2026-09-11)

- 숫자 상자의 양쪽에서 끝나는 동일 축 선분을 치수선 후보로 묶는다. 틈 위치가 숫자 상자와 맞고, 선이 숫자 영역을 지나며, 양 끝 보조선과 벽 끝점까지 맞아야 한다.
- 검출된 원본 선분은 유지하고 추정 연결 구간은 보라 점선으로 별도 표시한다. 이미지나 프로젝트 벽을 분석만으로 수정하지 않는다. 연속 선 근거가 있으면 추정 연결보다 우선한다.
- 큰 틈, 다른 축, 숫자 영역 밖의 단절, 보조선 누락은 제외한다. 수평/수직 및 반대 방향 끝점을 지원한다.
- 빌드 성공, 전체 자동 테스트 124개 통과. 브라우저의 합성 단절 치수선 이미지에서도 벽 1개 검출 및 추정 점선/안내를 확인했다. 기존 127.0.0.1 프로젝트는 변경하지 않았다.

한계: 숫자 밖의 손상·여러 단절·사선·화살표는 아직 처리하지 않는다. OCR 문자 상자가 부정확하면 후보를 놓치거나 잘못 묶을 수 있다. 실제 복잡한 도면에서의 정답률 검증은 별도 과제다.

검증: 143개 테스트. 기존 축척 검증과 프로젝트 유효성 검사까지 내부 벽을 유지하는 통합 사례 포함. 실제 복잡 도면 성공률은 아직 검증하지 않았다.


## 실도면 검증 및 자체 재분석

공개 도면 2종 3페이지의 로컬 검증은 완전 공간 생성 0/3이었다. `docs/validation/2026-09-11-real-plans.md`에 입력 출처, 재현 방법, 실패 원인을 기록했다. 사용자 체크를 기본 흐름으로 요구하지 않고 3개 선 검출 조건을 자동 실행하며, 최소 두 성공 결과의 구조·축척 일치와 충돌 부재를 확인한다. 빈 PDF 인식 표기는 로컬 OCR로 전환한다. 151개 자동 테스트 통과, 실도면 러너는 별도 실행했다. API는 사용하지 않았으며 M0는 미완료다.


## 공간 복원 1차 — 공유 벽·접합·짧은 연결부

실제 교차점을 분리하고 평면 그래프에서 외곽/내부 벽을 추출한다. 짧은 연결부는 양끝과 긴 구조 네트워크의 연결을 검사해 유지한다. 원래 길이의 치수 근거는 분할 후에도 축척 계산에 사용한다. 160개 테스트와 빌드를 통과했다. 실도면 재검증은 여전히 전체 생성 0/3이며 개구부·이중선·사선 검출은 미완료다. 구체적인 후속 구현은 `docs/implementation/space-reconstruction.md`에 기록했다. 사용자 요청에 따라 이번 변경은 웹에 배포하지 않는다.


## 개구부 경계 모델 및 자동 연결

문/창문을 실제 벽과 분리된 개구부로 저장하고 벽 끝점에 연결했다. 바닥 경계에만 가상 연결을 사용하며, 작품 설치면이나 3D 벽 메시로 생성하지 않는다. 2D/3D는 개구부를 점선으로 표시한다. 벽 수정 시 연결점을 따라가고, 삭제 시 해당 개구부를 제거하며 Undo/Redo로 복원한다. JSON 검증은 잘못된 참조/중복 ID/0 길이를 거부한다.

문·창문 표기와 같은 선상에서 서로 마주 보는 벽 끝점의 틈이 유일하게 연결될 때 자동 후보를 생성한다. OCR 90 미만, 여러 후보 충돌, 다른 선과 교차, 검증 범위 밖 폭은 보류한다. 폭은 문자 상자가 아니라 실제 벽 끝점으로 계산한다. 문짝 회전호·창틀·상인방/창턱 높이는 아직 추론하지 않는다. 문·창문 후보 유형과 위치도 3회 자체 검증 결과 비교에 포함했다.

169개 자동 테스트와 빌드 통과. 별도 로컬 포트의 브라우저에서 개구부 프로젝트 불러오기, 3D의 열린 출입구와 이어진 바닥, 평면 전환 및 오류 없음 확인. 공개 도면 3페이지 재검증은 여전히 완전 생성 0/3이다. `docs/validation/2026-09-11-openings-retest.json` 참조. 웹 배포하지 않음. 전체 다섯 목표는 계속 미완료 상태이며 다음 구현은 이중선·선 후보 유실 처리다.


## 후보 보존·이중선·전체 단위 선언

자동 분석은 최대 500개 선 후보를 보존하고 수동 도구는 기존 100개 기본값을 유지한다. 저장 검증도 500개까지 허용한다. 양끝을 잇는 선이 유일하게 확인되는 평행 이중선만 중심선 후보로 변환한다. 끝이 열린 평행선, 복도 폭의 간격, 경쟁하는 끝단 근거는 합치지 않는다. 이 판정은 구조 후보 판정이며 길쭉한 가구/창틀의 의미 분류까지 해결한 것은 아니다.

페이지 전체의 명시적 단위 선언(예: All measurements in cm, 단위: mm)을 표기로 보존하고 단위 없는 숫자의 자동 축척 계산에 적용한다. 원래 숫자와 개별 명시 단위를 유지하며 서로 충돌하는 전체 단위, 낮은 OCR 점수, 특정 객체 치수 문구는 기본 단위로 사용하지 않는다. Espacio 실제 두 페이지에서 cm 선언 보존을 확인했다.

179개 테스트와 빌드 통과. 동일 공개 도면 재검증은 전체 생성 0/3으로 유지되며, 일부 입력은 500개 상한에도 도달했다. 후보 수 증가는 정확도 개선으로 집계하지 않는다. `docs/validation/2026-09-11-paired-units-retest.json`에 결과를 보존했다. 외부 API와 웹 배포는 사용하지 않았다. 다음은 세로/회전 숫자와 구조선 근거 보완이다.


## 세로·회전 숫자 자동 보완

래스터 OCR 입력을 0° 일반 인식 후 90°/180°/270° 숫자 인식으로 보완한다. 회전·확대 좌표를 원본으로 되돌리고, 겹친 같은 숫자는 중복 제거한다. 다른 값은 원문과 충돌 플래그를 보존하며 자동 축척/치수선 연결에서 제외한다. 낮은 점수의 추가 인식은 채택하지 않는다. 회전별 실패/취소를 처리하고 기존 PDF 문자 근거는 불필요한 회전 OCR로 대체하지 않는다.

185개 테스트 및 빌드 통과. 공개 Espacio 1페이지에서 시각적으로 선택한 세로 치수 7개를 정답 영역으로 기록했으며, 자동 사용 가능한 정확한 값이 기본 OCR 0/7 → 회전 보완 5/7로 증가했다. 60은 반대 방향의 09와 충돌해 제외, 125는 미확보다. 선택한 7개에 대한 결과이지 전체 페이지 정확도가 아니다. 원본 PDF SHA-256과 좌표/정답을 `docs/validation/espacio-selected-numbers.json`에, 결과를 `docs/validation/2026-09-11-rotated-numbers.json`에 보존했다. Node Canvas/Tesseract로 실제 래스터를 검증했으며 브라우저 렌더링 전체 흐름 재검증은 별도다.

전체 공간 생성은 여전히 0/3으로 다섯 목표는 미완료다. 외부 API 및 웹 배포는 사용하지 않았다. 다음은 전체/부분 치수 연결과 구조선 단절 근거 보완이다.


## 전체/부분 치수 연결 및 두꺼운 선 교차점 보정

연속된 여러 벽의 전체 치수, 하나의 벽 중간에 놓인 부분 치수를 치수선 및 양끝 보조선으로 연결한다. 실제 벽이 없는 구간은 연결하지 않는다. 부분 치수가 전체 구간을 빈틈없이 구성할 때 합계를 대조하고 2%를 넘는 불일치를 보류한다. 겹치거나 경쟁하는 부분 치수는 합산하지 않는다. 자동 공간 생성과 축척 검증에 통합했다.

두꺼운 래스터 선 끝의 외곽 픽셀과 수직 벽 중심선 사이 오프셋을 선 두께와 상한 12px로 보정한다. 수평·수직 방향을 유지하고, 경쟁하는 교차점/문 크기의 틈/선분 붕괴는 보정하지 않는다. 고정 4px 근접 연결 전에 처리한다.

193개 테스트와 빌드 통과. 동일한 공개 도면 재검증은 전체 생성 0/3이다. Espacio에서 구조 후보가 늘었지만 정답 구조 재현율이나 성공률 향상으로 집계하지 않는다. 결과는 `docs/validation/2026-09-11-dimension-spans-retest.json`에 보존했다. 다음은 외곽 후보와 가구·범례 선 분리 및 사선 검출이다. 전체 다섯 목표는 미완료이며 외부 API/웹 배포는 사용하지 않는다.


## 래스터 벽 띠 병합·회전 시설 표기·계단 검출 범위

두꺼운 벽이 여러 평행 띠로 분리되었을 때 원본 이진 픽셀의 97% 이상이 채워진 구간만 병합한다. 16px 두께 상한, 길이 90% 이상 겹침과 끝점 차이 제한을 적용하며 빈 간격이 있는 평행선은 유지한다. 회전 OCR에서 얻은 90점 이상 시설 표기도 보존한다.

계단 표기 주변의 규칙적인 반복 단 선 3개 이상으로 검출 범위를 만든다. 문자 상자를 면적으로 사용하지 않는다. 최소 두 분석 조건이 일치하고 나머지 검출 결과에 모순이 없어야 분석 화면과 평면도에 표시한다. JSON 저장/불러오기에서 선·표기 참조와 범위를 검증한다. 현재는 검출한 단 선의 범위 표시이며 계단 전체 외곽 복원, 3D 계단 모델, 작품 배치 차단은 아직 구현하지 않았다.

202개 자동 테스트 및 빌드 통과. 실제 Espacio 1페이지에서 출입문·창문·계단 표기를 얻었고 계단 영역 1개가 세 조건에서 일치했다. 공개 도면 3페이지의 전체 공간 자동 생성은 여전히 0/3이다. 결과는 `docs/validation/2026-09-11-stair-regions-retest.json`에 저장했다. 로컬 Node Canvas/OCR 검증이며 이번 표시 변경의 브라우저 검증은 별도다. 외부 인식 API 및 웹 배포 없이 구현했다.

다음 우선순위는 실제 도면 외곽의 누락 선 복원과 가구·계단 단 선의 벽 오분류 제거다. 이후 사선, 완전한 설치 제외 영역 및 자동 페이지 선택을 검증한다. M0와 다섯 세부 목표는 계속 미완료다.


## 계단 단 선의 벽 오분류 제거

계단 표기와 규칙적 단 선의 결합 근거가 있을 때, 가운데 단 선을 이중벽 병합·구조 그래프 구성 전에 벽 후보에서 제외한다. 양쪽 끝 선은 계단실 벽일 수 있어 유지하며 다른 선으로 같은 방향으로 이어지는 단 선도 제거하지 않는다. 원본 분석 선은 보존한다. 자동 공간 채택에는 기존의 여러 검출 조건 간 일치 검증이 계속 적용된다.

204개 테스트와 빌드를 통과했다. 실제 Espacio 1페이지에서 세 조건 모두 가운데 계단 선 1개가 벽 후보에서 빠져 후보 수가 32/34/39 → 31/33/38로 변했다. 다른 두 페이지는 변하지 않았다. 전체 공간 생성은 여전히 0/3이며 후보 수 감소를 전체 구조 정확도로 집계하지 않는다. 결과는 `docs/validation/2026-09-11-stair-tread-retest.json`에 보존했다. 외부 API·웹 배포 없이 진행했으며 다음 핵심 과제는 외곽 누락 선과 사선 검출이다.


## 사선 래스터 검출과 모서리 연결

수평·수직 띠를 제거한 잉크의 연결 성분에 주축 직선을 맞춰 사선 후보를 검출한다. 길이·폭·횡방향 편차·연속 구간 조건을 함께 확인하며 서로 떨어진 성분을 합치지 않는다. 꺾인 선 묶음은 직선으로 바꾸지 않는다. 이것은 사선 후보 검출이며 가구와 벽의 의미 구분이나 서로 연결된 복잡한 사선망 전체의 분해까지 해결한 것은 아니다.

두꺼운 구조 후보의 사선 교차점도 기존 12px 이내 두께 기반 오차 범위에서 연결한다. 얕은 교차각, 경쟁하는 교차점, 큰 틈은 보정하지 않는다. 얇은 치수 보조선은 구조 모서리 보정에 참여시키지 않는다. 사선 후보가 수직 띠 병합에 들어가는 경우도 차단했다.

209개 테스트와 빌드 통과. 양·음 방향과 수평/수직에 가까운 각도, 실제 틈 보존, 꺾인 성분 거부를 검증했다. 사선 외벽을 포함한 합성 래스터 방에서 벽 검출→모서리 연결→독립 치수 근거 2개→축척 있는 닫힌 공간 생성까지 통과했다. 합성 사례는 실제 도면 완료율에 포함하지 않는다.

공개 도면 재검증 결과는 `docs/validation/2026-09-11-diagonal-retest.json`이며 전체 자동 생성은 여전히 0/3이다. 새로 검출된 사선 후보의 실도면 정답 여부는 별도 주석 검증이 필요하다. 사용자가 체크하는 단계는 추가하지 않았다. 외부 API/웹 배포 없이 진행했다. 다음은 외곽 누락 구간의 원본 픽셀 근거와 복잡한 선망 분해다. 전체 목표는 미완료다.


## 연결 근거가 있는 얇은 구조선 보존

## 치수 좌표의 구간별 변환 기반

## 변환된 도면 레이어와 이미지 준비

`prepareMappedVenue`는 구간별 좌표 변환으로 벽을 나누고 개구부의 벽 끝점 참조를 새 조각에 연결한다. 숫자·설비 표기, 계단 영역과 검출 근거 선을 동일한 스칼라 도면 좌표로 옮겨 기존 프로젝트 형식을 사용할 수 있게 한다. 범위 밖 표기/선은 별도 결과로 반환하고 계단 영역 또는 근거 선이 누락되면 변환을 보류한다. 원본 페이지는 호출자가 보존해야 한다. 선 굵기는 표시용 보정이며 벽 두께 측정이 아니다.

자동 가져오기 흐름에는 아직 연결하지 않았다. 실제 도면 인식 알고리즘은 이번에 변경하지 않았으며 직전 실제 검증의 전체 생성 0/3 상태를 개선했다고 주장하지 않는다. 다음은 변환 가능한 분석 결과를 이 경로로 보내고 원본 보존·제외된 표기 처리·브라우저 렌더링을 검증하는 작업이다. 웹 배포 없이 커밋·푸시하며 전체 목표는 미완료다.


## 개별 치수 복원을 자동 가져오기와 3D에 연결

`prepareConstrainedVenue`가 닫힌 구조·개구부·전체/부분 치수·인접 숫자를 모아 좌표를 풀고 변환 레이어를 준비한다. `analyzePlan`은 기존 단일 축척 방식이 실패할 때 이 결과를 사용하며, 서로 다른 조건에서 두 개 이상 일치하고 다른 성공 결과와 충돌하지 않을 때만 이미지를 변환한다. 렌더링 실패/취소 시 적용하지 않는다. 원본 이미지·해상도·표기는 검증되는 `sourcePlan` 필드로 저장한다. 숫자/선/크기가 바뀌면 기존 변환 결과를 재사용하지 않는다.

미리보기는 변환된 이미지와 같은 좌표를 사용한다. 변환 전 원본을 펼쳐볼 수 있고 적용 후에도 원본 저장이 가능하다. 도면을 교체/제거하면 이전 원본 연결도 제거한다. 서로 다른 분석 결과 비교에 벽 높이·두께와 계단 설치 제외 영역도 포함했다.

실제 이미지 입력에서 치수선의 1px 끝 돌출이 벽 끝과 별개 좌표로 처리되는 문제를 발견했다. 보조선 검증을 유지하면서 유일한 벽 끝점이 1px 이내에 있을 때만 맞춘다. 치수 문자의 선과의 거리도 글자 크기에 따라 최대60px까지 허용하되 양 끝 보조선과 유일한 구간 조건은 유지한다.

## 분리된 치수 묶음 사이의 배치 모순 검증

서로 연결되지 않은 치수 묶음도 원본 좌표의 순서를 공유한다. 인접 좌표의 순서를 유지하는 묶음별 위치 제약을 만들고 양의 순환이 생기면 배치 불가능으로 판정한다. 예를 들어 내부 구간2000mm가 이를 감싸는 구간1000mm 안에 들어가야 하는 경우, 각 묶음 내부에 숫자 모순이 없어도 전체 배치는 불가능하다. 보정된 위치값을 결과로 사용하거나 빈 구간의 길이를 생성하지 않는다. 0.001mm 수치 허용 오차를 사용한다.

## 정상 PDF 문자층과 이미지 설비 표기의 혼합 인식

문자층이 정상이라는 이유로 OCR을 생략하면서 이미지로 삽입된 비상구·소방 표지를 놓치는 문제를 확인했다. 정상 PDF의 기존 숫자·단위는 보존하고 전체 및4개 겹치는 구역의 로컬 OCR로 설비 표기만 추가한다. 구역 OCR은 최대2배/3600px, eng+kor를 사용하며90점 이상만 채택한다. 보완 실패 시 원래 문자 근거를 보존하고 취소는 즉시 중단한다. 겹치는 표기는 중복 제거하며 새 ID의 충돌을 피한다. 명시적인 FIRE HOSE REEL 표기도 소화전 계열로 분류하지만 그림 자체를 분류한 것은 아니다.

## 실제 공간 생성과 치수 검증 경로 통일

실제 공간 생성에서 문·창문 양쪽의 평행 벽 축 일치 근거를 치수 해석기에 전달하지 않던 누락을 수정했다. 기존 corpus 계산은 이 근거를 사용하고 있어 앱보다 강한 조건으로 측정하고 있었다. `venueDimensions`를 양쪽 경로에서 공유해 벽 표기·개구부 치수·치수선·축 일치 근거가 같도록 했다. 알려진 개구부와 평행한 양쪽 벽, 최대2px의 오차가 있어야 축을 연결하며 모서리 문이나 단순 근접은 근거로 삼지 않는다.

좌표 변환에서도 해석기가 합친 축을 그대로 적용한다. 그렇지 않으면 같은 축으로 판정한 벽 끝점이 보간 때문에 다시 어긋난다. 역변환은 대표 원본 축으로 돌아가며 이 미세한 축 보정은 완전한 가역 변환이 아니다. 보정으로 순서가 뒤집힌 작은 영역은 거부한다. 회귀 사례에서 분리된 두 가로 치수 연결이 해석됐고 문 폭과 세로 치수가 없는 상태는 계속 미확정이었다.

실제4개 PDF/5개 대상 페이지를 재검증했다. Espacio1의 창문 축 연결 근거가 공통 계산에 포함되지만 아직 독립된 치수 연결이 다수 남는다. Espacio2의180/225 표기 충돌 역시 남으며 평면 도면 전체 생성0/4, 사시도0/1은 변하지 않았다. 결과: `docs/validation/2026-09-12-venue-dimensions-retest.json`. 웹 배포 없이 커밋·푸시한다.


## 벽 옆에 붙은 가구와 실제 K2 도면

공식 K2 Gallery Floorplan을 새 회귀 자료로 추가했다. 출처·SHA256을 manifest에 기록하고 원본은 임시 폴더에만 보관한다. 소수점 쉼표가 포함된 벽 식별번호 치수, 두 전시실, 회색 벽, 문짝과 가구를 포함한다. 도면 전체 정답이나 정확한 축척 검증 자료로 간주하지 않는다.

`Glass Table`을 명시적인 가구 표기로 분류한다. 가구의 네 변을 확인할 때 원래 방향과 전치 방향을 함께 검사하여 긴 벽을 수평·수직 어느 쪽에서 공유하더라도 독립된 가구 변만 제외하도록 했다. 동일 제안은 합치고 서로 다른 외곽 제안이 있으면 분리를 보류한다. 긴 공유 벽은 남긴다. 별도 방 이름 등 더 긴 문구를 가구로 넓게 분류하지 않는다.

실제 K2에서 Glass Table 표기가 새로 인식됐다. 검출 조건125에서는 테이블 윗선(x426.75~696.68,y1237.71px)이 제외되어 벽 후보73→72가 됐다. 조건155/190은 각각95/103으로 변화가 없었으며 회색 벽과 맞닿은 외곽 분리는 미해결이다. 기존 도면의 전체 공간 생성 상태는 유지됐고 새 자료를 포함한 평면 도면 전체 생성은0/5, 사시도0/1이다. 가구 인식·분리 전체가 완료됐다는 뜻이 아니다. 결과: `docs/validation/2026-09-12-attached-furniture-retest.json`.

가로·세로 공유 벽 보존, 불완전/모호한 외곽 제외를 회귀 테스트하고 전체 테스트·빌드 및 실제5개 PDF/6개 페이지를 재검증했다. 이 배치는 브라우저 조작 검증 없이 도메인 계산과 corpus 결과를 확인했으며 웹 배포 없이 커밋·푸시한다.


## 회색 벽과 이어진 가구 선의 부분 분리

앞선 K2 검증의 원인을 정정한다. 원본 검출 좌표를 추적한 결과125/155/190 모두 테이블 외곽 자체는 찾았다.155/190에서는 얇은 가구 가로선이 회색 벽 내부까지 연속되어 길어졌고, 긴 공유 벽 보존 규칙 때문에 그 선 전체를 남긴 것이 원인이었다.

독립적으로 확인된 가구 사각형에서 얇은 선의 한쪽 끝만 가구에 해당하고 반대쪽은 더 이어질 때, 가구 밖까지 이어지는 두꺼운 수직 지지 벽이 정확히 하나 있는 경우에 한해 가구 쪽 부분을 잘라낸다. 남는 선 끝은 지지 벽 중심축에 맞춘다. 선 자체가 두껍거나 가구 양쪽 모두로 이어지거나 지지 벽이 없거나 여러 개이면 유지한다. 수평·수직 및 반대 방향에서 같은 규칙을 적용하고 입력 데이터를 변경하지 않는다.

실제 K2 테이블 윗선은 세 검출 조건에서 모두 벽 후보에서 제외됐다. 조건155는95→94개,190은103→101개이며125는72개로 유지됐다.155/190의 긴 회색 벽 중심선은 보존됐다. 기존 도면의 닫힌 경계 및 전체 생성 상태는 유지됐다. 전체 자동 생성은 여전히 평면 도면0/5, 사시도0/1이다. 가구 한 곳의 분리 개선으로 전체 복원을 완료했다고 보지 않는다.

339개 테스트·빌드와 실제5개 PDF/6개 대상 페이지 재검증을 통과했다. 결과: `docs/validation/2026-09-12-furniture-terminal-trim-retest.json`. 이번 배치는 브라우저 UI를 변경하지 않았으며 검증은 도메인 계산과 실제 PDF 처리 결과를 대상으로 했다. 웹 배포 없이 커밋·푸시한다.


## 복수 치수의 공유 단위와 잘못된 단일 길이 연결 수정

K2 창턱의 `Window sill: 2,68 x 0,38m`에서 앞의 단위 없는 숫자가 누락돼0.38m만 남고, 이를 수평 벽에380mm로 연결하는 오류를 재현했다. 곱하기로 연결된 치수 묶음 끝에 단위가 한 번 있으면 앞의 숫자에도 적용해2.68m와0.38m를 모두 보존한다. 복수 치수는 기존의 단일 벽 연결 조건을 통과하지 않는다. 이 표기가 폭·깊이 중 무엇인지 자동 확정한 것은 아니다.

공백 없는120x80x30cm, 서로 다른 단위의2mx30cm도 처리한다.2m×30처럼 일부 단위가 빠진 묶음도 숫자를 누락하지 않되 누락된 단위는null로 남긴다. 일반 문장의 앞 숫자까지 단위를 전파하지 않으며 쉼표의 소수점/천 단위 모호성은 유지한다.

가로로 적힌 식별번호 치수를 세로 벽에 연결하는 실험도 진행했으나, K2의B3=3.05m가 문 표시를 지나가는 긴 벽 전체에 연결되는 오인식을 확인했다. 해당 연결 변경은 적용하지 않았다. 문이 회색 벽 위에 덧그려진 구간을 먼저 분리해야 하므로 가로 글씨의 세로 벽 연결은 여전히 미완료다.

실제 PDF 재검증에서 K2 조건125/155의 잘못된380mm 연결이 제거됐다.190에는 원래 해당 연결이 없었다.125의 연결은0개,155/190에 남은 연결은2930/2790/1800mm이며 세로 치수를 새로 확정한 것은 아니다. 전체 공간 생성은 평면 도면0/5, 사시도0/1로 유지된다.341개 테스트·빌드와 실제5개 PDF/6개 대상 페이지를 검증했으며 웹 배포 없이 커밋·푸시한다. 결과: `docs/validation/2026-09-12-shared-dimension-unit-retest.json`.
