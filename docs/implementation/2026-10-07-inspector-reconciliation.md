# 2026-10-07 — 작품 정보 폼 중복 정리

공개 웹에서 첫 작품→다른 작품→벽을 선택하면 작품 정보 section 수가 1→2→1이 되어 이전 작품 정보 폼이 남았다. Inspector 소스는 작품 정보 폼을 한 번만 렌더했지만 같은 Fragment의 정보 폼과 재질 폼이 동일한 React key를 사용했다. 작품 교체 시 올바른 재조정을 보장하도록 정보/작품 재질/벽 재질에 서로 다른 접두어와 프로젝트·객체 ID를 사용한다. 작품 데이터·치수·저장 구조는 바꾸지 않는다.

관련 기존 테스트 11개와 TypeScript/Vite 빌드 통과. 로컬 새 탭은 브라우저의 ERR_BLOCKED_BY_CLIENT로 열리지 않아 새로운 로컬 UI 통과를 주장하지 않는다. 기존 공개 버전의 재현은 확인했으며 새 공개 버전에서 반복 전환 검증을 이어간다. [검증 기록](../validation/2026-10-07-inspector-reconciliation.json).

Cloudflare `458d4815-0a75-48ed-93a7-472084c4d6fb`/공개 entry `index-ClTHtoCy.js`에서 세 작품과 두 벽을 교차 선택했다. 정보 폼과 작가 필드 수 모두 1→1→0→1→0→1이며 오래된 폼이 남지 않는다. 콘솔 경고/오류 없음, 공개 프로젝트 데이터/Undo 변경 없음. [수정 화면](../validation/2026-10-07-inspector-public.png). 노멀 맵 등 앞선 구현은 이 배포에도 포함된다.
