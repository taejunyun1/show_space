# 2026-10-07 영상 벽면도 비율 · 프로젝터 1차 구현

원문 2 §61의 Projector / Throw Ratio / Distance / Aspect Ratio / Image Size / Brightness와 실제 공간 Geometry 투사를 구현하는 단계다. 사용자가 줄여 달라고 한 도면 인식·문/설비 직접 편집 범위는 확장하지 않는다. 사진의 자동 3D/재질 생성 유료 모델과도 별개다.

## 이번 변경

- 영상의 2D 포스터를 편집 벽면도·현장 설치 벽면도·공유 벽면도에서 원본 비율로 표시한다. contain은 검은 여백, cover는 가운데 크롭이다. SVG PNG 캡처에서도 같은 결과를 보존한다.
- PDF는 현재 배치와 Scene마다 실제 스크린 비율/fit에 맞춘 포스터를 준비한다. 같은 영상이라도 다른 배치의 포스터를 잘못 재사용하지 않는다. 현장 drawing 데이터에는 widthPx/heightPx/fit만 전달하고 영상 원본·재생 메타데이터를 넣지 않는다.
- 프로젝터를 기존 조명 객체의 `projection` 설정으로 저장한다. 선택·위치 이동·조준점 변경·잠금·복제/삭제·Undo·Scene·JSON/ZIP에 같은 편집 경로를 사용한다. 조명 없는 모델 기반 공간에서도 추가할 수 있다.
- 정지 JPG/PNG/WebP 입력, 자체 테스트 패턴, 렌즈 투사비 0.3–10, 화면 비율 0.5–3, 밝기 0–50,000 lm를 지원한다. 거리 입력은 100–100,000 mm다. 거리 변경은 조준점을 유지하며 프로젝터 위치를 이동한다.
- 폭 = 광축 거리 / 투사비, 높이 = 폭 / 화면 비율. 표시 크기는 광축에 수직인 면 기준이며 비스듬한 실제 표면에는 원근 모양으로 투사된다. contain/cover는 원본 이미지 비율을 보존한다.
- Three 0.180.0의 mapped SpotLight를 사용해 실제 MeshStandard/Physical 표면에 투사한다. 이미지 밖의 원뿔에 흰 빛이 남지 않도록 버전 검사된 셰이더 수정을 사용한다. [r180의 원본 셰이더](https://github.com/mrdoob/three.js/blob/r180/src/renderers/shaders/ShaderChunk/lights_fragment_begin.glsl.js)를 기준으로 하며 해당 문자열이 바뀌면 명확히 실패한다.
- 프로젝터는 최대 2대, 이미지 맵은 긴 변 1,024 px다. 프로젝터 차폐 그림자를 우선한다. 태양이 있으면 빠른 편집의 그림자 예산을 최대 3개까지 사용해 두 프로젝터의 차폐를 유지하며 전체 상한은 4개다.
- 광속/원뿔의 밝기 계산에 고정 미리보기 노출 0.05를 적용한다. 화면의 상대 비교용이며 실제 Lux·색 재현·장비 성능 검증은 아니다. IES/Lux/조도 맵 (§62), 영상 프로젝션, 렌즈 시프트/키스톤 보정은 구현 완료로 간주하지 않는다.
- 공유는 private imageUrl·NOTE·잠금을 제외하고 공개 이미지 ID와 투사 설정만 전달한다. 선택 Scene의 이미지는 전역 ID로 재매핑한다. 로컬 발표 자산은 공개 엔드포인트로 폴백하지 않는다.
- PNG와 PDF 3D 렌더 경로에 프로젝터 맵을 연결한다. 캡처는 최신 이미지/위치/설정이 실제 렌더에 반영될 때까지 기다린다. GLB/glTF 표준 광원에는 이미지 투사가 없어 프로젝터를 일반 흰 스팟으로 오인해 내보내지 않는다. 제외 범위는 내보내기 안내와 glTF 보고서에 명시한다.

## 확인한 증거

1. 격리된 자체 합성 프로젝트를 실제 앱의 JSON 복원 메뉴로 불러왔다. 기존 프로젝트는 보존했다.
2. 실제 브라우저에서 벽 이미지 투사, 앞의 차폐 벽에 의한 가려짐, 투사비 1.5 → 3의 2,000×1,125 → 1,000×562.5 mm 변화, 저장 Scene의 바닥 투사를 확인했다. `docs/validation/2026-10-07-projector-*.png`에 당시 화면이 있다. 이 증거는 마지막 contain/cover 맵 베이크 변경 전의 16:9 패턴 투사다.
3. 실제 편집 벽면도와 다운로드된 1,920×980 PNG에서 정사각 영상의 검은 여백/색 포스터를 확인했다. `2026-10-07-video-elevation-contain.png`, `2026-10-07-video-elevation-capture.png`에 보존한다.
4. 실제 Canvas 픽셀 검증으로 가로 영상의 여백/중앙 크롭, 축소된 포스터 좌표, 세로 프로젝터 이미지 여백/중앙 크롭과 원본 텍스처 불변을 확인했다. Canvas는 기존 PDF 의존성과 같은 @napi-rs/canvas 1.0.9를 개발 의존성으로 명시했다.
5. 실제 PDF 생성 후 PDF.js로 두 페이지를 렌더했다. 같은 영상의 현재 contain / 저장 Scene cover가 서로 다른 이미지와 정확한 픽셀로 출력됐으며 private NOTE는 없다. 원본 PDF는 `/tmp/gonggan-video-fitted-poster-20261007.pdf`, 렌더된 페이지는 validation의 `2026-10-07-video-pdf-{contain,cover}.png`다.
6. 실제 로컬 Worker/R2/D1에서 current + 선택 Scene을 발행했다. 이미지 ID 중복 제거, 바이트 동일 원본, 투사 설정 allowlist, 회수 후 HTTP 410을 확인했다. 첫 수동 검증 링크도 회수했다. 운영 계정/운영 공유를 사용하지 않았다.
7. 최종 전체 테스트·빌드·diff 검증 결과는 아래 실행 기록과 validation JSON에 남긴다.

## 아직 확인해야 하는 범위와 배포 상태

브라우저 자동화의 file chooser 대기 중 연결이 종료됐다. 초기화/재연결도 `failed to write kernel assets: No such file or directory`로 실패했다. 다른 브라우저 기술이나 인증 우회로 대체하지 않았다.

다음은 코드 연결 또는 자동 검증까지이며 실제 브라우저 완료로 표현하지 않는다: 마지막 투사 이미지 업로드/contain·cover 조작, 두 프로젝터 동시 UI, 밝기 0·잠금 UI, 실제 imported GLB 표면 투사, 공개/발표 3D 프로젝터 표시, 프로젝터 PNG/PDF 3D 출력. 재연결 후 자체 합성 프로젝트로 이어서 검증한다.

이번 추가 변경은 커밋/푸시 대상으로 보존하며 위 브라우저 검증 전에는 운영 배포하지 않는다. 현재 운영은 이전에 검증한 도면·3D 불러오기 및 영상 공유/발표 배포 상태를 유지한다. 운영 Supabase 계정/다른 기기 검증, 원문 §62 등 전체 미완료 항목은 요구사항 감사에서 계속 추적한다.

## 이미지 입력 후속 수정

- JPG·PNG·WebP의 실제 파일 시그니처와 디코딩 결과를 확인한다. 지원하지 않는 형식, 빈/손상 파일, 20MiB 초과 파일과 6천만 픽셀 초과 이미지는 적용 전에 거절한다.
- 5MB(5,000,000 bytes) 이하 파일은 다시 인코딩하지 않고 원본 바이트를 보존한다. 큰 파일은 기존 20MiB 입력·2,048px WebP 최적화 경로를 유지하고 화면에 최적화 여부를 알린다. 실제 투사 맵은 별도로 1,024px 상한을 유지한다. 후속 계정 공유 검토에서 5MiB와 서버 5MB 상한의 차이를 발견해 입력 기준을 서버와 일치시켰다.
- 프로젝트 ID와 조명 ID를 기준으로 Inspector를 분리한다. 이전에도 조명 ID가 다른 선택은 상위 Inspector에서 분리됐지만, 서로 다른 프로젝트의 같은 조명 ID는 상태가 재사용될 수 있었다. 이제 프로젝트 전환의 대기/오류 상태도 분리한다.
- 선택 변경·화면 닫힘·새 입력에서 이전 요청을 취소한다. 디코딩이 늦게 완료돼도 bitmap을 닫고, 완료 직전 현재 선택과 편집 데이터도 다시 확인한다. 잠긴 입력은 파일 필드까지 비활성화한다.
- 실제 PNG/JPG/WebP를 Canvas 백엔드로 디코딩하고 원본 바이트 동일성을 확인했다. 세로 PNG의 현재/저장 Scene → ZIP 왕복 → 공유 중복 제거도 확인했다. 손상 파일·대용량 최적화·디코딩 중 취소를 포함한 새 테스트 6개가 통과했다.
- 전체 테스트 1,001 통과 / 선택 실행 4 제외, 관련 최종 테스트 17 통과. 실제 브라우저 도구 초기화는 같은 kernel assets 오류로 실패했다. 파일 선택 UI·공유 3D·프로젝터 출력 및 운영 배포는 계속 미검증이다. 이 자동 검증을 실제 브라우저 완료로 대체하지 않는다.
