# 협업 댓글의 계정·공개 범위 전환 보호

2026-10-07. 운영 인증 설정과 브라우저 연결 대기는 사용자 결정에 따라 보류하고, 원문 2의 협업 Comment에서 독립적으로 검증 가능한 React 생명주기를 보완했다.

`ReviewCommentsPanel`의 기존 조건식은 `prefix + credential ? owner : account`로 평가되어 항상 owner 분기를 선택했다. 공개/비공개 문자열도 최종 식별자에 들어가지 않았다. 공개 열람 화면에서 로그인·로그아웃·계정 전환 시 같은 화면 context로 남아 이전 댓글/권한과 초안이 유지되고, 요청 중단·재조회 effect가 실행되지 않을 수 있었다. 서버의 계정 검증/소유권 규칙은 별도로 유지된다.

현재 context는 공개/비공개 범위, 리소스 ID, owner/account 구분, 전달된 비밀이 아닌 소유자 식별자 또는 계정 ID를 JSON tuple로 담는다. 토큰을 식별자에 넣지 않는다. context가 바뀐 render에서는 이전 tagged 목록/권한/오류가 숨겨지고, effect가 요청을 중단한 뒤 목록을 다시 읽는다. 새 의견의 이름·본문·대상 모드·위치·필터·계정 다이얼로그를 초기화한다. 답글/수정 폼은 이전 목록과 함께 제거된다. 같은 context의 새로고침/409 충돌은 초안을 유지한다.

`src/components/ReviewCommentsPanel.lifecycle.test.tsx`는 실제 React 19 createRoot/StrictMode/act 및 Zustand 구독을 jsdom에서 실행한다. 인증 초기화/세션 제공자와 fetch 응답만 제어하며 실제 ReviewClient의 경로·본문·응답 파서를 사용한다. fetch 모형은 abort 이후에도 응답을 반환하도록 해 AbortSignal과 결과 guard를 모두 검증한다.

새 회귀 8개가 확인한 동작:

- 익명 StrictMode 초기 mount의 취소된 응답 무시, 로그인 후 재조회, 로그아웃 시 작성/삭제 권한과 본문·표시 이름·답글 제거.
- A 목록의 지연 응답이 B 목록/권한을 덮어쓰지 않음. 새 요청은 B credential 사용.
- A 의견 등록이 진행 중일 때 B 전환: POST 중단, 뒤늦은 A 저장 응답이 B 목록/초안을 바꾸지 않음.
- A 수정 폼과 처리 완료 PATCH 진행 중 B 전환: 폼 제거, 요청 중단, 늦은 변경 응답 무시.
- 동일 리소스/소유자 식별자에서 비공개→공개 전환: 비공개 목록 제거. UUID를 공개 주소로 재사용할 때 기존 주소 검증 오류가 표시되고 이전 비공개 내용은 남지 않음.
- 같은 계정의 409 충돌 및 새로고침은 초안 유지. unmount 시 요청 중단 및 지연 응답 무시.
- A 세션 제공이 지연되는 동안 B 전환: A token이 뒤늦게 반환되어도 A HTTP 요청을 시작하지 않음.
- 소유자 credential 제공 지연·소유자 변경·이전 요청 410 회수 응답: 새 소유자의 목록/오류에 섞이지 않음.

검증: 전체 1,141 통과 / 선택 10 제외, TypeScript 및 Vite production build, `git diff --check` 통과. `jsdom@28.1.0`을 개발 의존성으로만 추가했고 현재 Node 24.14와 호환되는 버전을 선택했다. 실제 브라우저·로그인 제공자·두 기기·WebGL 픽셀을 대신하는 검증이 아니다. 요청을 abort해도 서버에 이미 완료된 쓰기를 되돌린다고 보장하지 않는다. 서버 권한/CAS와 클라이언트 결과 격리를 분리한다.

이 변경은 커밋/푸시 대상이며 이번에는 재배포하지 않는다. 공개 웹의 직전 누적 배포는 소스 `8fb69dc`를 유지한다. 원문 24단계 전체 전시 인수와 실제 인증/기기/사용자 모델 검증은 계속 미완료다.
