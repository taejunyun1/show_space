# 작품 라이브러리

2026-10-04. 원본 추가 요구 문서 2 §14의 프로젝트와 독립된 Artwork Card(썸네일·제목·연도·치수·종류·설치 형식·재료), 여러 전시에서 재사용을 로컬 저장으로 구현한다.

## 사용과 데이터

왼쪽 **작품 라이브러리**에서 이미지 또는 3D 작품 하나를 선택해 저장한다. 제목·작가·연도·재료·분류로 검색하고 이미지/3D 형식으로 필터한다. 카드의 배치 버튼은 현재 프로젝트에 새 객체를 만들며 이미지 작품의 대상 벽을 별도로 선택한다. 3D 작품은 원점의 바닥 중앙·회전 0으로 시작하고 3D 보기로 전환한다. 물리 크기와 원본 모델 피벗 보정은 유지한다. 새 배치는 선택 도구와 선택 객체를 갱신하고 하나의 Undo 단위다. 축척 미정 도면과 처리 중 바뀐 프로젝트에는 배치하지 않는다.

저장 허용 목록은 작품의 제목·작가·연도·본체 치수·종류·설치 형식·재료·설명, 이미지 작품의 액자·매트·앞면 보호·표면 재질, 이미지/3D 원본 자산이다. 프로젝트 ID·객체 ID·설치 벽/면·위치·회전·그룹·잠금·표시 상태·설치 메모/체크리스트/참고 사진을 템플릿에 복사하지 않는다. 배치마다 독립 사본을 만들고 다른 전시와 라이브러리 원본을 연동 수정하지 않는다.

예제 스프라이트 이미지는 해당 패널만 비율을 유지해 PNG로 포함한다. 이미 등록된 내장 이미지와 모델은 바이트를 보존한다. JPG/PNG/WebP 이미지 한 장 5MiB/긴 변 2,048px, 썸네일 128KiB/256px, 기존 정적 GLB의 12MiB 제한을 적용한다. 실제 이미지 썸네일과 작품만 담은 256×256px 3D 렌더를 생성한다. 작은 작품도 동일한 화면 점유율을 갖고 가까운 클리핑 면에 사라지지 않도록 프레이밍한다. detached renderer·geometry·texture·bitmap을 해제하며 편집 중 카메라·선택·Undo를 변경하지 않는다. 3D 썸네일은 저장할 때만 만들고 목록은 작은 내장 이미지를 쓴다.

IndexedDB `gonggan-artwork-library-v1`의 documents에 자산 포함 템플릿, summaries에 자산 없는 목록 메타데이터와 썸네일을 분리한다. 최대 500개/UTF-8 JSON 기준 80MiB(메타데이터 여유 포함)이며 보관 항목도 포함한다. 문서와 목록을 같은 트랜잭션에 쓰고, 저장 실패·수량/용량 초과는 전체 롤백한다. 동시 탭의 보관/복구는 revision으로 오래된 쓰기를 거부하며 BroadcastChannel/포커스 복귀로 목록을 갱신한다.

보관/복구는 원본 자산을 유지한다. 영구 삭제는 제공하지 않는다. 라이브러리 JSON 백업은 활성/보관 작품과 자산을 모두 담고, 복원은 새 항목 ID로 추가해 기존 목록을 덮어쓰지 않는다. 모든 템플릿·이미지 실제 디코딩·GLB 원본 bounds/offset을 검사한 뒤 원자적으로 저장한다. 프로젝트 JSON/자산 ZIP과 독립된 파일이다.

## 검증과 한계

751개 테스트 통과·선택 벤치마크 2개 제외, TypeScript/Vite 빌드 통과(기존 큰 번들 경고 유지). 디자인 허용 목록·독립 사본·원본 모델/치수 보존·설치 상태 초기화·잘못된 값·축척/프로젝트 변경 거부·단일 Undo/Redo를 검증했다. fake-indexeddb로 별도 연결의 지속 저장·revision 충돌·트랜잭션 중 목록 저장 실패/재시도·백업 전체 검사·수량/용량·동시 탭 상한을 검증한다. 다양한 치수의 썸네일 모서리 포함·일정 점유율·near/far 클리핑을 검사했다.

실제 로컬 UI에서 이미지/3D 저장, 실제 디코딩된 썸네일, 연도 검색·빈 결과·3D 필터·보관/복구를 확인했다. 새 전시 벽 B에 이미지 작품을 배치하고 액자 30mm·깊이 70mm·매트 60mm·유리와 정보를 유지한다. Undo/Redo로 개수가 1→0→1로 복구됐다. 3D 작품은 원본 GLB/치수 유지, 위치/회전 0·설치 메모 비움으로 배치됐다. 내려받은 프로젝트 JSON과 라이브러리 백업의 모든 디자인 필드/자산이 일치한다. 라이브러리 백업에 원래 설치 메모 PRIVATE 표식이 없다.

별도 origin에서 3개(보관 1개 포함)를 복원하고 재접속 후 유지했다. 모델 원본 너비 변조, 실제 형식이 다른 이미지, PNG 헤더만 정상이고 디코딩 불가능한 이미지 파일을 모두 거부하고 기존 3개를 유지했다. 390px 실제 DOM에서 창 clientWidth=scrollWidth=348, 좌우 20/370px로 가로 넘침이 없다. 모바일 실기기 검증은 아니다. 로컬 콘솔 경고/오류 없음. 기록 `../validation/2026-10-04-artwork-library.json`.

현재 브라우저/주소별 Library이며 계정 클라우드/기기 간 자동 동기화는 미연결이다. 원본 이미지보다 세부 정보를 늘리거나 2D를 3D 재질로 변환하지 않는다. 영상/프로젝션 재생, 원본 SKP 직접 입력, 500개 실자산 대용량·실기기 GPU 성능 검증은 남아 있다. 실제 인증과 원본 전체 요구 감사도 미완료여서 전체 목표는 진행 중이다.
