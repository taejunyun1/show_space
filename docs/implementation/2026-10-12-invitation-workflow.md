# 초대·참여자 관리와 공동 편집 열기

2026-10-12. 앞선 공동 열람에 초대 생성/수락 및 편집기로 여는 실제 UI 흐름을 연결했다. 즉시 배포와 운영 인증/브라우저 연결 대기는 기존 결정대로 보류한다. 도면 인식·문/설비 직접 편집·유료 생성 및 실시간 동시 편집 범위는 확장하지 않는다.

## 수정한 동작

- 역할 선택값을 이벤트에서 즉시 저장한다. 세션 응답을 기다리는 동안 select가 이전 서버 역할로 돌아가도 요청은 사용자가 선택한 역할을 보낸다.
- 관리 창은 열린 계정·로컬 전시/복원 context·대상 클라우드 ID에 묶는다. 계정 A→B→A와 같은 ID의 복원도 동기적 구독으로 기존 요청·목록·초대 링크를 폐기하고 창을 닫는다. 대상 ID가 바뀌면 입력과 비밀 링크를 새 내부 창으로 넘기지 않는다.
- ‘공동 작업 취소’와 ‘초대 작업 취소’는 즉시 다음 요청을 허용한다. 옛 성공/오류/finally는 새 요청을 적용하거나 busy를 해제하지 않는다. 서버에서 이미 수락한 초대·권한 변경을 되돌린다는 의미는 아니다.
- 불확실한 초대 생성은 동일 ID/이메일/역할/토큰으로 재시도한다. 서버가 이미 accepted/revoked라고 확인하면 기존 초안을 버려 다음 생성은 새 ID로 진행한다. 지연된 클립보드 완료가 다음 링크를 ‘복사됨’으로 표시하지 않으며, 현재 링크의 초대 취소 성공은 표시를 지운다. 상대가 이미 복사한 링크/파일을 삭제한다는 주장은 하지 않는다.
- 초대 페이지는 초대 ID와 계정 epoch에 묶는다. 계정 왕복은 이전 preview/수락/편집 요청을 폐기하고 새 권한을 읽는다. URL fragment는 기존 초대별 세션 보관 정책으로 읽은 뒤 주소에서 제거한다. 서버에는 토큰의 hash만 저장한다.
- `/join/`은 `App`을 마운트하지 않으므로 초기 로컬 전시가 아직 hydrate되지 않을 수 있다. ‘편집기로 열기’에서 기존 저장 작업을 먼저 복원하고 저장 큐를 마친다. 미완료 이동/회전·로컬 저장 오류·파일 준비 중 추가 편집/같은 ID 복원·취소가 있으면 열기를 중단한다. 파일/권한 검증→비활성 로컬 복사→계정 cloud link→guarded 시작 프로젝트 활성화 후 editor state를 로드한다. 원래 로컬 문서는 유지한다.

## 전달 검증

React/jsdom StrictMode 회귀 15개를 추가했다. 지연 session/preview/invite/clipboard/file, 계정 왕복·복원·대상 변경, 취소 후 새 요청, 처리된 초안의 새 생성, 미완료 이동·파일 준비 중 새 편집/복원과 취소를 확인했다. 일반 사례의 Team/파일 응답은 adapter이며 아래 native 사례는 실제 컴포넌트와 제품 API를 실행한다.

native 사례는 앞선 두 JPEG/Scene 백업을 실제 ZIP/image decoder로 읽고 production clients/actions/Worker를 사용한다. 합성 확인 이메일 A/B/C, 로컬 SQLite batch/R2, fake-indexeddb로 진행하며 실제 이메일은 전송하지 않는다.

1. A의 실제 관리 창에서 B의 editor 초대를 생성한다. Worker 201 확정 후 응답을 지연→취소→동일 ID 재시도 200을 실행해 초대 1개를 확인한다. 목록과 SQL에는 원래 토큰이 없고 token hash만 있다. 실제 링크 복사 UI도 확인한다.
2. 실제 B 초대 페이지에서 fragment를 읽어 제거하고 내용을 확인한다. 수락 확정/응답 지연→취소→같은 수락 재시도는 200/200이며 참여 권한은 1개다. 이때 로컬 전시/시작 프로젝트는 그대로다.
3. 아직 hydrate되지 않고 편집기 저장 writer도 없는 join 진입을 재현한다. 실제 공동 프로젝트 열람은 로컬 작업을 바꾸지 않는다. ‘편집기로 열기’가 기존 저장 작업을 hydrate한 후 두 도면의 검증된 새 로컬 복사본과 계정 cloud link를 생성·활성화하고 editor state를 로드한다. 앞선 로컬 문서는 그대로 남는다. navigation은 `onEditorReady` callback으로 확인했으며 실제 브라우저 이동/리디렉션은 검증하지 않았다.
4. A의 실제 역할 select로 viewer→commenter를 변경하고 참여 제외 버튼을 실행한다. 최종 membership은 commenter·revoked·revision 4이며 B의 파일 읽기는 404다. C의 새 초대를 생성/취소하면 표시된 링크도 사라진다.
5. A가 다시 읽은 원격 revision 1 ZIP은 최초 저장 바이트/전시와 같다. 현재 열린 로컬 복사본과 원래 문서도 유지된다. 독립 Python ZIP CRC 검사 및 PNG 2개의 SHA256은 원본 백업과 일치한다.
