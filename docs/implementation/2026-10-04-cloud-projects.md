# 계정·비공개 클라우드 프로젝트 저장 1차

2026-10-04. T2의 인증·저장 경로와 UI를 구현하고 Cloudflare 저장소를 준비했다. 실제 Supabase 프로젝트 URL/공개 키가 아직 없으므로 배포 사이트의 로그인·클라우드 기능은 준비 중이다. 실제 로그인, 메일 전달, Google OAuth, 두 실계정·두 기기 왕복은 완료로 집계하지 않는다.

## 사용 흐름

상단 **계정**에서 이메일 로그인 링크를 요청한다. Supabase 표준 SDK의 PKCE·세션 저장·토큰 갱신을 사용한다. 이메일 링크는 요청한 브라우저에서 열어야 한다. Google 버튼은 제공자 연결 후 명시적으로 활성화할 때만 나타난다. 로그아웃은 현재 기기의 세션을 종료한다.

**프로젝트 → 현재 프로젝트 클라우드 저장**을 처음 누르면 해당 프로젝트의 자동 저장을 시작한다. 로그인만으로 로컬 프로젝트를 업로드하지 않는다. 프로젝트 창에서 자동 저장을 끌 수 있고, 업로드 중 취소해도 대기 중인 백업을 유지한다. 로컬 저장과 클라우드 저장 상태는 따로 표시한다. 프로젝트 수정·재로그인·네트워크 온라인 이벤트에 재시도하며 상시 백그라운드 작업이나 다른 기기의 변경 실시간 수신은 구현하지 않았다.

클라우드 목록은 로그인 계정의 항목만 표시한다. **클라우드에서 열기**는 현재 작업을 로컬 저장한 다음 파일 전체를 검증하여 새로운 로컬 프로젝트로 추가한다. 연결된 현재 클라우드 항목의 보관은 막고, 다른 항목은 보관·복구할 수 있다. 두 기기가 같은 저장 버전을 수정하면 오래된 업로드를 거부한다. 충돌한 작업은 **현재 작업을 새 클라우드 복사본으로 저장**하여 보존한다.

로컬 프로젝트는 브라우저/주소에 속한다. 계정 변경 시 기존 로컬 전시가 자동 삭제되거나 다른 계정으로 업로드되지 않는다. 클라우드 연결과 업로드 대기열만 계정 ID로 구분한다. 같은 브라우저를 여러 사람이 사용하는 경우 로컬 프로젝트는 공유된다.

## 보존·검증

- 백업은 기존 `.gonggan.zip` 자산 패키지를 사용한다. 저장된 도면 이미지, 작품 이미지, 참고 GLB, 3D 작품, 모든 Scene, 재질, 조명·야외 설정, 치수, 비공개 메모·참고 사진을 포함한다. 보관하지 않은 원본 업로드 파일·Undo 기록·공유 관리 토큰은 제외한다.
- 패키지 최대 80MiB, 계정당 프로젝트 최대 200개(보관 항목 포함). D1은 소유자·메타데이터·버전·R2 포인터를 저장하고, R2는 파일을 저장한다.
- 서버는 표준 `auth.getUser(token)`의 제공자 응답으로 계정을 확인한다. 클라이언트의 계정 ID나 JWT payload를 소유권 근거로 사용하지 않는다. 조회·파일·갱신·보관 SQL 모두 계정 ID로 제한한다. 원본 R2 파일은 공개하지 않는다.
- 업로드는 R2 스트림과 네이티브 SHA-256 체크섬을 사용한다. 업로드 크기와 ZIP 시작 서명을 확인한 뒤 D1 버전 비교로 최신 포인터를 변경한다. Worker에서 큰 ZIP 전체를 풀지 않는다. 클라이언트가 다운로드 전체 SHA-256, ZIP 구조·크기·manifest·각 자산 SHA-256·스키마·이미지 디코딩을 검증한 뒤 편집기에 적용한다. 서버는 임의 ZIP의 전체 의미를 검증하는 업로드 서비스가 아니다.
- 업로드할 정확한 Blob을 계정별 IndexedDB 대기열에 먼저 보존한다. 재시도는 같은 파일·같은 버전을 사용한다. 응답이 사라져도 인증된 메타데이터 조회로 저장 여부를 확인한다. 다른 탭의 대기열을 교체하거나 삭제하지 않도록 요청 ID와 트랜잭션으로 보호한다. 이 탭이 확인한 로컬 버전과 다른 탭의 최신 로컬 버전이 다르면 클라우드 저장 완료로 표시하지 않는다.
- 클라우드는 최신 패키지만 유지한다. 성공한 버전 교체 뒤 이전 객체는 최선 노력으로 정리한다. D1 결과가 불확실하면 참조 가능성이 있는 객체를 삭제하지 않는다. 이 경우 및 정리 실패의 고아 객체 청소는 후속 운영 작업이다. 클라우드 버전 히스토리/영구 삭제 기능은 없다.
- 비공개 프로젝트 저장과 공개 공유는 별도다. 공개 공유 작성자 관리는 기존 `OWNER_TOKEN` 방식이며 계정 소유권 이전은 아직 연결하지 않았다. 로그인 세션/작성자 키는 백업·공유 스냅샷에 포함하지 않는다.

## 구성

전시 전용 D1 `gonggan-exhibition-projects`, ID `09e81757-5086-4735-b5b3-445b01225283`, 바인딩 `PROJECTS_DB`. `migrations/0001_cloud_projects.sql`을 remote에 적용했다. 전시 전용 R2 `gonggan-exhibition-projects`, 바인딩 `PRIVATE_PROJECTS`. r2.dev 접근은 비활성이고 공개 도메인은 없다. 기존 공유 버킷은 `SHARES`로 유지한다.

실제 인증 연결에 필요한 Worker 설정:

- `SUPABASE_URL`: 사용자의 Supabase hosted 프로젝트 URL.
- `SUPABASE_PUBLISHABLE_KEY`: 공개 publishable 또는 legacy anon 키. secret/service_role 키는 클라이언트 설정으로 반환하지 않으며 잘못 설정하면 인증을 비활성화한다.
- `SUPABASE_GOOGLE_ENABLED=true`: Google 제공자를 별도로 구성한 뒤 선택적으로 설정.

Supabase의 Site URL을 배포 주소로 설정하고 Redirect URL에 `https://gonggan-exhibition-preview.taejunyun.workers.dev/auth/callback`을 허용한다. 로컬 인증 테스트를 하려면 해당 localhost callback도 별도로 허용한다. `.skp` 원본 입력이나 추가 계정 생성/약관 수락은 실행하지 않았다. 비밀 키를 Git에 저장하지 않는다. 설정이 없으면 `/api/auth/config`는 `{enabled:false}`, 비공개 API는 503으로 응답하고 로컬 저장을 계속 제공한다.

## 검증 범위

실제 SQLite SQL, fake-indexeddb의 독립 연결, 표준 SDK에 주입한 테스트 제공자 응답으로 인증 거부·계정 분리·동시 CAS·동일 파일 재시도·보관/복구·잘못된 체크섬·크기 제한·응답 유실·취소·계정 변경·로컬 탭 충돌을 검증했다. 실제 전체 패키지의 메모 사진·GLB·Scene까지 HTTP 클라이언트를 통해 왕복했다.

별도 `/tmp` 전용 Worker에서 실제 로컬 Wrangler D1·R2에 3,319바이트 합성 패키지를 저장/다운로드했다. 생성 201, 동일 재시도 200, 수정 200/revision 2, 오래된 버전 409, 다른 테스트 계정 404, 비인증 401, 잘못된 SHA-256 503을 확인했다. 인증 제공자는 모의 응답이며 이 래퍼와 테스트 계정 토큰은 배포하지 않는다. 실제 이메일/Google 로그인이나 production 계정별 왕복의 증거가 아니다.

브라우저에서 인증 미설정 안내, 기존 로컬 프로젝트 5개와 메모·사진·3D 작품 보존, 콘솔 오류·경고 없음을 확인했다. 실제 인증 설정 후 계정/기기 전환·프로젝트 열기·자동 저장·충돌 복사본·오프라인 복구를 다시 검증해야 T2 전체 완료로 집계할 수 있다.

최종 검증: 전체 자동 테스트 694개 통과, 선택형 벤치마크 2개 제외. TypeScript와 Vite 빌드 통과. 기존 대형 출력/3D 번들 경고는 유지한다.

검증 실행 환경: Node.js v24.14.0. SQL 테스트는 Node의 `node:sqlite`를 사용하며 production Worker는 이 모듈을 포함하지 않는다.
