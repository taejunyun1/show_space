# 작품 가져오기 전환 보호와 시리즈 UI 흐름

2026-10-08. 원문 1 §8–14 및 문서 2 §14–26의 작품 등록→배열 흐름에서 운영 인증/브라우저 연결 없이 검증할 수 있는 실제 React 화면 동작을 확인했다.

## 발견 및 변경

Outliner의 이미지 입력은 `readImage(file)`이 끝난 뒤 현재 프로젝트에 `addArtwork`를 실행했다. 처리 도중 프로젝트를 바꾸거나 Outliner가 unmount되면 늦은 결과가 다른 프로젝트/후속 작업에 들어갔다. 작품 추가는 항상 첫 번째 벽을 사용해 선택한 벽을 무시했다. 과거 파일의 finally도 새 업로드의 busy 상태를 지울 수 있었다. 최초 UI 회귀 6개 중 이 경계의 네 사례가 실패했고, 배열/취소 두 사례는 통과했다.

이미지·영상·3D 작품 입력에 하나의 활성 가져오기 작업을 적용했다. 시작 시 프로젝트 ID와 설치 벽 ID를 보관하고 같은 화면의 중복 동시 입력을 무시한다. 실제 editor store의 프로젝트 전환마다 작업을 폐기하고 새 프로젝트의 입력 상태를 열어 준다. A→B→A가 한 React batch 안에 있어도 각각의 store 전환을 확인한다. unmount도 작업을 폐기한다. 늦게 도착한 결과·오류·finally는 새로운 목록/선택/뷰/메시지/busy에 적용하지 않는다.

Editor의 이미지 추가에도 별도 target 검사를 추가했다. 명시한 프로젝트가 다르면 단일 편집 명령 전에 거절한다. 명시한 벽이 삭제됐으면 다른 벽으로 fallback하지 않는다. 정상 입력은 시작 시 선택한 벽에 설치하며, 예제 작품 추가는 현재 선택한 벽을 사용한다. 도메인 addArtwork는 네 번째 wallId를 생략한 기존 호출의 첫 벽 동작을 유지한다. 실제 크기 숫자·프레임 기본값과 기존 이미지 처리 정책은 변경하지 않았다.

## 검증 범위

`Outliner.workflow.test.tsx`는 jsdom에서 실제 React createRoot/act, Zustand, Outliner, ArtworkSeriesDialog, NumberField, LengthUnitContext, ElevationView와 편집 명령을 실행한다. 이미지/영상/모델 decoder의 완료 시점만 제어하고, 열지 않는 재질/환경/Library dialog는 격리한다. 실제 PNG/영상/GLB decode나 브라우저/GPU 외관을 이 테스트의 근거로 주장하지 않는다. DOM dialog showModal은 adapter이며 native focus trap/파일 선택기 인수도 별도다.

새 UI 회귀 11개:

- 이미지 처리 중 다른 벽을 선택해도 시작 시 벽에 설치, 선택 정보 및 한 번의 편집 이력 확인.
- A 입력 중 B 전환 후 B 입력 가능, A 완료가 B의 목록이나 진행 상태를 바꾸지 않음.
- A→B→A 이후 늦은 A 결과 제거, 한 React batch 안의 전환도 제거.
- unmount 이후 늦은 결과 제거.
- 설치 벽 삭제 시 거절, 다른 벽에 임의로 추가하지 않음.
- 중복 입력 차단, 폐기된 파일의 실패 메시지 제외, 현재 파일 실패 표시 및 다시 입력 가능.
- 영상/모델의 지연 완료가 새 프로젝트의 데이터·view·알림을 바꾸지 않음 (각 1개).
- 시리즈 창 열기→순서 변경→2점 선택→35cm 간격→B면 적용→벽면도 B면 확인→한 번의 Undo/Redo. 미배치 작품 설치, 그룹 형성, 미선택 작품 보존 및 750mm 중심 간격 확인.
- 벽을 넘는 배열 조건의 경고/적용 차단, 취소 시 데이터/히스토리 불변.

`imageArtworkImport.test.ts`의 새 명령 경계 2개는 stale 프로젝트/삭제된 명시 벽 거절과 redo·선택·프로젝트 불변을 UI 작업 폐기와 별도로 검증한다. 전체 1,161 통과 / 선택 10 제외, TypeScript 및 production build, diff 검사 통과.

파일 처리 자체를 강제 중단하는 것은 아니다. 이미 실행 중인 decoder는 기존 cleanup으로 끝내고 결과를 폐기한다. 운영 인증/두 실제 기기·브라우저 파일 선택/레이아웃/포인터/GPU 픽셀·원문 24단계 전체 전시 및 사용자 성공 지표는 계속 남는다. 이번 변경은 Git에 기록하며 즉시 재배포하지 않는다. 공개 웹의 직전 배포 소스는 `8fb69dc`다.
