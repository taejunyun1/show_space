# 계정별 클라우드 복원 지점 — 2026-10-07

문서2 §70의 Version History/Restore Point를 기존 비공개 클라우드 프로젝트에 확장한다. 프로젝트 목록의 클라우드 카드에서 최신 **저장된 클라우드 상태**를 수동 기록한다. 로컬 편집은 먼저 클라우드 저장을 완료해야 하며 로컬 버전 목록을 자동 업로드하지 않는다. 모든 Auto Save의 영구 이력과는 구별한다.

## 저장·비교·복원

- `0002_cloud_history.sql`의 독립 테이블에 소유자/부모 프로젝트/지점 ID/이름/저장 revision/자산 포인터를 저장한다. R2의 독립 history 객체로 복사해 이후 최신 패키지 정리가 지점을 삭제하지 않는다. 같은 사용자·같은 부모를 모든 SQL/파일 요청에서 검사한다. R2 공개 주소를 만들지 않는다.
- 프로젝트당50지점, 계정당500지점/1GiB, 지점당80MiB. 보관된 항목도 한도에 포함하고 자동 삭제하지 않는다. 캡처 publication 한 SQL 문장에서 최신 포인터와 두 개수/총 바이트 한도를 확인하므로 동시 캡처가 한도를 우회하지 않는다.
- 저장 요청 ID와 revision/이름으로 동일 요청을 재시도한다. 응답 유실/불확실한 D1 결과는 인증된 지점 metadata로 확인하며 참조 가능성이 있는 파일을 삭제하지 않는다. 같은 이름의 불확실한 화면 재시도는 같은 ID를 사용한다. 별도 새 기록은 새 ID다.
- 파일 SHA-256/크기/ZIP manifest/각 자산 해시/스키마/이미지 디코딩을 검사해 비교·미리보기·복원한다. 비교는 현재 클라우드 내용 기준이며 기기마다 생성되는 로컬 프로젝트 ID만 내용 변경에서 제외한다. 클라우드 부모 ID의 소유권 검사는 유지한다.
- 복원 전 현재 클라우드 전시를 자동 지점으로 저장한다. 파일 오류·계정 변경·저장 한도·다른 기기 변경 시 현재 전시를 덮어쓰지 않는다. 안전 기록 이후 수정이 발생해도 기존 latest API의 revision CAS가 거부하며 안전 지점은 남는다.
- 복원 후 새 로컬 항목/새 ID를 만들어 연다. 기존 로컬 항목(아직 업로드하지 않은 편집 포함)은 보존한다. 새 복원본은 확인된 cloud revision과 연결하고 자동 저장을 이어간다. 클라우드 교체는 완료했지만 로컬 저장이 실패하면 클라우드에서 다시 열 수 있다.
- 보관/복구는 지점 revision으로 검사한다. 영구 삭제는 보관된 항목에서 확인 화면을 거치며 모든 기기에 적용된다. 파일 정리는 확인된 D1 삭제 후에만 한다. 이미 없는 자기 부모 지점의 삭제 재시도는 성공으로 확인하되 다른 계정의 부모는404다. 불확실한 삭제 결과/파일 정리 실패의 고아 파일은 운영 후속 정리 범위다.
- 공개 공유/Scene/기존 최신 저장 API 및 저장 패키지 형식은 유지한다. 클라우드 지점 목록 자체는 프로젝트 ZIP에 넣지 않는다.

## 검증

- 전체932 테스트 통과/선택 벤치마크2 제외, 관련 API24개 통과, TypeScript/Vite2645모듈 빌드 통과. 테스트 인증 제공자와 계정 토큰/표시는 production 자산에 없다.
- 실제 SQLite+HTTP 클라이언트에서 계정 격리, 불확실한 커밋/응답 유실, 같은 ID 재시도, 동시 프로젝트50지점 한도, 계정500지점/1GiB 한도, 다른 계정 한도 독립, 보관/복구/재시도 삭제, 복사 중 부모 수정, 안전 기록 이후 부모 수정, 전체 메모/Normal/Scene 복원, 손상 해시·이미지 실패·계정 guard를 검증했다.
- 실제 **로컬 Wrangler D1/R2 + 모의 제공자**에서5개 예제 작품 전시의 A(높이3200/폭900/메모A), B(3500/1100/메모B) 지점을 만들었다. 다른 항목은 벽/작품이며 자기 버전 비교는 동일하다. 읽기 전용3D에서5개 실제 이미지가 렌더된다.
- A복원→950mm 새 저장→자동 안전 B로복원(3500/1100/메모B), 새로고침 및 보관/복구를 확인했다. 기존 로컬 항목을 보존한다. 다른 origin의 별도 로컬 DB에서 A목록 조회→A복원(900/메모A)을 확인했다. 최신 클라우드 revision7/총5지점(안전3)이 존재한다.
- 실제 파일 다운로드3550286바이트/5자산의 ZIP CRC·manifest·모든 SHA-256을 대조했으며 서버 A 지점 바이트와 일치한다. 390×844에서 대화상자351/client·scroll349px, 문서390px로 가로 넘침이 없다.
- 모의 계정 B 목록은 비어 있으며 A의 목록/metadata/파일 API는404, 비인증401. 콘솔 경고/오류 없음. 최초 proxy-only 두 번째 주소의 복원은 기존 동일 출처 검사가403으로 거부했다. 생산 코드를 완화하지 않고 화면/API를 함께 제공하는 두 번째 Worker 주소에서 통과했다.
- 실제 사용자 데이터의 영구 삭제·production 모의 로그인·실계정 가입/약관 수락은 수행하지 않았다. 임시 검증 코드/DB는 `/tmp/gonggan-cloud-history-20261007`에만 있다.
