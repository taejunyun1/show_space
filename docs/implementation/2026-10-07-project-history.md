# 2026-10-07 — 프로젝트 버전 기록과 복원 지점

문서 2 §70의 향후 Version History/Restore Point를 프로젝트 목록의 각 카드에 연결한다. 사용자가 이름을 붙여 프로젝트 전체를 저장하고 새로고침 후 비교·3D 미리보기·복원·백업·보관/복구를 사용할 수 있다. Scene과 Undo는 기존대로 유지하며 버전은 현재 도면·구조·작품·모델·메모·Scene을 함께 보존한다.

## 저장과 복원

- 별도 IndexedDB에 작은 복원 지점 목록과 완전한 자산 ZIP을 저장한다. 기존 프로젝트 저장 DB/스키마를 변경하지 않는다. 같은 프로젝트 내용과 내장 자산을 가진 버전은 아카이브 하나를 공유한다.
- ZIP 80MB/기존 복원 검사, 프로젝트당 50지점, 브라우저 전체 아카이브 200MiB 한도다. 오래된 기록을 자동 삭제하지 않는다. 보관은 복구 가능하며, 영구 삭제는 보관된 기록에서 명시적인 확인 화면을 거친다. 마지막 참조 삭제에서만 아카이브 용량을 반환한다.
- 비교는 모든 현재 프로젝트 스키마 필드의 차이를 한국어 항목으로 보여준다. 예제 작품 경로를 백업 내장 자산과 같은 표현으로 정규화해 파일 경로 변경을 실제 작품 변경으로 잘못 표시하지 않는다. 비교 당시의 현재 작업은 바꾸지 않는다.
- 복원 전에 현재 프로젝트 전체를 자동 복원 지점으로 기록한다. 자산/이미지 검사·현재 저장 revision·보관 상태를 확인하고 조건부 저장한다. 안전 지점 저장이나 다른 탭 검사에 실패하면 현재 프로젝트를 덮어쓰지 않는다.
- 복원 후 이 탭이 기억하는 저장 revision도 갱신해 다음 자동 저장이 오래된 revision 때문에 실패하지 않게 한다. Undo는 새로 시작하며 복원 직전 상태는 버전 기록에 남는다.
- 버전 3D 미리보기는 기존 읽기 전용 발표 렌더를 사용한다. 다운로드는 선택한 지점의 `.gonggan.zip`이며 상단 저장 프로젝트 불러오기로 새 프로젝트에 복원할 수 있다.

## 검증

- 전체 **918 테스트 통과 / 선택 벤치마크 2 제외**, TypeScript/Vite 빌드 통과.
- 실제 로컬 UI에서 네 벽/작품 한 점/메모/Scene 한 개의 A 지점(벽 높이3200mm, 작품 폭900mm)과 B 지점(3500mm,1100mm)을 저장했다. 재접속 후 두 지점이 보존되며 같은 B는 동일, A는 벽/작품이 다름으로 표시된다.
- A의 읽기 전용 3D와 이미지를 확인하고 A로 복원해 3200/900mm·원래 메모·Scene을 확인했다. 복원 후950mm 새 편집 저장도 성공했다. 자동 안전 지점으로 복원 직전 B의3500/1100mm·후속 메모로 다시 복원했다.
- 실제 버전 ZIP 737,142바이트/2자산의 CRC·프로젝트/자산 SHA-256을 대조했다. 실제 파일 선택기로 새 프로젝트에 불러와 A의 치수·메모·Scene을 확인했다.
- 보관된 버전 보기→복구, 390×844에서 dialog 폭351px/client·scroll349px/문서390px를 확인했다. 콘솔 경고/오류 없음.
- 직접 만든 프로젝트 두 개만 복구 가능한 보관으로 정리했고 버전 기록 네 개는 유지했다. 원래 ANCA 전시/수정 시각은 보존했다. 실제 사용자 데이터의 영구 삭제는 수행하지 않았다.
- 단위 테스트는 독립 DB 연결·완전한 이미지/노멀/Scene·같은 내용 자산 공유·프로젝트 ID 격리·동시 한도·트랜잭션 실패 롤백·손상 해시·복원 전 안전 기록·다른 탭 변경·복원 후 저장 revision·경로 정규화 비교를 검증한다.
