# 캡처용 모델 준비 상태와 실패 전달

2026-10-07 · 원문 1 §27/28, 원문 2 §48/68의 입력 모델 누락 보호

기존 3D PNG 캡처는 이미지/3D 작품의 객체 이름이 존재하는지만 기다렸다. 참고 전시장 GLB는 대기 대상에서 빠졌으며, 실패한 3D 작품은 전체 시간 초과 뒤 이미지 준비 오류로 표시됐다. 모델을 교체하는 render와 useEffect 사이에는 이전 형상이 잠시 남을 수도 있었다.

현재 PNG 캡처는 표시 중인 전시장 GLB와 모든 3D 작품의 준비 상태를 확인한다. 모델 컴포넌트는 로딩 중/성공/실패 모두 별도 marker를 유지한다. 원본 bytes를 담은 data URL과 저장된 크기·기준점이 현재 입력과 일치하고 형상/텍스처 검사가 성공했을 때만 ready로 판정한다. 문자열로 된 대형 data URL을 매 render마다 JSON 직렬화하지 않고 원본 값과 작은 bounds key를 비교한다. 변경된 입력은 이전 성공/실패를 재사용하지 않는다.

알려진 모델/작품 이미지 실패는 즉시 캡처 오류로 전달한다. 로딩은 기존 10초 대기 범위에서 프레임을 요청하며, 준비되지 않은 모델은 조용히 누락해 저장하지 않는다. 숨긴 모델, 숨김/삭제된 벽의 이미지 작품은 대기 대상에서 제외한다. 프로젝트/드래그 미리보기의 기준 객체가 대기 중 바뀌면 캡처를 중단하고 다시 시도하도록 안내한다. 고해상도 이미지/조명 대기 뒤 실제 PNG 렌더 직전에도 모델 준비와 프로젝트를 다시 확인한다. 기존 finally의 배경/환경·해상도·격자·capture mode 복원을 유지한다.

PDF 3D/3D 작품 상세는 이미 detached `prepareExportScene`을 await하는 경로다. 이전에 추가한 정적 모델 텍스처 검사 덕분에 입력 이미지 본문 실패는 WebGLRenderer를 생성하기 전에 중단된다. 이 경로에 별도 살아 있는 편집기 marker나 상태를 사용하지 않는다.

검증: 실제 Three Group을 이용해 전시장+모든 표시 작품 대기, legacy 이름/누락 marker/이전 source와 bounds 제외, effect 이전 상태 전환, 숨김/삭제 벽, 이미지 실패, 비동기 성공/즉시 실패/시간 초과/프로젝트 변경 guard를 확인했다. 가짜 시계는 대기 시간만 제어한다. PNG 준비 검사 9개와 실제 GLTFLoader/native PNG decoder를 통한 PDF 현재 3D·3D 작품 상세·전시장 모델 실패 회귀 1개를 추가했다. PDF renderer를 가짜로 성공시키지 않고 renderer 생성부가 호출되지 않는 실패 경계를 확인했다. 전체 1,125 통과/선택 10 제외, TypeScript/Vite 빌드·diff 검사 통과.

한계: 이 회귀는 실제 브라우저 React/R3F 장면의 commit 및 GPU/PNG/PDF 결과 픽셀을 대신하지 않는다. 표면 finish의 별도 texture/normal 로딩과 모든 시점/GPU 상태 인수는 별도 점검 대상이다. 전체 24단계 전시 흐름, 운영 인증/기기, 배포 인수도 미완료 상태를 유지한다.
