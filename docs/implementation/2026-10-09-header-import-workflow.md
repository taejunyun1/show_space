# 상단 GLB·프로젝트·백업 입력의 작업 보호와 저장 확인

2026-10-09. 기존 도면·3D 불러오기에서 GLB와 저장 프로젝트 JSON·백업 ZIP의 연결 흐름을 검증했다. `.skp` 직접 지원은 추가하지 않고 기존 안내를 유지한다. 도면 인식 고도화나 문·설비·설치 제외 영역 직접 편집은 확장하지 않는다.

## 변경

Header가 실제 프로젝트 ID 전환을 동기적으로 감시해 이전 입력을 폐기한다. A→B→A가 한 React batch에 있어도 이전 결과·진행 안내·오류·finally가 다음 프로젝트나 새 입력의 busy를 바꾸지 않는다. Header unmount도 입력을 폐기한다. 자신의 복사본을 적용하는 한 번의 ID 전환만 해당 입력 작업에 허용한다. ref가 중복 진입을 막고 저장 데이터 hydration·이동/회전 중 입력을 거절한다. 모델 decoder 완료 시에도 편집 상태와 도면 축척을 다시 확인한다. 진행 중인 decoder 계산 자체를 강제 중단하지는 않는다.

JSON도 ZIP과 같은 이미지·영상 검사 함수를 사용한다. 손상된 이미지 바이트를 기존 프로젝트 교체 전에 차단한다. 유효한 GLB는 실제 크기와 원본 바이트를 유지하며 현재 프로젝트의 벽·작품을 보존한다.

프로젝트 복원은 기존 초안을 revision-checked 저장으로 확정하고 기존 JSON 백업을 내보낸 뒤 새로운 UUID 복사본을 적용한다. 복사본 저장 완료를 기다려 성공을 안내한다. 기존 초안 저장 중 추가 편집이 생기면 복원을 멈추고 최신 편집을 유지한다. 새 복사본의 저장 공간 부족은 성공으로 표시하지 않는다. 이 경우 기존 프로젝트는 목록과 JSON 백업에 남고 복사본은 편집기에 저장 오류 상태로 남는다. UI 교체와 저장이 완전히 원자적인 거래는 아니다. 이미 시작한 저장은 프로젝트 전환이나 unmount 뒤에도 대기열에서 완료될 수 있다.

## 검증

새 `Header.importWorkflow.test.tsx` 17개는 실제 React createRoot/StrictMode/act, Header·ImportDialog, Zustand와 실제 IndexedDB 저장 대기열/목록을 사용한다. 파일 읽기 지연은 제어하며 다운로드는 Blob 전달을 확인한다. 열지 않는 계정·메모·목록 창만 제외한다.

- GLB·ZIP 처리 중 프로젝트 왕복/화면 unmount, 오래된 오류·진행·finally와 새 입력 격리를 확인한다.
- 기존 저장 중 프로젝트 전환과 같은 ID 추가 편집이 기존 결과의 교체·다운로드를 막는지 확인한다.
- 정상 복원에서 새로운 UUID, 기존 최신 초안과 JSON 백업, 복사본의 실제 저장 및 active ID를 확인한다.
- 새 항목 저장 대기/실패에서 성공 안내를 막고 기존 저장 항목을 보존한다.
- JPG 라우팅과 SKP 미지원 안내, 이동/회전 중 decoder 시작·완료 거절을 확인한다.
- 실제 합성 전시장 GLB를 Three GLTFLoader로 읽는다. 12,000×3,000×8,000mm 경계, 원점 보정 [-10,-2,-5]m, 배율 1, 원본 바이트, 벽·작품 유지와 단일 Undo를 확인한다.
- 실제 ZIP·JSON 바이트와 native PNG decoder를 사용해 이미지 작품 2점, 전체 전시장 모델, Scene 구조와 내부 메모를 실제 IndexedDB에 보존한다. ZIP의 생산용 CRC/hash 및 미디어 검증 코드를 실행한다.
- JSON의 손상 PNG는 프로젝트 교체·백업 다운로드 전에 거절한다.

Binary transport는 외부 Three loader와 같은 native ArrayBuffer/File/Blob realm을 사용한다. 실제 브라우저 파일 입력·다운로드·GPU 표시의 근거는 아니다. 생성한 GLB·PNG는 합성 입력이며 사용자 SketchUp 파일이나 복잡한 실제 도면의 성공률을 증명하지 않는다.
